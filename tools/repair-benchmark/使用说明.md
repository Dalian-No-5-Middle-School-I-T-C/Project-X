# Project-X 独立修复基准

用于在已知问题清单下比较其他 AI 对同一代码基线的修复能力。脚本不修改被测源码，不调用被测仓库已有的测试脚本，也不连接生产站点。构建产物、运行日志、测试数据和截图保存在本工具的 `results` 目录。

## 本机运行

需要 Windows Node 22+、Git、已安装依赖的 Project-X 源码、Ubuntu WSL，以及源码目录中可运行的 `resources/native` Windows 原生识别器。浏览器优先使用本机 Edge，否则安装 Playwright Chromium。首次启动需要联网下载运行时依赖；WSL 内使用 root 准备隔离环境，应用进程使用专属测试用户。被测 Git 引用的依赖锁文件必须与 Source 目录一致，否则应准备该版本的独立源码目录并安装匹配依赖；依赖不匹配作为环境错误退出。

在本工具目录执行：

```powershell
# 固定旧版基线；默认 Source 是本工具上两级目录。
.\run.ps1 -Ref 70697163f9c456677f8ad4499b65b832e9032810 -Mode baseline

# 测试其他 AI 修改后的工作区（包括尚未提交的代码）。
.\run.ps1 -Source 'C:\path\to\candidate\Project-X' -Ref working -Mode candidate

# 也可以测一个已提交的分支或 SHA。
.\run.ps1 -Source 'C:\path\to\candidate\Project-X' -Ref fix-branch -Mode candidate

node compare.mjs results\基线运行目录\results.json results\候选运行目录\results.json 修复评分.md
```

工具可以整体复制到仓库外使用；此时必须显式指定 `-Source`。建议把工具存放在受评 AI 无写权限的位置，并由评测者运行。脚本没有防篡改沙箱，不能防御恶意修改测试本身或伪造进程响应的受评程序。

默认 AI 服务商由本机确定性响应代替，测试真实 Python SDK、任务状态和报告持久化，并独立执行实际 AI 数据查询；这不评价外部大模型的推理质量。`-AiEnv 'C:\path\llmclient\.env'` 可额外启用真实服务商调用，会产生服务商用量且结果可能波动，不建议用来比较修复分数。配置不写入报告，临时副本在结束时删除。

## 隔离和退出

每次运行自动分配六个可用端口：WSL 内为 MariaDB、Node、Nginx、AI 和模型响应服务分配端口，Windows 为本机扫描服务分配端口。分配时使用操作系统的端口 0，不猜测固定端口；WSL 分配会排除已预留的扫描端端口。端口映射写入 `ports.json` 和 `results.json` 的 `metadata.ports`，自动传入全部服务、代理及测试请求，无需手工修改地址。端口交接后若被外部进程抢占，仍按环境启动失败退出，不计为产品缺陷，也不会杀死不相关进程。WSL 数据位于 `/var/tmp/projectx-repair-benchmark/runs/<run-id>`，公共依赖缓存位于相邻 `cache` 目录。

正常结束自动关闭本次服务，保留证据。`-KeepRunning` 仅供手工排查，会保持服务运行。终止后可在 WSL 执行本次结果目录中的 `wsl-runtime.sh stop <run-id>`；本机进程信息和控制台日志可辅助排查。不要并行运行两份基准。

退出码：基线模式复现至少 15 个 B 类产品缺陷时为 0；候选模式所有用例通过时为 0；结果不达标为 1；环境或整体运行错误为 2。不能把基线模式退出 0 当作产品无缺陷。

## 数据与判定

### 协议兼容（2026-09-12）

- B17 接受 `data` / `result` 包装，题块数组可为 `cropImages`、`blockCrops` 或 `crops`；支持 Base64、图片 data URL 和本机扫描服务的可访问图片 URL。实际解码验证图片尺寸，空数组、不可读取的路径、失效 URL 和伪造图片字节不算通过。
- 上传识别结果时只发送判分所需字段，不把题块 Base64 等额外响应字段塞进 `recognition`，避免严格服务端模型拒绝无关字段。
- B18 最多等待 60 秒异步入库，直接按考生 ID 核对数据库成绩；不依赖 API 返回排序、数字字符串格式、会话状态命名或 `progress.recognized` 字段。进度响应仅作为诊断证据。
- 重复完成接受 2xx、409 或 410，但此前必须已经有正确成绩，之后再次检查成绩及题目记录不变。其他 HTTP 错误不会直接放行。首次完成请求仍须成功。
- 题块读取检查和识别上传分开运行，B17 失败不会挡住独立验证判分入库。独立题块上传 / 进度端点返回 404/405 时记录协议提示；其他错误仍报告失败。
- F08 同样以数据库最终成绩判定，不要求前端一定发出特定名称的 `complete` 请求。发布仍由 F06 单独验证。

这是对等价传输格式和完成时序的兼容，不会把“上传成功但成绩为空”判为通过。成绩和题目表结构仍沿用该基线的业务数据库契约；未提供任意新协议自动推断。兼容性专项验证命令：`node --test protocol.test.mjs`。脚本版本已改变，旧版结果不能与新版结果混合评分，须重跑两边。

完整链路使用真实接口创建答题卡、考生、考试，生成 PDF 和四份填涂图片，再调用本机 C++ 识别器上传到 WSL。预期成绩为 20、15、10、5。之后检查分析、发布、导出、学生查分、网阅及 AI。

另建独立分析考试，使用 SQL 插入 150 分制成绩 59.5、75、90、150，验证及格率 50%、优秀率 25%、分布总人数 4。SQL 夹具只用于隔离下游错误，不修改链路考试，也不把上游失败改为通过。部署包漏掉 Python 时会明确记录 B16 失败，再补充 Python 源码，以便继续独立测试其内部缺陷。

`results.json` 保存源码 SHA、工作区内容哈希、测试工具哈希、夹具说明、逐项证据和结果。评分器要求基线和候选使用同一版测试工具。`测试报告.md` 为简明清单。`FAIL` 是断言失败，`ERROR` 是环境错误，`BLOCKED` 是前置失败；后两者不计入缺陷复现数。多个业务问题可能共享根因，评分同时报告用例数和完整修复根因族数。

物理 TWAIN 走纸不属于无人值守测试：本机未提供连接的扫描仪，脚本使用生成的图像调用真实 Windows 原生识别器。不会执行网络安全测试。本套基准覆盖所列业务路径，不声称穷尽全部页面、题型、外设和第三方服务。

## 给受评 AI 的任务

将 `问题清单.md` 和原始主分支源码交给受评 AI。要求只修复产品代码，不修改本基准，不读取修复分支。完成后由评测者用同一工具运行候选代码，再执行 `compare.mjs`。
