
# Project-X 测试数据兼容性分析报告与升级计划

## 📊 现状摘要

| 项目 | 值 |
|------|------|
| 当前版本 | **v1.9.6**（package.json） |
| 测试数据声称兼容版本 | **v1.6.3 / v1.7.0**（manifest.json） |
| 数据库迁移版本数 | **27 个**（v1~v27，v17 跳过） |
| 测试数据覆盖的功能 | 基础考试、排名、大考组、跨考、在线阅卷（1P 基础） |
| 种子脚本实际适配到的版本 | **~v1.9.4**（使用了 v24 迁移的列） |

## ✅ 兼容性判定

### 方式一：种子脚本（`import-all.sh seed`）— ✅ 基本兼容

`seed.ts` 内部调用 `initializeDatabase()` → `runMigrations()` → 确保所有 27 个迁移已执行后才写入数据。因此**种子脚本本身可以成功运行**，不会遇到缺列/缺表错误。

唯一的注意点：
- `block_grading_config` INSERT 未包含 v27 新增的 `scoring_mode` / `score_distribution`，但两列都有 `NOT NULL DEFAULT`，SQLite 自动填充，**不会报错**
- `review_assignments` INSERT 包含了 v24 新增的 `auto_assigned` 列 ✅

### 方式二：ZIP 恢复（`import-all.sh restore`）— ⚠️ 有隐患但可修复

- 预构建的 `projectx-demo.zip` 是某次 `build-backup.ts` 的产物
- ZIP 内的 `schema_migrations` 表记录了构建时已执行的迁移版本号
- 如果 ZIP 构建时只到 v24（v1.9.4），恢复后缺少 v25/v26/v27 的列
- **但**：恢复后重启服务，`initializeDatabase()` 会自动执行缺失的迁移（所有迁移都是幂等的 `addColumnIfMissing`）
- **隐患**：用户可能不知道需要重启；且 `ensureDefaultAdmin()` 在 restore handler 内执行时，如果 v23/v25 的 `password_change_required` 列还未补齐，可能导致启动崩溃（不过 v25 backfill 迁移专门解决了这个问题）

### 方式三：CSV 导入 — ✅ 完全兼容

`students.csv` 和 `teachers.csv` 通过 `POST /api/users/import-csv` 导入，该 API 只涉及基础用户字段，不受迁移影响。

## 🔴 发现的问题

### 问题 1：manifest.json 版本号过时（低优先级）
- 声明兼容 `v1.6.3 / v1.7.0`，但种子脚本已适配到 v1.9.4+
- 应更新为 `v1.9.6+` 或 `v1.9.4 ~ v1.9.x`

### 问题 2：在线阅卷测试数据不完整（中优先级）
- `seed-review.ts` 仅覆盖 **1P 单教师模式**（review_mode=1）
- **未覆盖** v1.9.0 重构的 2P/3P 多轮审阅、争议仲裁流程
- `block_grading_config` 缺少 `scoring_mode` / `score_distribution` 显式设置（依赖默认值，无法测试"逐题评分"模式）

### 问题 3：verify.ts 验证覆盖不足（中优先级）
- 未验证在线阅卷功能（打分面板、批注、会话续批）
- 未验证全局设置（`system_settings`）
- 未验证教师权限（`teacher_permissions`）
- 未验证导出模板（`export_templates`）
- 未验证原卷多页（`original_paper_pages`，v1.9.6 新增）

### 问题 4：新功能无测试数据（低~中优先级）
| 功能 | 引入版本 | 测试数据 |
|------|---------|---------|
| 原卷多页上传 | v1.9.6 | ❌ 无 |
| 全局设置页面 | v1.9.6 | ❌ 无（仅依赖迁移默认值） |
| 2P/3P 网阅 | v1.9.0 | ❌ 无 |
| 教师子角色权限 | v1.8.x | ❌ 无 |
| 赋分公式 | v1.4.0 | ❌ 无 |
| 考试归档 | v1.x | ❌ 无 |
| AI 分析 | v1.4.0 | ❌ 无（需外部 API key） |

### 问题 5：ZIP 备份包可能过时（低优先级）
- 如果 `projectx-demo.zip` 是在 v27 迁移加入前构建的，schema_migrations 不含 v25~v27
- 恢复后需重启才能补齐列；不重启可能在 `ensureDefaultAdmin()` 时崩溃

## 📋 升级计划

### 阶段 1：验证现有数据可用性（只读验证，不改代码）

1. **运行种子脚本**
   ```bash
   npm run dev
   npx tsx testdata/demo-exams/scripts/seed.ts
   ```
   预期：无 SQL 错误，8 场考试 + 16 名学生 + 网阅演示数据全部写入

2. **运行 verify.ts**
   ```bash
   npx tsx testdata/demo-exams/scripts/verify.ts
   ```
   预期：全部 ✓

3. **运行项目内置验证**
   ```bash
   npm run verify:auth
   npm run verify:security-critical
   ```
   预期：全部通过

### 阶段 2：修复文档与元数据

4. **更新 manifest.json 兼容版本**
   - `"compatibleWith"` 从 `["v1.6.3", "v1.7.0"]` → `["v1.9.4", "v1.9.5", "v1.9.6"]`
   - 更新版本号从 `1.1.0` → `1.2.0`

5. **重建 ZIP 备份包**
   ```bash
   npx tsx testdata/demo-exams/scripts/build-backup.ts
   ```
   确保 ZIP 内的 `schema_migrations` 包含全部 27 个版本

### 阶段 3：增强种子脚本（扩展测试覆盖）

6. **seed-review.ts 增加 2P 审阅数据**
   - 新增一个 2P 模式的考试/题块，含 2 名教师独立评分 + 1 名仲裁员
   - 插入 `review_sessions` 和 `review_annotations` 数据
   - 设置 `block_grading_config.review_mode = 2`

7. **seed-review.ts 显式设置 scoring_mode**
   - 题块 A 用 `block_total`（默认），题块 B 用 `per_question`
   - 同时设置 `score_distribution` 为 `proportional` 和 `equal` 各一个

8. **seed.ts 增加全局设置演示数据**
   - 向 `system_settings` 写入 `require_original_paper` / `highlight_missing_paper`

### 阶段 4：扩展验证脚本

9. **verify.ts 新增验证项**
   - 在线阅卷：`GET /api/review/exams/:id/assignments` → 检查分配数据
   - 全局设置：`GET /api/system-settings` → 检查键值存在
   - 打分面板：`GET /api/review/exams/:id/block/:blockId/crops` → 检查裁切图数据
   - 教师登录打分：demo-teacher 登录 → 创建 review_session → 提交分数

10. **新增 verify-online-review.ts（可选）**
    - 端到端验证网阅流程：分配 → 开始批阅 → 提交分数 → 争议检测 → 仲裁

### 阶段 5：文档同步

11. **更新 testdata/README.md 和 testdata/demo-exams/README.md**
    - 反映新增的测试场景
    - 更新兼容性说明
