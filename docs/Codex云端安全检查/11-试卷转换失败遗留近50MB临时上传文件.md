## 概要

**由本次变更引入。** 新增试卷上传/转换路径仅成功时清理临时文件。应把清理放进覆盖全部上传后处理的 finally，并在进入 Sharp 等解析器前验证魔数。

上传中间件把每个最多 50 MB 的文件写入 papers/_tmp。验证仅检查攻击者控制的扩展名和文件大小，所以名为 .jpg 等图像扩展名的任意数据会被接受并交给 Sharp。畸形图像在元数据提取或转换时被 Sharp 拒绝，storePaperFile() 抛错。只有函数成功返回才删除临时文件；catch 返回 HTTP 500，不删除 req.file.path。Multer 每次生成不同临时文件，目录也没有清理逻辑。默认 grade:write 教师因此可反复提交扩展名合法的畸形文件，每请求永久占用最多约 50 MB，填满应用卷，在敏感运行期间干扰扫描、判分、数据库及其他上传。

## 验证

1. 普通认证教师的默认 grade:write 可达端点，无更严格卡片所有权或存在检查。
2. 扩展名合法畸形图像被 Multer 接受，以唯一名写 papers/_tmp，可接近 50 MiB。
3. 内容进入 Sharp，触发被处理的转换异常/HTTP 500，跳过仅成功时 unlink。
4. 端点复现显示重复失败留下不同完整临时文件，大小和哈希一致；精确 50 MiB 边界另作不泄漏对照。
5. 无仓库试卷临时清理、总配额或上传限流限制累积；定时清理只处理数据库关联扫描记录。

## 攻击路径分析

不适用强制排除：共享影响而非本人，前提现实，无需管理员/操作者或受保护本地写权限。普通教师从授权上传跨越到未授权消耗共享存储。仓库含公开 Nginx 监听代理回环服务，因此网络范围为远程。最强限制是认证、Multer 单文件上限、Node 回环及需要重复请求。默认所有教师仍满足认证权限，代理使回环不再隔离远程，单文件限制不约束累计保留量。因此影响、可能性均高，矩阵为高危而非严重：已证明为单服务/文件系统可用性损失，不是管理员接管、规模化隐蔽改分、整个安装群失陷或 RCE。

### 路径

默认 grade:write 普通教师 → 合法扩展名认证 multipart → POST /api/cards/:cardId/paper → Multer 保存略小于 50 MiB → papers/_tmp 磁盘存储 → 内容进入 storePaperFile / metadata() → Sharp 元数据解析失败 → 在仅成功清理前抛错 → catch 遗漏 unlink → 唯一文件无配额/陈旧清理地累积 → 持久累计磁盘耗尽。

攻击过程：恶意/失陷普通教师通过正常原始试卷流程反复上传名为 malformed.jpg 的畸形数据。强制认证时 POST 门禁需 grade:write，默认教师具备。Multer 在路由处理前写临时文件。验证只查可控扩展名和大小，随后 Sharp 解析抛错。清理只在 storePaperFile 成功之后，catch 返回 500 不删除。可执行验证经 HTTP 执行未修改的门禁、路由、转换器与 Sharp：匿名 401；认证的 52,428,799 字节及 1 MiB 畸形 .jpg 均 500，留下逐字节相同的文件，总计 53,481,472 字节。最强反向证据是回环监听、RBAC 拒匿名，以及 Multer 对精确 50 MiB 上传拒绝并删除部分文件。但已检入 Nginx 在 80/443 发布回环服务，普通教师有权限，低于上限一字节的上传会持久残留，无累计配额、限流或临时清理，因此不足以否定。没有秘密参与；跨越的是教师授权上传到共享应用文件系统可用性的边界。

## 发生可能性

**高。** 路径直接，经已检入代理配置远程暴露；保守认证开启假设下只需普通教师，普通 multipart，无竞态或复杂解析器技巧。HTTP 复现证明两次畸形上传留下两个完整且内容相同文件。需重复与有限磁盘，但每请求近 50 MiB，仓库无总配额、限流或清理中止累积。**攻击向量：远程网络。**

## 影响程度

**高。** 每次成功攻击持久累计近 50 MiB。耗尽共享应用文件系统可阻止试卷上传及文件支持的扫描/判分；SQLite 或日志若同卷也会受影响。考试流程可用性在给定威胁模型中价值高。证明限于单服务及文件系统，无机密性、完整性、全群或代码执行效果。

## 假设条件

- 生产按威胁模型开启 PROJECTX_AUTH_ENFORCE，保守路径使用普通认证教师，不依赖仓库匿名兼容默认。
- 已检入 Nginx 表示受支持的 80/443 到回环 5174 公开部署。
- 应用文件系统容量有限，没有外部每用户存储配额或仓库外陈旧文件清理。
- 可重复试卷上传，未发现仓库通用 API 上传限流。

原文另列前提：

- 可经 Web 服务访问试卷 POST。
- 强制认证假设下，有默认 grade:write 普通教师账号。
- 反复上传合法图像扩展名、内容畸形且低于单文件上限的 multipart。
- 足够请求耗尽 data/answer-card/papers/_tmp 所在有限文件系统。

## 控制措施

- 认证开启时匿名 401，POST 需 grade:write。
- Multer 名义单文件 50 MiB；验证精确边界拒绝且无部分残留。
- 扩展名允许列表不验证内容签名/解析合法性。
- 正常成功路径在 storePaperFile 返回后尝试 unlink。
- safeId 清理卡目录 ID，避免此路径成为目录穿越。
- 定时清理只覆盖过期扫描记录，不覆盖 papers/_tmp。
- 无累计配额、每主体上传限流或陈旧试卷临时文件清理。

## 盲点

- 因未安装 expr-eval，验证未启动完整生产服务；真实令牌验证由静态确认，未变门禁、路由、Multer、Sharp、HTTP、文件系统动态执行。
- 实际容量、空闲监控、配额、容器限制与外部代理限流未知。
- .codex-deploy-tmp 的 Nginx/systemd 文件展示公开部署，但不代表每个实例。
- 数据库及其他服务同卷程度取决于部署，以及 SQLite 或远程 MariaDB。
- 手工删除可恢复空间，但仓库无自动控制防复发。

export function validatePaperFile(filename: string, size: number): string | null {
  const ext = path.extname(filename).toLowerCase();
  if (ext === ".doc") return "不支持 .doc 格式，请转为 .docx 后上传";
  if (!ALLOWED_EXTENSIONS.has(ext)) return `不支持 ${ext} 格式，请上传 DOCX/PDF/图片文件`;
  if (size > MAX_FILE_SIZE) return `文件过大（${(size / 1024 / 1024).toFixed(1)}MB），最大 50MB`;
  return null;
~~~~
