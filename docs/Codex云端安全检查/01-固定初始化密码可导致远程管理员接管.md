## 概要

**由本次变更引入。** 在这一变更范围之前，新管理员会获得由密码学安全随机源生成的 24 字节 base64url 密码，旧的 admin123 凭据也会自动轮换为随机密码。本提交用固定且公开记录的密码替换了这些保护，并在启动时将所有仍处于强制改密状态的现有管理员——包括此前使用随机初始化密码的安装实例——统一改为 admin123。

修改后的初始化逻辑为每个新建 SQLite 或 MariaDB 管理员计算常量 admin123 的密码哈希。此外，每次启动时，只要现有管理员的 password_change_required 标记仍然存在，就会将其密码重置为这个已知值。因此，未认证的网络攻击者只需使用 admin/admin123 发送一次登录请求，就能获得已认证的管理员会话，再以 admin123 为旧密码、以攻击者自行选择的值为新密码调用改密端点。强制改密门禁只阻止普通业务 API；认证和改密路由被有意挂载在该门禁之前，因此不能防止账号接管。第一次尝试就使用正确密码时，登录限流不起作用。虽然 Node 服务监听回环地址，所述部署模型通过反向代理或隧道对外提供它，使新安装或恢复后的竞争窗口可被远程利用。利用成功后，攻击者可完全控制用户、凭据、考试、成绩、敏感学生记录、备份及系统配置。

## 验证

1. 确认在近似生产的全新 SQLite 初始化中配置了固定的 admin/admin123，并确认数据库中的哈希可通过该密码验证。
2. 确认未认证请求能用该凭据登录并获得管理员会话，即使存在强制改密标记和登录限流。
3. 确认强制改密状态的会话能调用真实改密路由，以 admin123 为旧密码选择新密码，并解除门禁。
4. 通过访问仅管理员可用的 /api/users，确认新会话在强制改密门禁之后具有管理员权限。
5. 结合仓库的 Cloudflare Tunnel 和 Nginx 部署指南，确认现实的网络可达性，并记录前提与相应防护。

## 证据注释

1. 认证路由挂载在强制改密门禁之前，使持有初始化密码的人能调用改密端点。
2. 将初始化管理员密码定义为固定且公开已知的 admin123。
3. 启动时将所有仍被标记为强制改密的现有管理员重置为 admin123，使待初始化和恢复后的安装实例暴露于风险。
4. MariaDB 和 SQLite 的初始化管理员均使用该固定密码创建。
5. 公开登录路由接受这组已知管理员凭据，并创建已认证 Cookie 或 Bearer 令牌。
6. 验证旧密码 admin123 后，攻击者可以将其替换为自选密码、清除强制改密标记，并通过重新登录获得不受该门禁限制的管理员访问。

## 攻击路径分析

不适用强制排除规则：影响不限于攻击者自身；攻击者最初未认证；不存在高权限、开发者、物理访问或受保护写入路径方面的前提；文档中的公开部署流程使这些条件具有现实性。仓库证据与可执行 PoC 证明了一条从公开登录到持久管理员接管的短程远程攻击链。影响为高，因为所得身份对敏感学校数据和管理操作具有通配权限。可能性为高，因为 admin/admin123 固定且已公开记录，第一次就输入正确密码使限流失去实际保护价值，而且改密端点被有意放在门禁之前。按要求的矩阵机械计算，高影响加高可能性仍为严重，因为它直接满足威胁模型中“未认证的管理员接管”这一严重等级标准。

### 路径

未认证远程攻击者 → 访问文档支持的公开部署入口 → 反向代理或 Cloudflare 隧道将 HTTPS 流量转发到回环端口 5174 → 公开 POST /api/auth/login → 首次正确登录签发随机会话令牌 → 获得带强制改密标记的已认证管理员会话 → 认证路由位于强制改密门禁之前 → 调用门禁之前的 POST /api/auth/change-password → 已知旧密码授权替换并清除标记 → 管理员凭据由攻击者控制 → 重新登录获得不受限制的管理员通配权限 → 访问受保护数据和管理操作。

攻击过程：一个未认证的互联网用户发现了按仓库 Cloudflare 隧道或 Nginx 文档公开的 Project-X 端点。在全新、恢复或仍待初始化的实例中，启动过程创建管理员账号，或将其重置为仓库公开记录的 admin123。一次正确登录即可获得管理员会话。强制改密控制对普通 API 返回 428，但包括改密在内的认证路由有意挂载在门禁之前。攻击者因此使用 admin123 作为旧密码修改密码，清除强制改密标记，再次登录后获得不受限制的管理员权限。所提供的可执行 PoC 通过真实 Express createApp() 接口确认了完整链路，包括接管后成功访问受保护的用户列表 API。数据库以 bcrypt 哈希保存凭据，初始化文件也使用 0600 权限，但相同明文值已被硬编码并公开记录，这些存储控制无法弥补这一点。登录限流允许第一次正确尝试。服务仅监听回环、文档省略实际隧道 URL、强制改密中间件以及对已初始化管理员的保护，都是有意义的反向证据，也限制了受影响部署范围；但它们均无法防止在明确支持的公开初始化或恢复窗口内发生接管。

## 发生可能性

**高。** 按仓库记载的公开隧道和反向代理流程，可远程利用；不需要已有账号或用户交互，使用仓库公开凭据发出一次正确请求即可成功。完整接管路径已经在真实 Express 应用上执行。风险仅限全新、恢复或强制改密状态的实例，合法初始化完成后窗口结束；但这一初始化竞争是正常且有文档支持的生产流程，并非仅操作者能触发或刻意构造的状态。**攻击向量：远程网络。**

## 影响程度

**高。** 该问题越过了未认证用户到管理员的身份边界。管理员角色具有通配权限，仓库路由提供用户与凭据管理、成绩与考试、导出、扫描端/API 密钥管理、权限及完整备份恢复。因此，对教育记录和整个安装实例的机密性、完整性与可用性均具有高影响。

## 假设条件

- 目标为全新安装、恢复后的安装，或管理员仍具有 password_change_required=1 的现有安装。
- 攻击者能够在合法管理员修改初始化密码之前，访问文档中的反向代理、Cloudflare 隧道或同机 API 端点。
- 部署代码对应提交 7103440c483faab2974db72d8c3a29cdf366376b；所提供的可执行 PoC 测试了 SQLite，MariaDB 的等价性由静态分析确认。

原文另外列出的利用前提如下，重复内容予以保留：

- 存在新管理员账号，或 password_change_required=1 的现有/恢复管理员账号。
- 可以经 localhost、文档中的反向代理或 Cloudflare 隧道访问 Express API。
- 利用发生在合法管理员完成首次改密之前。

## 控制措施

- 密码以 bcrypt 哈希保存，而非数据库明文。
- 在支持的平台上，初始化密码文件以 0600 模式创建。
- 登录每 15 分钟限制为每账号 10 次、每 IP 60 次尝试。
- 认证使用随机不透明会话令牌。
- 浏览器认证使用 HttpOnly 和 SameSite=Lax Cookie。
- password_change_required 有效时，requirePasswordChangeCompleted 阻止普通 API。
- 改密会撤销该用户的其他会话。
- password_change_required=0 的现有管理员不会被重置。
- Node 进程监听 127.0.0.1，因此需要本地访问或代理/隧道。
- 下游管理路由要求认证和权限，但被接管的管理员身份具有通配权限。

## 盲点

- 仓库证据证明支持公开入口，但无法证明某个实际在线实例当前是否有可达的隧道或反向代理。
- 实际随机 Cloudflare 隧道主机名被有意省略，因此仓库并未证明攻击者能发现某个特定快速隧道部署。
- 可执行 PoC 测试了 SQLite；MariaDB 对应创建和重置分支只进行了静态检查，未动态执行。
- PoC 证明了管理员接管及访问管理员专用用户列表端点，但未破坏性地调用所有下游管理操作。
- password_change_required=0、已经完成初始化的管理员不受这条初始化路径影响。
