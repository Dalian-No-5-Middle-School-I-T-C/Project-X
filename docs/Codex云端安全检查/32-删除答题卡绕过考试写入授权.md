# 32 删除答题卡绕过考试写入授权

- 原标题：Card deletion bypasses exam-write authorization
- 云端级别：Medium
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/224e8a794eb48191b3c2c4f42aa970f2?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=&page=2)
- 关联提交：[243e8cc](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/243e8cc491f56eedd541d4d27bef521b9d8d6d1b)

## 概要

此前删被引用卡片不删考试，本提交新增级联删除／解除关联，却复用 /api/cards 非 GET 的 grade:write 门禁，而正常 /api/exams 变更需要独立 exam:write。DELETE /api/cards/:cardId 接受 deleteReferencedExams／unlinkExams，遍历全部引用卡片的考试，不再检查考试写权限或每考试范围，直接置关联为空或 deleteExamRows 永久删除逐题分、总分、扫描批次及考试。无标志时 409 还返回关联考试名。

默认旧教师同时有两权限，会掩盖问题；数据库 roles.permissions 支持细粒度分离，收紧角色的部署受影响。应对所有次级考试单独验证 exam:write 及班级／学科／考试范围后再删或解绑。

## 验证及证据

认证开启、角色只有 card:read＋grade:write 无 exam:write：可列表取得卡片 ID；直接 DELETE 考试 403，但间接卡片删除 200，真实库确认两个考试及逐题分、总分、批次、级联扫描记录移除。无标志响应泄露考试名；unlink 分支只源码追踪，未另发 HTTP。

## 攻击路径与分级

低权限阅卷账号 → 卡片列表 → deleteReferencedExams=true → grade:write 通过 → 全局查引用考试 → 无次级授权事务删除／解绑 → 跨资源破坏。

影响程度高：多考试权威记录完整性和可用性严重受损。原可能性字段先写 High，解释因默认教师本来有 exam:write、用户 API 只可分配三内置角色且无自定义编辑器、强制认证默认关闭和仅回环监听，调中；角色细粒度机制确实有效且实验可达，不排除。最终中危。

## 假设、控制与盲点

生产启用 PROJECTX_AUTH_ENFORCE；数据库角色被收紧为上述权限组合；攻击者有效账号；卡片可知且被考试引用；入口可达。现有身份、401/403、直接 exam:write、safeId、事务、无标志 409 和回环绑定不覆盖间接对象授权；默认双权限降低常见部署概率。

未找到具体代理／隧道 manifest；角色定制频率／外部管理界面未知；解绑未动态运行；下游定制中间件不在审查范围。删的是扫描元数据，外部备份或孤立图片能否帮助恢复依部署而定，不消除即时损害。
