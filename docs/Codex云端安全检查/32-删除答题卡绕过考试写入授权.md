## 概要

此问题由本次修改引入。此前删除被引用的答题卡不会删除关联考试；本次提交加入级联删除和解除关联，却复用答题卡的成绩写入权限检查，没有对新增受影响的考试资源授权。

/api/cards 将所有非 GET 请求映射到 grade:write，而考试修改要求独立的 exam:write。新 DELETE 接受可控的 deleteReferencedExams／unlinkExams，枚举所有引用答题卡的考试，不检查 exam:write 或逐考试访问权，就清空关联或调用 deleteExamRows；后者永久删除题目成绩、总分、扫描批次和考试。因此，仅有判分权限的角色只要知道答题卡 ID，就能发送带 {"deleteReferencedExams":true} 的 DELETE，毁掉全部关联考试及成绩。不提供标志时的 409 响应还会泄露考试名。默认旧版教师同时拥有两种权限，掩盖了这一角色问题；但威胁模型明确支持细粒度权限记录，分离判分与考试管理的部署会受到影响。解除关联或删除之前，必须独立检查 exam:write 以及适用的考试、班级和学科范围。

## 验证

1. 拥有 grade:write、没有 exam:write 的认证角色能够到达答题卡删除接口；直接删除考试返回 403，间接路径却继续执行。
2. 两个标志无需第二次考试写入或逐考试授权，就能修改考试。删除路径经过动态验证，解除关联路径通过源码确认。
3. 真实认证 HTTP 请求确认考试、题目成绩、总分、批次及扫描记录被删除。
4. 不提供标志时，409 响应向低权限角色泄露考试名。
5. roles.permissions 支持收窄权限；验证启用角色访问控制，且 card:read 可以通过 GET 枚举答题卡 ID。

## 证据注释

1. 新辅助函数不可逆地删除题目成绩、总分、批次和考试。
2. 非 GET 答题卡请求要求 grade:write，考试请求则要求独立的 exam:write。
3. 可控标志使所有引用考试在没有写入权限或范围验证时，就被解除关联或删除。

## 攻击路径分析

原高危正确反映了较大的技术影响和已证明的绕过，但反向证据降低了发生可能性：默认教师本来就有 exam:write，用户 API 只能分配三个内置角色，认证默认关闭，服务直接绑定回环地址。仍不排除，因为 roles.permissions 正在有效执行，收窄角色已通过正常认证接口验证，威胁模型也包含代理。高影响与中等可能性得到中危。影响不限于本人，攻击者是低权限用户而非管理员或运维，前提现实，不适用强制排除。

### 路径

拥有 card:read 和 grade:write、没有 exam:write 的账号 → GET 答题卡取得 ID → DELETE 答题卡通过成绩权限检查 → 全局查找 card_id 引用考试 → 没有逐考试授权 → 自行选择删除或解除关联标志 → 事务 DELETE 或全局 UPDATE → 考试成绩被删除，或关联被解除。

仅有判分权限的教师或控制其账号的攻击者登录远程学校服务，列出答题卡，选择其无权管理的考试所用答题卡，然后发送删除标志。答题卡权限检查放行，尽管同一账号直接删除考试会被拒绝。处理器全局枚举考试并调用辅助函数删除，没有第二次授权，永久删除考试、题目成绩、总分及批次，扫描记录又随批次级联删除。真实概念验证中，直接 DELETE 考试返回 403，间接删除答题卡返回 200；数据库确认两场考试及成绩、扫描数据被删除。不提供标志也会泄露名称。默认教师同时拥有两种权限、内置 API 没有自定义角色编辑、兼容模式默认关闭认证、服务只监听 localhost，这些降低可能性但不否定问题：权限独立保存于 roles.permissions 并被加载，生产假设启用认证，威胁模型允许代理。对于分离判分与考试管理的实例，这是真实的跨资源授权漏洞。

## 发生可能性

原栏标注 High（高），校准为中。前提成立后，只需低复杂度认证请求，无需用户交互、竞争或秘密，ID 可以列出，概念验证也已证明。但权限分离不是默认种子教师状态，用户 API 没有自定义权限编辑，需要启用可选角色访问控制，回环服务还需要代理，因此整体为中。攻击向量为远程网络。

## 影响程度

高。权限从判分越界到考试管理，能够毁坏多个关联考试、总分、题目成绩、批次及级联扫描记录，造成重大完整性和可用性影响。还可以全局解除关联，冲突响应会泄露名称。由于没有逐考试检查，可能影响其他教师、班级或学科，不限于本人。

## 假设条件

- 生产环境按威胁模型启用认证。
- Node 本身绑定回环地址，但可按威胁模型通过代理或隧道公开。
- 数据库中的教师或其他角色被收窄为 card:read 加 grade:write，没有 exam:write。
- 攻击者持有该角色的有效账号，且至少一张可发现答题卡被考试引用。

原文另列前提：

- API 可达。
- PROJECTX_AUTH_ENFORCE=1 或 true。
- 有效账号具有上述权限组合。
- 知道答题卡 ID，可通过 card:read 列出。
- 至少一场考试引用该答题卡。

## 控制措施

- optionalAuth 解析 Bearer、Cookie 或查询令牌。
- 强制认证时，makeGate 对匿名请求返回 401，缺少所选权限时返回 403。
- 直接修改考试要求 exam:write。
- safeId 验证答题卡 ID。
- 破坏性操作在事务内执行。
- 存在引用且没有标志时返回 409。
- 默认教师拥有两种权限，减少受影响的默认部署数量。
- Node 绑定回环地址，需要其他入口才能公开。

## 盲点

- 没有代理、隧道、Kubernetes、Terraform 或负载均衡清单，互联网可达性依据威胁模型部署。
- 不知道运维修改 roles.permissions 的频率，或下游外部角色管理的情况。
- 删除和名称泄露经过动态验证，解除关联只进行了源码追踪。
- 此处理器未见班级、学科或考试范围检查，但无法评估下游分支或部署中间件。
- 辅助函数删除扫描数据库元数据；外部备份或孤立图片能否用于恢复取决于部署，不能消除即时完整性和可用性影响。

function deleteExamRows(db: ReturnType<typeof getDatabase>, examIds: number[]): void {
  for (const examId of examIds) {
    db.prepare("DELETE FROM question_scores WHERE exam_id = ?").run(examId);
    db.prepare("DELETE FROM student_scores WHERE exam_id = ?").run(examId);
    db.prepare("DELETE FROM scan_batches WHERE exam_id = ?").run(examId);
    db.prepare("DELETE FROM exams WHERE id = ?").run(examId);
  }

  app.delete("/api/cards/:cardId", async (req, res, next) => {
    try {
      const cardId = safeId(paramValue(req.params.cardId));
      const card = cardRepo.findById(cardId);
      if (!card) {
        res.status(404).json({ message: "答题卡不存在" });
        return;
      }
      // 检查是否被考试引用
      const examRepo = new ExamRepository();
      const exams = examRepo.listExams();
      const referenced = exams.filter((e: any) => e.card_id === cardId);
      if (referenced.length > 0) {
        const body = (req.body ?? {}) as Record<string, unknown>;
        const unlinkExams = requestFlag(body.unlinkExams);
        const deleteReferencedExams = requestFlag(body.deleteReferencedExams);
        if (!unlinkExams && !deleteReferencedExams) {
          res.status(409).json({
            message: `无法直接删除答题卡：已被 ${referenced.length} 个考试引用`,
            referencedExamCount: referenced.length,
            referencedExamNames: referenced.map((e: any) => e.name)
          });
          return;
        }
        const db = getDatabase();
        db.transaction(() => {
          if (deleteReferencedExams) {
            deleteExamRows(db, referenced.map((e: any) => Number(e.id)));
          } else {
            db.prepare("UPDATE exams SET card_id = NULL, updated_at = CURRENT_TIMESTAMP WHERE card_id = ?").run(cardId);
          }
          cardRepo.deleteCard(cardId);
        })();
