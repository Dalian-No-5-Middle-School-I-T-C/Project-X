## 概要

本变更新增脆弱 POST /api/review/exams/:examId/block-crops/:cropId/submit 和 ReviewService。它把未结构验证的请求对象交给 upsert，允许插入不存在题目，重算权威总分/排名时使用攻击者控制的成绩元数据。

具有成绩读写权限及考试访问的教师可从队列获得有效裁图 ID，提交任意 scores 数组。路由只检查非空数组。服务虽加载裁图和答题卡，却从不验证 questionNumber 是否在裁图 question_numbers 中、属于其题块，或甚至存在于卡上，还信任 scoreType。尤其客户端 maxScore 优先于权威值；未知题目直接以提交分数为满分。例如 {"questionNumber":999999,"scoreType":"subjective","score":1000000,"maxScore":1000000} 会插入新的满分题。score_type 是 upsert 冲突键的一部分，任意类型还能为同一题创建多条唯一行。服务随后将所有行计入学生总分并重算排名。对队列返回裁图反复操作，可在可访问考试内规模破坏，并跨客观题、主观题和题块边界。必须仅从所选裁图和权威题块派生成员、类型和满分，拒绝未知/重复题和非有限数，并在写入前执行题块阅卷范围。

## 验证

1. 确认正常成绩权限、合法考试范围的非管理员教师可达提交并获得裁图 ID。
2. 确认路径接受可控 questionNumber、scoreType、score、maxScore，不执行裁图/卡成员、类型、边界、重复或有限性检查。
3. 确认服务/schema 允许不存在题目，以及通过攻击者选择 score_type 创建一题多行。
4. 经真实 HTTP 动态证明伪造行改变权威总分和排名。
5. 识别实质前提、防护，包括考试/裁图检查与审计，区分已证明完整性和未测试可用性/规模主张。

## 证据注释

1. 新路由只查 scores 为非空数组，直接转发全部可控字段。
2. 服务验证裁图属于考试并构建全卡满分元数据，但不解析/执行裁图题目列表或题块成员关系。
3. 信任客户端 maxScore/scoreType，未知题以提交分为上限，upsert 插入伪造题分。
4. 全部题分行进入权威总分，随后整场排名重算。

## 攻击路径分析

不适用强制排除：非本人影响、正常可达前提，攻击者是部分可信普通教师而非管理员、操作者、开发者或主机用户。虽然 grade:write 是受保护写权，教师本就可有意改已有分，但已证明权限差异为逃出所选裁图权威题目/满分边界，插入伪造规范数据。使用文档公开 HTTPS 时网络可能性高，已经真实认证 HTTP 演示。总分与同学排名被破坏，影响高；仅需构造请求与队列裁图 ID，可能性高。矩阵为高危而非严重，因为限认证成绩写者可见考试、需已有裁图、有审计，没有全局接管、广泛泄密或已证明跨考试破坏。

### 路径

认证学科教师 grade:write → 有效 Bearer/Cookie → 文档 HTTPS 到 Express → GET 可访问考试队列 → 返回有效 crop ID → 携该 ID 提交伪造 JSON → 路由仅查非空数组 → 服务信任题号、类型、分数、满分 → upsert 未验证元数据 → question_scores 产生伪造/重复类型行 → 所有行求和并重排 → student_scores 总分及考试排名改变。

攻击过程：默认成绩权限学科教师打开正常阅卷，取得可访问考试裁图 ID，以伪造分数对象替换浏览器请求。路由仅验证非空数组。ReviewService 虽检查裁图—考试并加载卡，却不用保存的 question_numbers，也不限制为其题块。接受任意 scoreType，客户端 maxScore 优先，未知题回退到提交分。score_type 在冲突键中，变换类型还可给已有题建立并行行。所有行汇总并重算排名。可执行验证开启认证、使用普通 subject_teacher，返回 200，插入题号 999999 的 1,000,000 分和另一条攻击者类型的第 1 题，将受害者从总分 5/排名 2 改为总分 1000505/排名 1。现有控制实质限制为认证成绩写者和可见考试，需真裁图/卡，并建审计；却不执行题目/类型/满分边界。浏览器通常只提交 current.questionNumbers 和派生类型，但原始 HTTP 控制 JSON，服务端不能依赖 UI。无秘密披露或代码执行入口。

## 发生可能性

**高。** 普通 JSON 请求，低复杂度，无竞态/交互。默认教师有写权，队列给有效 ID，认证开启 PoC 成功。前提仅教师、可见考试、既有学生裁图。Node 直接回环，但文档公开 HTTPS。认证与考试范围阻止匿名、学生和跨考试，却不使范围内教师路径不现实。**攻击向量：远程网络。**

## 影响程度

**高。** 权威教育记录完整性严重受损。可加不存在题目、制造满分、创建同题并行行、抬高或改变总分，并改变本人目标及同学排名。队列使在可见考试多裁图重复现实。无泄密、跨考试、代码执行或全实例管理控制，审计使修改可检测。

## 假设条件

- 生产按威胁模型开启认证，不过提交路由独立要求认证及 grade:write。
- 远程依文档 HTTPS Nginx，Node 本身 127.0.0.1:5174。
- 普通教师有 grade:read、grade:write 及目标可见性。
- 考试关联答题卡，至少有一张关联学生的裁图。

## 控制措施

- optionalAuth 解析 Bearer/Cookie，requirePermission 拒匿名提交。
- 阅卷路由需 grade:write。
- requireExamAccess 限制学科教师至其学科/分配班级。
- 服务要求裁图属于考试且关联学生。
- 服务要求考试引用既有卡。
- 题分与总分更新有事务。
- 名义分数钳位无效，因为上限由攻击者控制或回退到其分数。
- 写入标记 manually_modified，answer_overrides 记录操作者，可审计不预防。
- Node 回环，部署指南经 HTTPS 代理公开。

## 盲点

- 只有部署指南，无环境特定入口清单，不能静态证明某实例公网可达。
- 动态 SQLite；MariaDB 列及唯一语义同样宽松，但未重放 PoC。
- 未负载测试多裁图重复和可用性；证明一名学生总分及对应考试排名。
- 本提交没有建立阅卷分配/领取模型，报告不依赖跨指定阅卷人边界。
- 另一个手工改分端点已允许写者改既有分，限制仅归于本端点的增量排名破坏能力；伪造题目、类型和满分元数据仍是独特已证明效果。
- 未确定该端点改分是否自动撤回已发布结果。

  const maxScoreByQuestion = new Map<number, number>();
  for (const block of card.bodyBlocks) {
    if (block.type === "objective") {
      for (const def of objectiveQuestionDefinitions(block)) {
        maxScoreByQuestion.set(def.questionNumber, Number(def.score ?? 0));
      }
    } else if (block.type === "subjective") {
      for (const question of block.questions ?? []) {
        const qNum = typeof question.number === "number" ? question.number : parseInt(String(question.number), 10);
        if (Number.isFinite(qNum)) maxScoreByQuestion.set(qNum, Number(question.score ?? 0));
