## 概要

本次提交在新的扫描同步路径中引入判分完整性的失败后放行。远程认证失败和可达的 404 会拒绝继续，但可用性失败会回退到没有版本信息的本地答题卡，调用方在本地判分之前又丢弃来源信息。

配置远程模式后，fetchSynced 将所有网络错误、超时、HTTP 5xx，甚至成功但包含非法 JSON 的响应，都视为静默读取本地同一对象的理由。函数虽然返回 source，fetchCardByIdSynced 却丢弃它。ScannerApp 无法区分权威远程数据和离线缓存，将整张答题卡导入本地并进入工作区，随后本地判分端点使用其布局及答案。现实顺序是学校修改或删除答题卡，扫描机保留旧定义，相邻网络或在途攻击者在选择之前阻断详情请求；HTTPS 不能防止丢包。扫描机没有逐卡警告或确认，就接受旧卡；如果刚取得远程列表，页脚甚至可能仍显示同步成功。同一 ID 因而产生看似可信却错误的 OCR 对齐或客观题分数。远程模式详情应在失败时拒绝继续，或返回并强制验证版本／校验和；显式离线模式应要求确认缓存版本，上传携带版本，使服务端能够拒绝不匹配扫描。

## 验证

1. 远程详情遇到网络失败、5xx 或非法 JSON 时返回本地内容，401、403 和 404 则拒绝继续。
2. 调用方丢弃来源，没有缓存警告、确认或新鲜度检查，就导入并进入工作区。
3. 同 ID 的陈旧答题卡被接受，本地判分使用旧布局和答案，复现了 10 分与 0 分的差异。
4. 执行真实同步、导入、判分模块及已有冒烟框架，复现行为和控制。
5. 确定远程配置、不同缓存、操作者选择及判分，以及能够中断详情请求的匿名在途攻击者前提。

## 证据注释

1. 工作区通过内嵌本地答题卡端点判分，使缓存成为显示成绩的权威来源。

## 攻击路径分析

单独策略检查不适用强制排除：影响不限于本人，不需要运维或管理员权限，前提现实。获授权操作者点击属于受害者交互，攻击者控制的是匿名网络中断。仓库和可执行证据建立从回退到判分的完整链条，但限于内部 Electron 扫描流程，需要相邻网络或在途位置，以及内容不同的缓存。旧布局和答案可能影响一批结果，因此影响高；本地网络位置及时间、状态条件使发生可能性为中。按矩阵，高影响与中等可能性得到中危，保留该级别。

### 路径

匿名相邻网络或在途攻击者 → 丢弃或重置出站的已认证详情连接 → 网络错误被 fetchSynced 的宽泛 catch 捕获 → 静默回退本地同一对象 → 内嵌数据库中的同 ID 旧答题卡 → source 被丢弃，旧卡被接受 → 本地答题卡及布局更新或插入 → 工作区进行本地 OCR 和判分 → 旧答案及布局决定分数 → 显示错误结果，并可导出。

攻击过程：扫描机刚取得远程列表，却在本地缓存同 ID 旧卡；操作者选择时，在途攻击者阻断详情。攻击者无需凭据，也无需破坏 HTTPS 机密性，只要干扰可用性。scannerSync 捕获 401、403、404 之外的失败并读取本地，详情封装去掉离线来源。ScannerApp 保存答题卡并进入工作区，用旧卡判分。导入真实同步及判分模块的复现表明，旧答案得到 10 分，而权威答案为 0 分，也确认网络错误、500 和畸形 JSON 都会回退。匿名攻击者跨越网络信任边界，有意选择陈旧的可信状态，因此是安全完整性问题，而不只是偶发正确性故障。强反向证据包括回退是有意设计、列表可显示“离线·显示缓存”、健康状态单独显示、认证及 404 拒绝继续、远程 API 密钥／JWT 强授权，以及内嵌回环监听。但详情来源已丢弃，列表状态不会随详情回退变化；选择性失败下，健康状态可能滞后或仍正常，没有控制阻止判分或验证版本。仓库证明错误的本地显示和 CSV 导出，没有证明直接写入中央成绩库；后台上传只携带 cardId，没有版本，权威服务端可能另行处理。

## 发生可能性

中。无需凭据，但需要能够中断出站连接的相邻网络或在途位置、同 ID 的不同缓存、远程修改或删除，以及故障窗口内操作者选择并判分。这些条件需要同时满足，但对于有意提供离线模式的受管理学校扫描机而言现实可行。按网络范围权重，本地网络及现实前提产生中等可能性。

## 影响程度

高。旧答题卡直接控制 OCR 几何布局、客观题答案、题目分值及总分。验证确定了 10 分与 0 分的差异，工作区能够批量处理并导出 CSV，支持潜在的高判分完整性影响；没有证明直接修改中央权威数据库。

## 假设条件

- Electron 配置远程同步及有效 scanner／full 密钥。
- 内嵌数据库保留同 ID 旧卡，远程随后变更或删除。
- 相邻网络或在途攻击者在选择时丢弃或重置详情连接；另一可能是远端 5xx。
- 操作者在恢复权威连接或发现陈旧内容之前选择并判分。
- 高影响假设本地或 CSV 批量分数被学校业务使用；没有确立直接进入中央数据库。

- 选择前后，攻击者能够中断权威详情请求。
- 操作者继续识别和判分。

## 控制措施

- 远程接口要求 scanner／full API 密钥或非学生认证 JWT。
- 401／403 传播给调用方，不回退。
- 权威 404 传播，停留在选择页并刷新列表。
- 列表页脚可以区分远程、本地和离线缓存。
- 独立状态轮询检查健康状态。
- 内嵌服务绑定回环地址，Electron 使用隔离、沙箱并禁用 Node 集成。
- 密钥通过 X-Api-Key 发送，服务端哈希匹配；扫描端在 localStorage 保留 30 天。
- HTTPS 保护机密性和真实性，不防止在途攻击者丢弃连接。
- 没有详情来源强制检查、不可变版本、上传版本绑定或阻断式离线确认。

## 盲点

- 没有清单证明远程端位于公网、VPN 或校园局域网。
- 复现模拟传输边界并导入生产模块，没有对打包 Electron 真实丢包，也没有运行原生 OCR。
- 不知道本地答题卡偏离权威版本的实际频率。
- 证明了显示及 CSV 中的旧分数，没有证明中央权威表直接保存。
- 后台图片和 cardId 不带版本，所审路径不能证明后续服务端会纠正、拒绝还是重复本地结果。
- 操作者注意到连接指示、旧内容或异常分数的概率未知。

async function fetchSynced<T>(localPath: string): Promise<{ data: T; source: SyncSource }> {
  const base = getRemoteBase();
  if (base) {
    const remotePath = toRemotePath(localPath);
    try {
      const res = await remoteScannerFetch(remotePath, {
        headers: getStoredApiKey() ? { "X-Api-Key": getStoredApiKey()! } : undefined,
      });
      if (!res.ok) {
        const status = res.status;
        let msg = res.statusText;
        try { const body = (await res.clone().json()) as any; msg = body?.message || body?.error || msg; } catch {}
        // 401/403 鉴权失败不回退；404 权威删除不回退；网络/5xx 才回退
        if (status === 401 || status === 403) {
          throw Object.assign(new Error(msg), { status, remoteAuthFailed: true });
        }
        if (status === 404) {
          throw Object.assign(new Error(msg), { status, remoteNotFound: true });
        }
        throw Object.assign(new Error(msg), { status });
      }
      return { data: (await res.json()) as T, source: "remote" };
    } catch (e: any) {
      if (e?.remoteAuthFailed || e?.remoteNotFound || e?.status === 401 || e?.status === 403 || e?.status === 404) throw e;
      // 网络错误 / 5xx / 超时 -> 静默回退本地
    }
  }
  const data = await fetchJson<T>(localPath);
  return { data, source: base ? "offline-cache" : "local" };
}
