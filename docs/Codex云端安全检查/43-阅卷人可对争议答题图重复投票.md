# 43 阅卷人可对争议答题图重复投票

- 原标题：Reviewer can cast duplicate votes on disputed answer crops
- 云端级别：Informational
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/27eec6b2da8c8191b31f11c048bf597f?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=&page=3)
- 关联提交：[df48a8e](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/df48a8ea0fc4286336d22928450397ac60fbce77)

## 概要

提交将重复阅卷人拒绝与轮次数限制改为依赖争议状态：disputed 图块允许原阅卷人再次提交，最多接收 reviewMode + 2 条记录，却未验证提交者是否新指派复评人或仲裁人。重复评分被当作独立意见，可能影响多数判定、题目成绩与学生总分，也可绕过已配置仲裁人的实际裁决作用。

## 验证与路径

原测试在数据库预置争议图块后，通过生产已认证 POST /api/review/exams/:examId/block-crops/:cropId/submit 复现：[10,0] 争议 → 原给 0 分者再次提交 0 → [10,0,0] 被中位数相邻多数算法判定解决 → 最终分数 0 写入 question_scores 与 student_scores，并重算总分/排名。记录中的 reviewer ID 未按独立身份去重。

普通教师需 grade:read、grade:write、目标考试访问权、图块 ID，且已存在于该图块评分历史。缺少领取、指派或预期复评人校验；配置仲裁人只会阻止仲裁人参与初评，并不阻止原阅卷人重复复评。

## 等级判断与关键可达性限制

技术影响中等、可能性低，初步为低危，最终显示信息提示。关键原因是该提交的 schema 将 review_round 默认设为 1，而服务按从 0 开始递增并限次，似乎会阻止正常第二次评阅及争议状态形成；未找到其他生产代码写入 disputed。PoC 必须通过受保护的数据库写入预置前提，未证明低权限用户可正常构造该状态，因此按策略排除，而不是因为接口已认证或监听回环地址。

一旦前提存在，真实成绩、总分及排名会受到影响；单请求只影响一张图块，分数有上下限，历史保留身份、分值和时间，可审计恢复。可对多张争议图重复操作。

## 防护与盲点

认证、考试范围、图块所属考试、分数范围均有检查；非争议状态拒绝重复阅卷人；争议复评有数量上限；事务与 review_round 比较交换防止并发覆盖；专门仲裁端点要求指定仲裁人。未发现一般提交限流，也未发现争议复评身份授权。

文档支持 Cloudflare Tunnel 暴露回环服务，但未检查具体部署。未重建历史版本/恢复库形成争议记录的全过程；外部工具、管理员或旧数据库可能已有此类记录，但仓库未证明其现实低权限产生路径。
