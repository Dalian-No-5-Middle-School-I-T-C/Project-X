## 概要

这一变更移除判分上传路由的考试范围检查，引入授权回归。剩余 cardGate 仅确立广义 GRADE_WRITE 能力；validateExamIdsAccess 仍实现必要的对象可见性检查，却不再于成绩持久化前调用。

POST /api/cards/:cardId/grading 仅受通用 grade:write 保护，从 multipart 请求体接收 examId，直接传给 persistGradingResults，不调用 validateExamIdsAccess。学科教师或班主任因此可以指定分配学科/班级以外的考试，上传含自选学号和答案的有效答题卡图像。持久化仅验证考试与学生存在，随后改变考试状态、创建扫描批次，并为每张识别图像 upsert student_scores 和 question_scores。路由也不要求所选卡匹配目标考试的卡，进一步简化滥用。成功批次可覆盖多名学生成绩并关闭未授权考试。基线版本明确解析 examId 并调用 validateExamIdsAccess，对可见范围外考试返回 403。

## 验证

1. 实际认证和 cardGate 链允许默认 grade:write 的受限教师访问判分端点，而有考试范围检查的端点对相同目标返回 403。
2. multipart examId 可控，独立于路由卡传到持久化；复现用 attacker-card 指向配置 target-card 的考试。
3. persistGradingResults 接受既有范围外考试，在没有等效范围检查时修改扫描批次、学生总分、题分及流程状态。
4. validateExamIdsAccess 是适用的对象范围控制；当前路由缺少它，且由目标回退提交明确移除。
5. 经真实认证 HTTP/multipart 接口以针对性断言复现授权绕过，并将原生 OCR 替身记为剩余证明限制。

## 证据注释

1. 持久化仅检查考试存在，立即改状态并创建判分批次。
2. 学号全局解析，随后 upsert 目标考试总分及逐题分数。
3. /api/cards 写入口只受 GRADE_WRITE 保护，无考试级范围。
4. 路由接受可控文件和 examId，不再验证调用者能访问该考试。
5. 未检查 examId 直接进入持久化。
6. 既有辅助函数执行教师考试可见性并返回 403，但路由不再调用。

## 攻击路径分析

确定事实后，矩阵将高影响、高可能性映射为高危，除非明确满足严重条件。直接可执行证据包括范围外总分替换、题分替换、扫描批次创建和考试关闭，支持高影响。正常产品端点可远程暴露、教师默认 grade:write、examId 可控且危险操作处无对象授权，支持高可能性。不适用强制排除：影响不限自身；前提现实；攻击者为普通受限教师，而非管理员、操作者、开发者或主机用户；权限增益是修改明确超出其班级/学科范围的考试。未升严重，因为仍需可信教师凭据、目标标识及成功识别输入，已证明效果限于所选学校实例/考试，而非未认证全实例失陷。因此最终可报告等级为高危，无策略排除。

### 路径

有默认 grade:write 的学科教师/班主任 → 认证 HTTP → 可公开隧道转发的回环 5174 Express → /api/cards 中间件 → cardGate 通用能力通过而无考试可见性检查 → 带文件和请求体 examId 的判分 POST → 按 URL 卡识别并判分 → 识别行和独立请求体 examId 转发 → persistGradingResults 未校验目标考试权限 → 仓储 upsert 分数并改变流程 → 范围外考试成绩、批次和状态被修改。

React 客户端将此 POST 作为正常答题卡判分与持久化流程。认证默认开启，教师默认满足 POST 的 grade:write，但门禁没有考试上下文。路由分别读取 URL cardId、multipart 文件和 examId，按所选卡判分，将未检查 examId 转发。持久化只查考试及全局解析学生存在，接着改状态、建批次、写两类分数；不比较 cardId 与 exam.card_id。可执行 HTTP 复现使用真实认证 Express 路由、中间件、仓储、事务与 SQLite，演示受班级限制的学科教师将范围外总分 3 改为 10、写题分、建已完成批次，并关闭关联另一张卡的考试。原生 OCR 被确定性、契约兼容识别器替代，限制了对具体图像像素构造的结论，却不削弱成功识别后授权/持久化失败的证明。无需或不会暴露秘密；敏感数据流是攻击者选择的判分输入写入权威成绩与考试流程。强反向证据为回环、教师认证及仍存在 validateExamIdsAccess；但文档通过公开隧道暴露 5174，普通教师有写权限，受影响路由又不调用对象辅助函数，故不能否定。这是可报告授权漏洞，而非纯正确性缺陷。

## 发生可能性

**高。** 正常第一方判分流程可经文档 Cloudflare 隧道远程到达。教师默认有权限，无受害者交互，HTTP 复现证明完整认证至数据库路径。前提仅为受限教师、考试 ID、已有学号和可成功识别文件。确定性替身留下对恶意像素可靠构造的疑问，但教师也可提交原本就能识别的有效卡片，只改 examId 重定向持久化，因此对内部威胁仍现实且低复杂度。**攻击向量：远程网络。**

## 影响程度

**高。** 目标是权威学业数据。受限教师可覆盖分配学科/班级之外考试中一名或多名已识别学生的总分及题分，创建看似合法且归于该教师的批次，并把活动考试变为 grading 或 closed。这跨明确教师/考试边界，可实质影响学业结果。不依赖机密性影响，完整性高，流程可用性影响次之。

## 假设条件

- 生产使用默认强制认证，未显式将 PROJECTX_AUTH_ENFORCE 设为 0/false。
- 攻击者有合法或失陷学科教师/班主任账号，完成必要强制改密，因此有默认 grade:write。
- 知道或可获得一个既有范围外数字考试 ID 和至少一个已有学号。
- 上传必须产生成功识别结果；PoC 使用确定性替身，未确立特定物理像素构造可靠性。
- scope.auth 的 internal_only 指普通认证学校工作人员，而非管理员专用或匿名端点。

原文另列前提：

- 有 grade:write 的认证教师。
- 教师学科/班主任范围不包含目标考试。
- 判分路由接受的既有卡 ID。
- 既有范围外考试 ID。
- 能成功识别出已有学号的上传文件。

## 控制措施

- 除显式 0/false 外默认强制认证。
- API 前解析 Bearer/Cookie 身份，待改密账号不能使用其他 API。
- cardGate 对匿名返回 401、无 grade:write 返回 403。
- 默认学生无写权限，已演示攻击者为教师。
- 调用 getVisibleExamIds / validateExamIdsAccess 的路由正确实现学科/班主任范围。
- 脆弱路由未调用 validateExamIdsAccess。
- CORS 允许列表不是授权，不阻止直接认证 HTTP。
- 识别上传单文件 20 MiB。
- 持久化验证考试/学生存在并按学生使用事务，但不是授权。
- 后端回环监听，文档 Cloudflare 可使之远程可达。
- 有登录限流，无判分路由限流缓解已认证教师。

## 盲点

- SQLite 动态复现，未单独执行 MariaDB，二者共享仓储/适配接口。
- OCR 用成功输出契约的确定性实现替代，未量化任意物理图像强制指定识别的可靠性。
- 文档支持公开 Cloudflare，实际部署未知；无隧道实例可能仅本机或其他可信代理可达。
- 静态证据不能确定隐藏考试 ID、全部目标学号发现难度；它们是普通学校业务标识，复现证明知道即可利用。
- 检查的仓库没有独立网络策略、代理访问控制或外部身份感知代理清单。
- 实际单请求可修改学生数依识别吞吐、请求处理和单文件上限之外的运行限制。

~~~~typescript
export async function validateExamIdsAccess(req: express.Request, res: express.Response, examIds: number[]): Promise<boolean> {
  const visibleIds = await getVisibleExamIds(req.user);
  if (visibleIds === null) return true;
  const visible = new Set(visibleIds);
  const denied = examIds.filter((examId) => !visible.has(examId));
  if (denied.length === 0) return true;
  res.status(403).json({ message: "权限不足：考试组包含不可访问的考试" });
  return false;
~~~~
