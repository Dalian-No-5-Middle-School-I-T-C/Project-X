## 概要

此问题由本次修改引入。提交新增考生搜索路由及全局搜索函数，后者以 _examId 接收考试 ID，却不使用；路由也没有应用已有的 can_view_students 权限矩阵检查。

能够访问任意一场考试且拥有普通 GRADE_READ 的教师，可调用 GET /api/exams/:examId/participant-search。虽然存在 requireExamAccess 和粗粒度角色检查，却缺少 makeViewPermissionGate("can_view_students")。更重要的是，searchStudentsForExam 有意忽略考试 ID，查询全部活动学生，没有联结考试、参考名单、教师班级或权限矩阵。学科教师或班主任因此能获得其他班级和年级的学生 ID、姓名及学号。LIMIT 20 不能防止枚举，攻击者可反复搜索学号前缀或姓名片段，威胁模型中的服务也没有一般限流。这与已有学生搜索的实现冲突：后者既检查 can_view_students，又将结果限制为目标考试中已有成绩的学生。结果是教师对学生及班级范围的授权绕过，可能泄露全校目录。

## 验证

1. 路由要求认证，但具有考试访问权及普通 GRADE_READ／EXAM_READ 的非管理员教师能够访问。
2. 缺少类似 student-search 所采用的细粒度检查，对照端点返回 403。
3. 可控 q 进入全部活动学生查询，没有应用考试、班级、年级或教师范围。
4. 真实 HTTP 响应返回其他班级及年级的 ID、姓名和学号。
5. LIMIT 20 不是授权控制；两次前缀查询枚举了全部 25 名预置的范围外学生。

## 攻击路径分析

不适用强制排除：影响不限于本人，前提现实，低权限教师不是管理员、运维、开发者或本机特权用户；生产流程越过明确的学生列表及班级、年级边界。尽管服务绑定回环地址，文档仍支持远程部署。攻击者可以枚举整个实例中可识别身份的学生目录，但不影响成绩、凭据、写入或可用性，因此影响为中。默认普通读取权限即可使用，真实接口也验证成功，发生可能性高。按矩阵，中等影响与高可能性得到中危，保留原级别。

### 路径

文档中的公共 HTTPS 隧道或代理 → 教师正常登录 → 学科教师或班主任选择任意可访问考试，控制 examId 和 q → participant-search?q=`<prefix>` → EXAM_READ、requireExamAccess 和 GRADE_READ 通过 → 缺少 can_view_students 检查 → 忽略 examId，将 q 传入参数化全局查询 → SELECT 全部活动学生 → 每次返回 20 条，通过前缀继续枚举 → 跨班级及年级的目录披露。

攻击过程：教师或控制其账号的用户登录，选择允许访问的考试，连续查询学号前缀或姓名片段。全局考试读取、考试访问和成绩读取检查通过，但不读取学生权限矩阵。函数有意接收 _examId，却不联结考试考生、班级、年级、教师班级或权限。响应直接暴露匹配的 ID、姓名和学号。采用默认生产认证的真实 Express 概念验证返回 200 及 20 条范围外记录，两次前缀查询枚举 25 名学生；类似的受保护搜索返回 403，不可访问考试也返回 403。不返回凭据或秘密，没有执行或写入效果。范围方面的反向证据包括回环监听、文档中的管理员跨年级名单需求、认证、有效考试访问、仅活动学生、参数化 SQL 和 20 行上限。文档中的代理使其不限于本机；管理员跨年级流程不能合理化普通教师绕过明确的 can_view_students=0；前缀查询又绕过单次行数限制。因此，这是可报告的机密性授权绕过，而非纯正确性问题。

## 发生可能性

高。只需普通已认证教师、一个可访问考试及默认读取权限。这是正常 Web 流程，文档支持远程访问，复杂度低，概念验证确认跨范围访问和前缀枚举。认证及考试可见性缩小攻击群体，但权限和状态在威胁模型中现实存在。攻击向量为远程网络。

## 影响程度

中。稳定账号 ID、姓名和学号跨越教师、班级、年级及学生列表边界，可以重复查询直至覆盖整个实例。没有成绩、密码、答卷图片或秘密，也不修改记录，因此机密性影响具有实质意义，但不达到高。

## 假设条件

- 部署包含多个班级或年级，且存在范围外活动学生。
- 合法或失陷教师账号具有普通 EXAM_READ／GRADE_READ，以及至少一场考试的访问权。
- 远程访问依赖文档中的 Cloudflare／Nginx，Node 本身绑定回环地址。
- 按威胁模型，姓名、学号及稳定 ID 属于受保护的学校目录数据。

原文另列前提：

- 存在已认证教师账号。
- 具备 EXAM_READ 和 GRADE_READ。
- 能访问任意有效且未软删除的考试。
- 非空、可控 q 能匹配活动学生。
- 同一实例中存在范围外学生。

## 控制措施

- 默认强制认证，拒绝无有效身份的请求。
- 全局考试 GET 要求 EXAM_READ。
- requireExamAccess 拒绝范围外访问，并隐藏软删除考试。
- 路由额外要求 GRADE_READ。
- 待强制改密账号被阻止访问其他 API。
- 只返回活动 student 角色。
- SQL 绑定参数并转义 LIKE 通配符，防止注入及纯通配符直接导出全部数据。
- 每个请求最多返回 20 行。
- 缺少的是类似端点已经使用的 can_view_students 检查。
- 没有专用或一般限流来防止重复前缀枚举。

## 盲点

- 动态验证使用 SQLite，没有单独测试 MariaDB；共享中间件和适配查询使数据库方言导致授权差异的可能性较低。
- 实际部署可能没有公网入口，范围限于本机或学校网络。
- 真实学生数量和敏感性取决于学校。
- 文档中的跨班级、年级显式名单属于管理员用途，应澄清候选搜索范围；这不消除普通教师已证明的权限绕过。
- 没有检查生产审计或真实学校数据。

export async function searchStudentsForExam(
  db: DbAdapter,
  _examId: number,
  q: string
): Promise<Array<{ id: number; name: string; student_number: string | null }>> {
  const keyword = (q ?? "").trim();
  if (!keyword) return [];
  const escaped = keyword.replace(/[\\%_]/g, (m) => `\\${m}`);
  const rows = await db.all(
    `SELECT u.id, u.name, u.student_number
     FROM users u
     WHERE u.role_id = ? AND u.is_active = 1
       AND (u.student_number LIKE ? ESCAPE '\\' OR u.name LIKE ? ESCAPE '\\')
     ORDER BY u.student_number
     LIMIT 20`,
    ROLE_IDS.STUDENT, `${escaped}%`, `%${escaped}%`
  ) as Array<{ id: number; name: string; student_number: string | null }>;
  return rows.map((r) => ({ id: r.id, name: r.name, student_number: r.student_number }));
