## 概要

此问题由本次提交引入。提交向用户提供并开始使用新的选项布局字段，却没有实现端到端规范化和数据库持久化。

提交在题块和题目两个层级加入 optionLayout，并用它选择新的 vertical-grid 布局。然而，CardRepository 既没有把该属性写入 objective_blocks 或 objective_questions，也没有在 findById() 中重建。因此，普通用户可以选择纵向布局，并收到包含纵向布局的成功 PUT 响应，但下一次 GET 会丢失设置，objectiveQuestionDefinitions() 将其默认为 horizontal。服务端 PDF 生成、布局重建和识别路由都通过 findById() 加载答题卡，因此也会采用恢复后的横向排列。单题设置甚至会更早丢失，因为 normalizeObjectiveQuestions() 返回的配置省略了 question.optionLayout。这不是授权边界漏洞：只有本来就有权设计答题卡的用户能够触发，而且文档中的 PDF 流程通常会生成前后一致的横向答题卡。不过，这仍是可靠性缺陷，会使导出或缓存布局不一致；如果以纵向预览或过时纵向布局作为实体答题卡来源，还可能产生错误识别。应通过数据库迁移和仓储读写路径持久化该字段，在 normalizeObjectiveQuestions() 中包含它，并增加保存、重新加载和 PDF 的往返测试。

## 证据注释

1. 新增面向用户的选择器将纵向布局保存在 ObjectiveBlock.optionLayout 中。
2. 数据库写入路径既不保存题块级 optionLayout，也不保存单题级 optionLayout。
3. 数据库读取路径重建客观题块及题目时省略了两个层级的布局属性，导致设置在重新加载后消失。
4. 题目规范化会重建每道题的配置，却省略新增 optionLayout，因此丢弃单题值。
5. 布局选择依赖丢失的属性；重新加载后没有该属性，规范化题目就会默认为 horizontal，而非 vertical-grid。

## 攻击路径分析

策略调整前的严重性仍为低，因为已证实的效果是数据一致性及可靠性故障，而所声称的学业完整性影响还需要额外发生过时实体答题卡不匹配。最终策略阶段适用强制排除：现实触发方式是已授权或本地答题卡写入操作，操作者没有获得超出其原有重写答题卡能力的权限或跨边界能力。最强反向事实是 PROJECTX_AUTH_ENFORCE 默认关闭，但这对本问题不具有决定性，因为仓库中的服务绑定 localhost；即使存在外部代理，能够 PUT 整张答题卡的未认证调用方，也可以直接损坏答题卡，无需依赖 optionLayout 丢失。影响为 low、发生可能性为 ignore 时，所要求的矩阵得到 adjusted_criticality=ignore。

### 路径

已授权教师或本地答题卡设计者 → 选择受支持的纵向排列 → React 纵向布局选择器或构造的 optionLayout JSON → 客户端提交完整答题卡 JSON → Express 答题卡服务上的 PUT /api/cards/:cardId → 服务规范化提交的答题卡 → normalizeCard() 和 normalizeObjectiveQuestions() → 单题值被省略，仓储也没有持久化列 → CardRepository 及 objective_blocks／objective_questions 表 → 重新加载时不重建题块级或题目级布局属性 → CardRepository.findById() 返回不含 optionLayout 的答题卡 → 缺失属性默认为 horizontal → buildLayout()、PDF 和识别重新生成横向坐标 → 产生已证实的布局不一致及条件性的识别完整性风险 → 设置丢失，或实体答题卡与识别布局在特定条件下不匹配。

攻击情景：教师或其他已获准设计答题卡的用户选择受支持的纵向布局并保存。PUT 路径计算并返回纵向布局，但规范化省略单题 optionLayout，仓储结构及读写路径同时省略题块级和题目级的值。后续重新加载将答题卡默认为横向，通过 findById() 加载的布局、PDF 和识别路径也使用恢复后的排列。可执行验证确认了纵向到横向的坐标变化。反对安全可报告性的最强证据是：启用角色访问控制时，这属于受保护的答题卡编写操作；操作者本来就有权修改整张答题卡及答案，没有跨越权限、身份、考试或保密边界。虽然认证强制执行默认关闭，但服务绑定回环地址，且该遗漏没有增加直接修改答题卡之外的能力。正常服务端 PDF 生成会重新加载持久化答题卡，因此通常生成一致的横向答题卡；实际判分损害还需要额外使用过时或外部生成的纵向实体答题卡。这些事实决定可报告性，但并不否定正确性缺陷的存在。

## 发生可能性

忽略（Ignore）。通过正常使用很容易触发功能缺陷，但有意义的安全攻击需要答题卡编写写入路径。强制角色访问控制下，这条路径属于本来就能修改整张答题卡和判分配置的教师；默认配置下，除非存在尚未证实的外部入口，否则只能通过回环访问。该遗漏没有为低权限操作者增加安全能力，因此适用特权／受保护写入路径排除规则。

## 影响程度

低（Low）。可执行概念验证证明，受支持的设置丢失，重新加载前后的纵向与横向坐标不一致。没有发生机密泄露、代码执行、身份失陷、提权或授权绕过。识别错误只是条件性的完整性后果，需要在重新生成横向布局之后继续使用过时或实体纵向答题卡，且没有完成端到端演示。

## 假设条件

- 评估的工作区确切位于提交 c3d94344dd22c0125d49053e16ec70cf7790dd2d。
- 启用 PROJECTX_AUTH_ENFORCE 时，答题卡写入要求已认证角色满足答题卡入口的写入权限；该提交中为 grade:write，默认教师权限包含它。
- 关闭 PROJECTX_AUTH_ENFORCE 时，答题卡路由不要求认证，但仓库服务默认绑定 127.0.0.1，也没有部署清单证明外部入口存在。
- 错误识别需要实体或缓存纵向答题卡仍被保留，而识别随后重建横向布局；没有端到端证明这种下游不匹配。
- HTTP 验证使用临时 expr-eval 加载桩，该桩与答题卡持久化、布局、PDF 或识别代码路径无关。

原文另列前提：

- 能通过设计器或 PUT /api/cards/:cardId 编辑并保存答题卡定义。
- 选择或提交 optionLayout=vertical。
- 后续重新加载、PDF 请求、布局重建或识别操作，通过 CardRepository.findById() 读取答题卡。
- 若要造成判分损害，需要在持久化答题卡已恢复横向后，继续使用实体或过时的纵向表示。

## 控制措施

- optionalAuth 为所有 /api 路由解析 Bearer 或 Cookie 身份。
- 启用 PROJECTX_AUTH_ENFORCE 时，/api/cards 入口向未认证调用方返回 401，缺少所需权限时返回 403。
- 默认学生权限不包含答题卡或成绩写入权限。
- HTTP 监听器默认绑定 127.0.0.1:5174。
- safeId 在仓储和文件系统使用前规范化答题卡标识符。
- PDF 响应禁用缓存，不过这不能修复持久化语义问题。
- 正常 PDF 和识别流程通过 CardRepository 重新加载，因而通常生成一致的横向产物，而不是保留不受支持的临时纵向状态。

## 盲点

- 没有已提交的入口、反向代理或负载均衡文件，能够确定某个具体部署是否将 5174 端口暴露给远程访问。
- PROJECTX_AUTH_ENFORCE 由部署控制，不能仅凭工作区确定实际认证边界。
- 没有针对实体纵向答题卡执行原生 OCR。
- 没有通过可视化解析 PDF 字节来确认每个渲染坐标。
- 验证服务器需要临时 expr-eval 模块加载桩，不过该依赖不在被执行的答题卡布局路径内。
- 仓库证据没有演示浏览器将临时纵向预览打印或导出为实体答题卡来源的过程。

export function normalizeObjectiveQuestions(block: ObjectiveBlock): ObjectiveQuestionConfig[] {
  const answerKey = normalizeObjectiveAnswerKey(block);
  return objectiveQuestionDefinitions(block).map((question) => {
    const options = normalizeOptions(answerKey[question.questionNumber], question.optionCount);
    return {
      questionNumber: question.questionNumber,
      mode: question.mode,
      optionCount: question.optionCount,
      score: question.score,
      answerKey: question.mode === "single" && options.length > 1 ? [options[0]] : options,
      scoringRule: question.scoringRule
    };

function objectiveArrangementMode(questions: ObjectiveQuestionDefinition[]): ObjectiveArrangementMode {
  if (questions.some(isVerticalQuestion)) {
    return "vertical-grid";
  }
  return questions.length >= 15 ? "grid" : "rows";
}

function isWideObjectiveQuestion(question: ObjectiveQuestionDefinition): boolean {
  return question.optionCount > OBJECTIVE_WIDE_OPTION_THRESHOLD;
}

function isVerticalQuestion(question: ObjectiveQuestionDefinition): boolean {
  return question.optionLayout === "vertical";
}

function isSoloRowQuestion(question: ObjectiveQuestionDefinition): boolean {
  return isWideObjectiveQuestion(question);
}

function objectiveGridCellQuestions(mode: ObjectiveArrangementMode): number {
  return mode === "vertical-grid" ? OBJECTIVE_VERTICAL_GROUP_QUESTIONS : OBJECTIVE_GRID_CELL_QUESTIONS;
