# 47 答题卡持久化时丢失纵向选项布局

- 原标题：Vertical option layout is discarded when cards are persisted
- 云端级别：Informational
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/b9b5623efbfc8191b92d847962604789?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=&page=3)
- 关联提交：[c3d9434](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/c3d94344dd22c0125d49053e16ec70cf7790dd2d)

## 概要

提交在题块和题目新增 optionLayout 并用于 vertical-grid，却未贯通归一化和数据库。CardRepository 不写入或重建该字段，objective_blocks / objective_questions 没有对应列；normalizeObjectiveQuestions() 更早丢弃题级 optionLayout。

选择纵向后 PUT 可成功返回纵向布局，下一次 GET 却丢失设置并默认 horizontal。PDF、布局重建和识别经 findById() 读卡，也回到横向。应添加迁移与仓储读写，保留归一化字段，并覆盖保存—重载—PDF 往返验证。

## 验证与路径

生产 HTTP 验证接受块级 vertical，重载丢失字段；确认两表缺列，题级设置在归一化中丢失，生产布局坐标由纵向网格变横向。未解析实际 PDF 所有坐标，也未用物理纵向卡执行原生识别。

设计者选择纵向 → 整卡 PUT → 归一化/仓储遗漏字段 → GET 默认横向 → PDF与识别使用横向坐标。

## 等级判断

已证明的是低影响的一致性和可靠性故障。实际判分损害还需旧纵向预览、缓存或外部制作的物理卡继续使用；正常服务端 PDF 会重载，通常稳定输出横向卡。受保护的编辑者原本可改整张卡和答案，没有新增跨边界能力，最终按策略排除为信息提示。

认证默认关闭的兼容模式也不产生此缺陷独有的攻击能力：可任意 PUT 整卡的人本就可直接破坏卡，服务默认只监听本机。

## 前提、防护与盲点

分析固定于 c3d94344dd22c0125d49053e16ec70cf7790dd2d。认证开启时写卡需 grade:write，学生无该权限；optionalAuth 解析身份，无身份/权限分别返回 401/403；safeId 归一化 ID，PDF 禁缓存。实际入口与认证开关未知。

测试使用与卡布局无关的 expr-eval 临时加载桩。未证明浏览器把瞬时纵向预览作为物理打印源，未执行原生 OCR，也未视觉解析 PDF；条件性识别后果不应当作已复现。
