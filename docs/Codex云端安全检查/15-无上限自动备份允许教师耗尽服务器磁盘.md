## 概要

本提交新增 autoBackupOnExamClose() 并在每次判分持久化后无条件调用，引入漏洞。另一修改文件为考试组创建增加 Zod 验证，没有同类问题。

每次 persistGradingResults() 完成，新函数在 data/answer-card/backups 写唯一命名的完整数据库副本。持久化只查考试存在，不要求从开放到关闭的状态转换、不验证保存过学生分数，也不防反复处理已关闭考试。备份不在既有清理范围，无数量、年龄、大小或剩余空间限制。强制认证部署中，默认教师具有路由所需 grade:write。教师可以用可访问卡、现有 examId 和一个很小或畸形文件反复 POST 判分。识别错误被转为失败行而非中止，持久化仍创建批次、关闭考试并启动数据库复制。请求间隔至少一毫秒就有不同备份名。因此可按整个数据库大小放大持续磁盘占用和并发复制 I/O，最终阻止写库、干扰扫描判分。备份应只在原子首次关闭转换执行，使用 SQLite 在线备份/VACUUM，设置保留/存储限制，并限流或移到管理员控制后台任务。

## 验证

1. 默认教师/grade:write 可达生产判分 HTTP，接受自选 examId 与最小上传。
2. 失败/畸形识别仍对既有考试持久化，不需首次关闭转换或已保存成绩。
3. 每次重复持久化在永久目录安排一个不同完整 SQLite 主库文件副本。
4. 没有保留、配额、去重、清理或剩余空间控制，复制量随数据库增大。
5. 现实专项执行显示三次重复请求在零学生分数下累积三份同大小备份。

## 攻击路径分析

不适用强制排除：共享影响而非本人；低权限教师而非管理员、操作者、开发者或本地主机用户；正常认证 HTTP 已执行前提。文档支持 Cloudflare 远程，PoC 确认可重复整库存储增长。最终磁盘耗尽可停止写库/判分，影响高；默认教师权限且无限流/保留，可能性高。矩阵仅在额外严重条件满足时升严重；这里只影响单学校服务可用性，无 RCE、管理员接管、整库外泄或广泛隐蔽改分，故可报告高危。

### 路径

远程认证教师 → Cloudflare/代理到回环 5174 → Express → 仅 grade:write 保护的判分 POST → 处理可控 multipart → 识别结果或捕获失败 → 失败成行、不阻止持久化 → 无条件重置状态和建批次 → 不论成绩保存数都关闭考试并安排备份 → 时间戳 copyFile data/projectx.db → 每独立时间戳一份整库，无清理 → 无界累积与共享服务中断。

普通教师用正常判分 API 可让服务器反复复制完整 SQLite。默认教师满足写权。函数接收 examId/文件，捕获识别异常为失败行，发成功响应，之后只要有 examId 就持久化。仅查考试存在，不要求首次转换或成功分数，因此全部行没学生 ID 也建批次、关闭、备份。毫秒时间戳与 copyFile 无保留/容量控制。可执行验证真实教师三次普通 HTTP，均识别失败、零保存，却产生三份各 4,677,632 字节、与源库等大的文件。最强反向证据为回环，但部署文档/start-server.sh 明确 Cloudflare 公开。MariaDB 或自定义库路径可能使硬编码 SQLite 来源找不到，因此确认范围限默认 SQLite，不是否定。认证、20 MiB 文件上限、卡存在、同毫秒文件名碰撞也不能防：教师有权，小文件足够，可用自己的卡/考试，稍作间隔就唯一。验证缺原生识别器不是利用必需，因为源码成功识别或任意捕获错误之后都持久化。无仓库清理、配额、剩余空间、去重或通用限流覆盖备份。文件仍在服务器，证明可用性而非未授权备份披露。

## 发生可能性

**高。** 文档远程产品部署，默认教师可达。普通前提，可创建/使用自己的卡与考试，无每考试首次关闭检查/限流；三次顺序请求、零成绩生成三份整库。SQLite 是文档默认模式。只在 MariaDB、自定义路径、教师权限或外部未记录配额/限流时降低。**攻击向量：远程网络。**

## 影响程度

**高。** 每次占用完整 SQLite 大小，可与后续请求复制 I/O 重叠。持久累积不清理，耗尽共享文件系统阻断写库、扫描、判分及其他用户。验证直接证明线性整文件累积，刻意未填满磁盘。未证明外泄或代码执行。

## 假设条件

- 默认 SQLite，活动库 data/projectx.db。
- 生产认证开启，攻击教师保留默认 grade:write。
- 能访问文档公网 Cloudflare 或其他配置代理。
- 无仓库外配额、代理限流、备份保留任务阻止累积。

原文另列前提：

- 有 grade:write 的账号，普通教师默认有。
- 已有卡与考试；默认 card:write / exam:write 可自行创建前提。
- 至少一个 multipart 文件和既有 examId。
- 默认 data/projectx.db 的 SQLite 本地模式。
- 不同毫秒时间戳的重复请求，以及足够时间消耗存储。

## 控制措施

- 认证开启时 cardGate 拒匿名、POST 需 grade:write。
- 默认教师仍有它，无法区分判分与备份/主机存储权限。
- 需既有卡、非空上传及既有考试。
- 单识别文件 20 MiB，但小文件即可，增长依据数据库大小而非上传大小。
- 回环监听，仓库部署公开 Cloudflare。
- 每 24 小时清理扫描/识别产物，不含数据库备份。
- 硬编码来源将确认累积限于默认 SQLite，MariaDB 通常没有对应活动 SQLite 来源。

## 盲点

- 实际数据库模式、PROJECTX_DB_PATH、ANSWER_CARD_DATA_DIR、角色定制、容量、配额、代理限流不能静态确定。
- 有界验证只证明三份同大小备份，未把宿主推到 ENOSPC；最终停机/并发 I/O 降级由线性累积推断。
- 验证缺原生识别器，源码显示成功与捕获错误均进入持久化。
- 未找到攻击者下载生成备份的仓库路径，不声称机密性影响。
- 外部自定义清理/监控可缩短残留或发现时间。
