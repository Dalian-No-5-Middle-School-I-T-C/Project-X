# 15 无上限自动备份允许教师耗尽服务器磁盘

- 原标题：Unbounded auto-backups let teachers exhaust server disk
- 云端级别：High
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/a0ec603e3cd481919a9c0821e4bae28a?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=)
- 关联提交：[9c510aa](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/9c510aa23eea009651a5f095628972298e72e91a)

## 概要

本提交新增 autoBackupOnExamClose，并在每次 persistGradingResults 后无条件调用。另一改动为考试组 Zod 验证，没有同等问题。备份使用毫秒时间戳，把完整 data/projectx.db 复制到 data/answer-card/backups。只检查考试存在，不要求首次从开放变为关闭，不要求真正保存学生分数，也不阻止已关闭考试重处理。没有数量、时间、字节、剩余空间或清理限制。

默认 grade:write 教师可对现有考试反复上传小型或畸形文件；识别异常被转为失败行，仍创建批次、关闭考试并触发整库拷贝。间隔至少一毫秒通常得到不同文件名。原报告建议仅在原子首次关闭时备份，用 SQLite online backup／VACUUM，增加保留及存储限制、限流或管理员后台任务。

## 验证及证据

真实登录普通教师和三次正常 HTTP 请求，全部识别失败、零学生分数，仍生成三个各 4677632 字节备份，均等于源库大小。证据包括只检查考试存在、无条件关闭和触发备份、异常识别仍持久化、角色级阅卷权限及唯一时间戳 copyFile。未实际填满磁盘。

## 攻击路径与分级

教师上传＋任意现有 examId → 识别成功或捕获错误 → 无首次关闭限制的持久化／批次 → 关闭考试 → 完整 SQLite 主文件复制 → 永久累计和并发拷贝 I/O。

发生可能性高：默认权限，可用自己创建的卡片与考试，小文件即可，无需识别器成功或竞态。影响程度高：每次消耗整个库大小，可能阻止 SQLite 写入和其他用户扫描／阅卷。不是教师应有的主机存储管理权。限单校服务可用性，无 RCE、接管、备份下载或隐蔽改分，因此高危。

## 假设及已有控制

明确适用于默认 SQLite 模式且活跃库位于 data/projectx.db；MariaDB 或自定义路径可能找不到硬编码源文件。生产认证开启、教师保留 grade:write、现有卡片及考试、至少一份文件、请求时间戳不同；无外部配额、限流或备份保留任务。Cloudflare／反代提供可达入口。

cardGate 拒匿名，检查卡片、非空上传和考试存在，Multer 单份 20 MiB；但备份大小取决于数据库而非上传。回环监听可经文档隧道公开。每 24 小时清理任务只处理扫描和识别文件，不覆盖备份。毫秒撞名只是有限限制，稍分隔请求即可避免。

## 盲点

生产数据库模式、PROJECTX_DB_PATH、ANSWER_CARD_DATA_DIR、角色、磁盘和外部策略未知。只证明三个文件线性增长，ENOSPC 和并发 I/O 停机为据此推断。测试缺原生识别器，但源码表明成功或捕获失败都会进入同一持久化。未找到攻击者下载这些备份的路径，不主张保密性影响；外部清理监控可缩短持续或发现时间。
