## 概要

本次提交新增付费 AI 分析端点和提供商调用循环，却没有任何滥用控制。已有的通用分析权限检查不能缓解重复或并行请求，Node 代理和 Python 辅助服务也都没有相应限制机制。

POST /api/analysis/exams/:examId/ai-analysis 接受调用方选择的已配置模型，并立即转发给 Python。生产中的唯一授权是默认每名教师都拥有的 grade:read，没有逐用户限流、全局并发上限、去重、队列、冷却或用量预算。每个请求可保持上游连接 120 秒。辅助服务同步执行付费循环，最多八轮，每轮 4096 token、较高推理强度，模型目录还有可选 pro 模型。失陷或恶意教师能够并行消耗资金和额度，耗尽辅助服务线程或连接，使合法教师无法使用 AI。如果兼容配置 PROJECTX_AUTH_ENFORCE 关闭，匿名用户也可访问，利用更容易。应加入用户和实例限流、小型全局并发队列、费用和 token 预算、取消及审计；AI 应要求专用权限，而不只是通用成绩读取。

## 验证

1. 强制认证时，匿名用户被拒绝，默认具有 grade:read 的教师可调用；源码确认关闭认证会绕过该检查。
2. 45 个并行教师请求全部被接受，并携带自选模型转发，没有应用限流、AI 并发限制、去重、冷却或预算。
3. 使用模拟 SDK 执行生产循环，产生八次 gpt-5.5-pro 调用，每次 max_tokens=4096、reasoning_effort=high。
4. 现实 HTTP 请求达到观察到的 FastAPI／AnyIO 40 个工作线程容量，额外请求排队，证明调用方可以使其饱和。
5. 确定有效考试及已配置密钥的前提；可用性耗尽经过动态演示，实际费用具有条件性，验证有意没有产生费用。

## 攻击路径分析

最终不予排除：影响不限于本人，路径可达，也不是仅操作者、开发者、物理访问者或管理员能够利用，不依赖受保护写入。普通教师是范围内低权限主体，新增安全能力在于没有专用授权或滥用控制地消耗共享付费资源及可用性敏感资源。线程饱和直接得到证明，最多八次的生产循环支持费用放大，因此影响高。正常网络端点对默认教师开放，低复杂度并行请求即可触达，验证也确认了重叠，因此发生可能性高。矩阵结果为高危而非严重，因为影响限于单实例 AI／提供商资源，金钱损失具有条件性，没有更广泛接管、改分或敏感数据失陷。

### 路径

恶意或失陷的默认教师 → 并行 POST，使用有效 examId 和自选模型 → AI 路由 → grade:read 授权，或关闭认证时绕过 → 每个请求转发并等待最多 120 秒 → FastAPI /analysis/run → 对配置模型同步调用 provider create → 最多八轮工具循环 → 占用共享线程，消耗提供商资源 → 饱和、排队、额度或费用耗尽。

服务链包括 5174 端口的 Express、8766 回环端口的 FastAPI，以及外部模型。生产教师流程唯一要求的能力是 grade:read。检查考试存在和 classId 格式后，就携带自选模型转发。辅助服务检查目录模型、密钥及数据库是否存在，再同步执行最多八次、每次 4096 token 的高推理调用。可执行验证使用真实 Express 认证、权限检查、代理及 FastAPI，只将付费操作替换为桩：匿名请求被拒绝；45 个默认教师并行请求均携带 gpt-5.5-pro 被接受并转发，40 个同时运行，其余排队。另一项循环验证复现八次调用参数。最强反向证据是两端绑定回环地址、认证拒绝匿名请求、可选内部 Bearer、120 秒取消及隐含 40 线程上限。但生产模型允许公开 Express，教师能通过权限检查，Node 合法使用内部密钥；超时不限制接收或资源消费，运行时上限仍允许全部请求排队并占满容量。金钱损失需要有资金的提供商账号及被接受的模型，验证未连接真实提供商，因此账单规模具有条件性；线程饱和及排队则直接得到证明。

## 发生可能性

高。在 AI 部署中，只需普通教师、有效考试及重复 HTTP 请求；教师明确包含在威胁模型内，接口也供其日常使用。没有竞争、解析器漏洞、管理员行动或直接秘密访问要求。45 个重叠请求全部到达辅助服务。回环绑定及没有仓库入口配置降低对具体部署的确信，但模型明确认为代理或隧道现实存在。兼容模式默认关闭认证会进一步增加可能性，不过评级不依赖这一弱配置。攻击向量为远程网络。

## 影响程度

高。影响是实例级，而非仅本人：教师可以占满共享同步工作容量，延迟合法分析，每个被接受请求最多进行八次昂贵操作。HTTP 验证证明 45 个请求全部进入，40 个使线程饱和，其余排队。额度及费用影响有生产循环支持，但取决于有资金的密钥、提供商接受、实际输出和计费。威胁模型明确将已认证低权限用户造成的 AI 费用或持续可用性耗尽视为高影响。

## 假设条件

- 使用文档中的 AI 流程，Python 运行，且至少一个提供商密钥对应有资金账号。
- 存在有效考试，这是转发前的必需条件。
- 保守按生产认证开启、攻击者控制普通教师评估；关闭认证时无需账号。
- 所提供威胁模型适用，运维代理或 Cloudflare 可以公开回环 Express。
- 金钱损失需要模型被接受并计费；线程饱和不要求证明实际账单。

## 控制措施

- PROJECTX_AUTH_ENFORCE 可以要求认证，返回 401／403。
- 生产式验证确认，开启时匿名请求被拒绝。
- 默认教师仍满足通用 grade:read。
- 辅助服务可以要求内部密钥保护直接请求。
- 两端默认绑定回环地址。
- 辅助服务拒绝未知模型、没有配置密钥的模型及缺少数据库的情况。
- Express 在 120 秒后中止 fetch。
- 观察到 AnyIO 隐含 40 个同步线程，但超额请求排队而不被拒绝。
- 文档中的 AI 报告使用成绩汇总，不有意发送学生姓名。
- 未发现逐用户限流、有界队列、预算、冷却、去重或 AI 专用权限。

## 盲点

- 没有仓库管理的代理、隧道、负载均衡或防火墙清单，远程访问依据威胁模型和运维配置。
- 付费操作使用同步桩，没有测量实际账单、模型 ID 接受、提供商额度、限流或时延。
- 40 线程容量可能随 AnyIO、FastAPI、Python 和部署变化。
- 120 秒 Express 中止本身不能证明底层 SDK 取消，取消行为尚未确定。
- 八次调用需要模型反复调用工具，普通分析可能更早结束。
- 仓库不披露账号预算、信用限额或具体实例的财务规模。

    try {
      const examId = Number(req.params.examId);
      if (!Number.isFinite(examId) || examId <= 0) {
        res.status(400).json({ message: "Invalid exam id" });
        return;
      }

      const analysisRepo = new AnalysisRepository();
      const exam = analysisRepo.getExam(examId);
      if (!exam) {
        res.status(404).json({ message: "Exam not found" });
        return;
      }

      const classIdValue = req.body?.classId;
      const classId = classIdValue === undefined || classIdValue === null || classIdValue === ""
        ? undefined
        : Number(classIdValue);
      if (classId !== undefined && !Number.isFinite(classId)) {
        res.status(400).json({ message: "Invalid class id" });
        return;
      }

      const response = await fetchLlmClient("/analysis/run", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({
          examId,
          classId,
          model: typeof req.body?.model === "string" ? req.body.model : undefined,
          locale: "zh-CN"
        })
      }, 120_000);
