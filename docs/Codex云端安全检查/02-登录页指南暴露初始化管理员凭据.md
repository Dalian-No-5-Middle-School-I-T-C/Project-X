## 概要

**由本次变更引入。** 本变更在未认证的 LoginPage 添加使用指南入口，并将包含实际初始化管理员凭据的指南打包进客户端。指南不应在认证前暴露凭据；初始化应使用每个安装实例独有的随机一次性秘密，或本地激活机制，而非固定密码。

没有用户登录时，App 渲染 LoginPage。本提交新增登录页按钮，可在没有认证的情况下打开 UserGuideModal。UserGuidePage 将完整 Markdown 指南静态导入客户端包并渲染，而指南明确写出初始化管理员用户名 admin 和密码 admin123。后端会创建完全相同的活动管理员账号，登录成功后产生管理员会话；管理员角色具有通配权限。因此，未认证的网络攻击者可以访问对外暴露的实例，直接从登录页阅读凭据，并在合法操作者改密前登录。任何强制改密流程都无法防止这场竞争，因为攻击者可以先完成它。攻击者由此可以访问学生记录、试卷、备份、凭据及成绩管理操作。已经修改初始化密码的既有部署不受影响。固定初始化凭据虽然早于这一变更就已存在，但通过已部署的认证前界面发布凭据，是本提交新引入的行为。

## 验证

1. 确认未认证的生产界面暴露新打包的指南及其中的字面凭据 admin/admin123：已通过源码、提交差异、成功的 Vite 构建，以及未认证 HTTP 获取的客户端包验证。
2. 确认全新受支持数据库会创建实际密码为 admin123 的活动管理员，且无需先激活：已通过新数据库和成功登录验证。
3. 执行真实登录接口，证明泄露的凭据产生已认证管理员会话：生产 /api/auth/login 返回 HTTP 200、令牌、管理员身份和通配权限。
4. 确认管理员授权并评估改密控制：该令牌可以访问受保护的 /api/users；攻击者修改密码后，可使用新密码再次登录。
5. 确定前提及引入情况：提交差异证明认证前 UI 暴露为新增行为；证据同时指出需要全新/恢复后且密码未改的账号，以及取决于部署方式的网络可达性。

## 攻击路径分析

在确认攻击路径事实之后进行了策略调整。影响为高，因为该路径从未认证访问跨越到具有通配权限的管理员身份，而且已演示受保护路由访问及改密能力。对于受影响状态，可能性为高：凭据通过正常的认证前产品界面提供，登录路由公开，文档中的生产架构支持 Nginx 远程访问，可执行 PoC 无需推测性的后续跳转即可完成接管。全新/恢复和密码未改这些要求缩小了受影响群体，但它们是现实部署前提，并非高权限、仅操作者、物理访问或无法达成的要求。影响不限于本人，也没有适用的强制排除条件。按要求的矩阵，高影响加高可能性仍为严重，因为直接的未认证管理员接管符合所述严重标准。

### 路径

未认证远程攻击者 → 未登录访问对外暴露的实例 → 公开 LoginPage 和使用指南弹窗 → 打开指南或直接下载公开 JavaScript 资源 → 客户端构建资源包含初始化凭据说明 → 获取并提交公开固定凭据 → POST /api/auth/login → 密码验证成功并返回会话令牌 → 获得具有通配权限的活动初始化管理员身份 → 通配权限满足受保护路由授权 → 执行管理及教育数据操作。

攻击过程：未认证网络用户在操作者修改初始化管理员密码之前，访问新部署或恢复后的 Project-X 实例。App 渲染 LoginPage，而该页面现在会在认证前提供指南弹窗。UserGuidePage 将完整指南导入公开客户端包，指南指出了实际固定初始化管理员凭据。服务端独立创建使用相同凭据的活动管理员。将凭据提交到普通登录路由会产生令牌，其角色具有通配权限。可执行验证确认：未认证可获取的构建资源包含凭据说明；登录成功；管理员保护端点可以访问；攻击者能够修改管理员密码并用新密码再次认证。最有力的反向证据是 startServer 绑定 127.0.0.1、利用仅在默认密码修改前有效，以及这一凭据在本提交之前已出现在仓库文档中。这些因素缩小了暴露面和受影响时间窗口，但并不能否定漏洞：deploy-guide.md 明确推荐向回环端口转发的公开 HTTPS Nginx 代理；新安装初始化自动创建活动凭据；没有强制激活状态阻止高权限操作；本提交首次通过已部署的认证前产品 UI 直接提供该凭据。已经改密的既有实例不受这条路径影响。

## 发生可能性

**高。** 对可达的全新或恢复实例，利用结果确定，不需要已有账号或用户交互，使用正常客户端及登录 API 即可。仓库记录了公开 HTTPS 反向代理部署，可执行验证确认了公开包泄露、成功登录、通配权限、受保护端点访问及密码替换的完整路径。风险限于操作者改密前的窗口，已轮换密码的既有实例不受影响；但这一部署竞争具有现实性，也被项目威胁模型直接指出。**攻击向量：远程网络。**

## 影响程度

**高。** 利用成功可取得具有通配权限的实例管理员身份。可执行验证证明了访问受保护管理员端点及替换管理员密码的能力。在仓库威胁模型中，管理员失陷允许对学生记录、账号、考试、成绩、备份及系统配置造成广泛的机密性和完整性影响，并可能通过破坏操作影响可用性。

## 假设条件

- 已部署客户端与 API 对应受影响提交。
- 实例为新安装或恢复后，初始化管理员密码尚未修改。
- 服务通过仓库记载的 HTTPS 反向代理或等效受支持入口可达。

原文另列的利用前提：

- 全新或恢复数据库中的固定初始化管理员凭据仍然有效。
- 网络可访问 Web 客户端及登录 API。
- 攻击者在合法操作者修改初始化密码之前完成认证。

## 控制措施

- Node 服务默认监听 127.0.0.1，远程可达需要本地客户端或配置反向代理。
- 登录服务使用 bcrypt 验证密码，并返回通用认证失败信息。
- 受保护路由使用认证中间件与角色/权限检查；匿名访问用户管理路由会被拒绝。
- 会话使用随机不透明令牌，浏览器 Cookie 带 HttpOnly 和 SameSite=Lax。
- 修改密码会撤销用户现有会话。
- 指南要求操作者立即修改默认密码。
- 这些控制不能防御持有当前有效初始化凭据的攻击者；没有认证前激活或强制改密状态阻止第一次高权限会话。

## 盲点

- 检出的代码无法证明某个真实部署当前是否通过代理或隧道公开端口 5174；公开暴露是有文档支持的方式，而非每个实例都已证实的事实。
- 验证时因 node_modules 缺少一个已声明依赖，无法启动完整 createApp 进程；可执行测试框架改用仓库生产初始化器、认证服务、中间件、路由、客户端构建及回环 HTTP 服务。
- 验证证明了受保护的用户管理操作和密码替换，但没有执行全部判分、备份、删除或配置操作。
- 固定初始化凭据早于本提交，并已在仓库文档中出现；本提交特有的回归是将其放入未认证客户端 UI 和公开包。
- 管理员密码修改后即无法通过此路径利用，仓库证据不能确定各操作者完成该步骤的速度。

  async login(identifier: string, password: string, isPersistent = false): Promise<LoginResult> {
    // 查找用户（支持 username 或 student_number 或 email）
    let user = this.userRepo.findByUsername(identifier);

    if (!user && /^\d+$/.test(identifier)) {
      // 纯数字，尝试学号
      user = this.userRepo.findByStudentNumber(identifier);
    }

    if (!user) {
      return { success: false, message: "用户名或密码错误" };
    }

    // 验证密码。兼容旧流程留下的学生空密码哈希：首次用学号登录时自动补齐为学号密码。
    let valid = false;
    if (!user.password_hash && user.role_name === "student" && user.student_number && password === user.student_number) {
      const newHash = await hashPassword(user.student_number);
      const db = getDatabase();
      db.prepare("UPDATE users SET password_hash = ?, updated_at = CURRENT_TIMESTAMP WHERE id = ?").run(newHash, user.id);
      user.password_hash = newHash;
      valid = true;
    } else {
      valid = await verifyPassword(password, user.password_hash);
    }
    if (!valid) {
      return { success: false, message: "用户名或密码错误" };
    }

    // 更新最后登录时间
    this.userRepo.updateLastLogin(user.id);

    // 生成 token
    const token = randomBytes(32).toString("hex");
    const expiresAt = Date.now() + (isPersistent ? PERSISTENT_TOKEN_EXPIRE_MS : TOKEN_EXPIRE_MS);
    this.tokenStore.set(token, { userId: user.id, expiresAt });
    this.scheduleSave();

    // 清除敏感信息
    const { password_hash, ...safeUser } = user;

    return {
      success: true,
      user: safeUser,
      token,
      permissions: permissionsForRole(user.role_id),
      message: "登录成功"
    };
