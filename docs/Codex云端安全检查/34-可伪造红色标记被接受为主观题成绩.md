# 34 可伪造红色标记被接受为主观题成绩

- 关联提交：[2b1a383](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/2b1a38303fbf98ad6c0f9f48da6d4c32251a3612)

## 概要

本提交自动识别并汇总主观题分值格红色标记，只验证视觉形状不验证评分者来源。学生在交卷前控制答题卡，可在最高分格画干净红线；识别器根据 HSV 红色、覆盖、连通分量、跨度和直线度判定，合法形状由 build_subjective_questions 输出 status=ok，TypeScript 随即 needsReview=false，计入主观总分和最终总分，并显示／导出 CSV。

没有必须教师确认或可信评分来源。建议 OCR 主观分保持待审核，除非来自受控阅卷后流程，或通过学生无法预填的教师认证渠道采集。

## 验证及证据

确认卡片分值格含最高值、视觉阈值可由普通红线满足、ok 分支无来源证据。真实 HTTP、布局、进程适配与 TypeScript 汇总测试只模拟不可运行的 Windows/OpenCV 输出，得到 15/15、needsReviewCount=0、issueCount=0。原生图像接受依据源码阈值与成功分支，未对真实伪造图动态执行。

## 攻击路径与分级

学生在自己交卷上标高分 → 员工正常扫描／导入 → /api/cards/:cardId/grading → 红色／线形检测 → ok → 无复核计入总分 → UI/CSV 被业务采用。

影响程度高：可把受影响学生主观分替换到满分，影响学校记录和比较结果，不只是自我影响；普通学生保管自己的卷不是特权物理访问。发生可能性中：需 manual_score_grid、清晰标记、正常员工处理、未人工发现，且缺原生实测。限通常自己的交卷，未证明自动写中心库，最终中危。

## 假设、控制与盲点

启用人工分值格，学生可事先写或操纵后来导入的图，员工依赖 ok 无警告结果，未假设仓库外红笔管理或强制对照。

控制为红色覆盖至少 1.2%、恰一个显著分量、足够跨度、平均／最大直线误差阈值、多选／畸形标 invalid、超过配置满分拒绝、缺失／无效给 0 并需复核、回环监听、每文件 20 MiB／最多 200 文件、识别 30 秒超时。这些校验形状，不证明谁画，也不要求批准成功结果。

没有真实 Windows/OpenCV 伪造图接受测试；外部人工核对、红笔控制、模式使用频率未知。该组件只证明显示及导出，中心库持久化或 CSV 实际采用是运行条件，不是已证代码效果。网络公开并非物理交卷链必要条件。
