## 概要

本次提交新增主观题评分格自动识别及汇总，验证红色标记的视觉形状，却不验证来源，将视觉上有效的标记当作已确认分数，而不是不可信建议。

学生在判卷之前控制纸质答题卡，扫描或上传图片也不可信。新识别器仅按 HSV 红色阈值、覆盖比例、连通组件数量、跨度和直线性识别选择，这些都无法证明标记出自授权阅卷人，而非学生或图片编辑者。学生可以在交卷前于最高分值格中画一条直红线；干净的伪造线会被 build_subjective_questions 标为 ok。TypeScript 只因状态为 ok 就设置 needsReview=false，将数值计入主观题分数及总分，再经端点显示和 CSV 导出。在没有强制阅卷确认或来源控制时直接采用为成绩，跨越了学生输入到阅卷完整性的边界，可能静默抬高一个或多个学生的分数。主观题 OCR 应保持待复核，除非输入来自受控的阅卷后流程；也可以通过学生无法预填的、经阅卷人认证的渠道采集分数。

## 验证

1. 可控纸质或扫描答题卡展示可选择的评分格，其中包括最高分。
2. 最近的识别控制只检查可复制的视觉特征，没有阅卷来源机制。
3. 确认满足阈值的干净单条红线，在原生输出中对应 ok 分数。
4. 真实判分接口确认，ok 分数计入总分，且无需复核。
5. 确认该值可被显示及导出，没有下游强制确认。

## 攻击路径分析

策略不予排除。伪造分数会改变机构记录，影响教育者及比较结果，不是只影响本人。普通学生持有自己的答题卡属于正常流程，不需要受保护系统的物理特权、运维权限或写入路径；工作人员只执行预期扫描。服务虽位于本机，攻击无需网络，因为恶意文档经日常操作进入系统，前提现实。受影响学生的主观题及总分完整性影响高；需要启用评分格、工作人员交互，存在目视发现机会，又缺少原生端到端验证，因此发生可能性为中。高影响与中等可能性得到中危。

### 路径

学生控制待提交答题卡 → 在目标评分格伪造红线 → 印刷评分格展示可选分值 → 工作人员正常扫描或导入 → 判分 POST → 图片及布局交给原生程序 → C++ 执行 HSV 和线形检测 → 有效数值标记 status=ok → TypeScript 汇总 → 无需复核即加入主观题分数及总分 → 显示及 CSV 导出。

学生在提交前于高分格画一条干净红线，即可利用正常流程。答题卡展示全部可选值，包括满分。原生检测检查宽泛 HSV、最小覆盖、单连通组件、线跨度及拟合误差，却没有授权标记者来源信号；通过后即标为 ok。TypeScript 复制分数、取消复核要求、汇总并交给界面和 CSV。最强反向证据是默认回环监听、评分格预期供人工阅卷使用、错误标记会被拒绝，以及认真阅卷人可能发现预先标记。这些降低概率和范围，但不能否定问题：输入来自日常扫描，而不是直接网络；规则验证形状而非来源；对干净标记，仓库没有强制确认。可执行验证确认 15/15、needsReviewCount=0、issueCount=0，但模拟了不可用原生程序；原生接受行为由明确阈值及成功分支静态确认。

## 发生可能性

中。标记简单，分值印在答题卡上，学生通常持有卡片，不需要账号或受保护访问。确定性的视觉质量检查不验证来源。利用需要 manual_score_grid、工作人员扫描、足够干净的标记，以及阅卷人没有发现或独立核对，因此降低为中。Linux 环境没有动态执行原生检测。

## 影响程度

高。攻击者可用自选分数直至满分替代学生主观题结果，并无警告地加入显示和导出总分，可能影响正式决策及比较，不只是影响本人。没有展示自动写入中央数据库，单个学生通常也只能控制自己的提交，这些限制范围，不达到严重级别。

## 假设条件

- 普通持卡书写不等于对受保护系统拥有物理特权。
- 至少一道题使用 manual_score_grid。
- 工作人员正常扫描，并可能信任 ok／无需复核状态。
- 不假设存在代码未强制要求的外部目视比对或红笔管控。
- 验证执行真实 HTTP、布局、进程适配及 TypeScript 汇总，只模拟不可用 Windows／OpenCV 边界。

原文另列前提：

- 存在包含评分格的纸质答题卡，或经过数字修改的图片。
- 学生在扫描前持有答题卡，或控制后续导入图片。
- 红线满足覆盖、组件、跨度和直线阈值。
- 工作人员执行正常扫描或导入。
- 没有独立来源检查，就依赖自动结果。

## 控制措施

- 要求至少 1.2% 红色覆盖。
- 要求恰好一个显著红色组件。
- 要求跨越足够格范围，并满足平均及最大直线误差阈值。
- 多选或畸形标记被标为 invalid。
- 超过配置满分的数值被拒绝。
- 缺失或无效标记给零分，并设置 needsReview=true。
- Express 默认绑定回环地址，Electron 使用临时端口。
- 单文件限制为 20 MiB，最多 200 个文件。
- 原生程序超时为 30 秒。
- 这些措施均不验证有效标记者身份，也不要求对成功识别进行审批。

## 盲点

- 没有 Windows 二进制或 OpenCV 构建环境，未使用伪造图片执行检测。
- 只依据符合阈值的指标模拟原生输出，确认下游接口和汇总，没有证明图像级接受。
- 不知道外部人工审核、红笔控制或防伪程序的情况。
- 没有入口或负载均衡清单，实际部署可能有不同暴露。
- 组件显示和导出结果，没有显示中央数据库持久化；CSV 使用属于操作层面，不由代码强制。
- 学校启用评分格的频率未知。
