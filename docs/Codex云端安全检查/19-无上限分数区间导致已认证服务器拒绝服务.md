# 19 无上限分数区间导致已认证服务器拒绝服务

- 原标题：Unbounded score ranges enable authenticated server DoS
- 云端级别：High
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/4159f92ce0648191b69ccc95b5fb24f4?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=)
- 关联提交：[7606e64](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/7606e6463cf73218339e7d45b03fc352ded01b33)

## 概要

本提交把总览固定五个分数区间／五次计数查询改为 generateDistributionRanges(fullScore)，从 0 每 10 分分配一个对象，再每区间执行单独 SQL COUNT。fullScore 来自 SUM(question_scores.max_score)，没有有限值或上限检查。卡片更新接受巨大题分，判分或答案重算把它存入 max_score。

普通教师可把题分设为 1000000000，通过重算持久化，再请求 /api/analysis/exams/:examId/overview，先尝试分配一亿对象，再可能执行一亿同步 SQLite 查询。即使在合法考试范围内也可耗尽共享进程。建议独立限制区间数、题分及汇总满分，并用单个分组 SQL 计算分布。

## 验证及证据

真实认证生产 HTTP 路径验证卡片写入、答案重算和总览。分数 1000000 产生 100000 区间、6.16 MB 响应、约 3.8 秒同步延迟、370.1 MiB RSS；1000000000 在限制 128 MiB 堆的进程中引发 OOM。源码和两次有界测量证明每十点一次分配与同步查询。证据为未限题分的 normalizeCard、重算写 grade.maxScore、持久化求和、同步区间构造及逐区间查询。

## 攻击路径与分级

普通教师 PUT 卡片巨大有限题分 → 关联考试 PUT answers 重算 → question_scores.max_score → 总览 SUM → O(fullScore/10) 对象、查询、响应 → 堆耗尽／事件循环阻塞。

发生可能性高：默认教师权限、常规 HTTP，数据可持久化，无竞态或受害者交互。影响程度高：共享 API 终止或长时间阻塞，影响全部教师、学生、扫描端。只需日常教师而非管理员或主机写入权限，非仅自身影响；限单实例可用性，未证明泄密、RCE、管理员接管或持久数据破坏，故高危。

## 假设、控制与盲点

生产按威胁模型启用 PROJECTX_AUTH_ENFORCE（该历史代码默认关闭，但测试开启）；有可写卡片、合法范围考试和至少一条 student_scores，经过判分或答案重算传播题分，然后请求总览。

角色门禁和 requireExamAccess 正常有效，8 MB JSON 只限请求字节而非数字大小，gradedCount=0 提前返回，Node 默认回环但文档支持 Nginx HTTPS。没有题分上限、独立区间数上限或分析限流；单请求足够。

仅 SQLite 动态验证，其他数据库查询成本可能不同，但对象分配仍无界。OOM 在 128 MiB 堆下证明，不代表生产默认阈值；370.1 MiB 测量独立证明显著放大。具体公网入口、主机配额、代理超时、监管及重启恢复策略未知。
