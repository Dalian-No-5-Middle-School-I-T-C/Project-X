## 概要

此问题由本次修改引入。此前总览固定使用五个区间，不论已保存满分是多少，都只执行五次计数。本次提交让内存分配和数据库工作量随攻击者可影响的 fullScore 线性增长，却没有增加分值或区间数量上限。

generateDistributionRanges() 从零开始每次增加 10，直到 fullScore，不验证或封顶。getExamOverview() 对 question_scores.max_score 求和得到 fullScore，同步调用该函数，再为每个区间单独查询数据库。答题卡更新接受客观题和主观题分值，没有有限性或上界检查；判分及答案重判将其传播到 max_score。因此，拥有普通答题卡、考试和判分权限的教师，可以将题目分值设为 1000000000 这样的巨大有限 JSON 数值，通过判分或重判保存，再请求总览。服务会先构建一亿个区间对象，再最多执行一亿次同步 SQLite 查询，耗尽内存或阻塞单个 Node 事件循环，使全校服务不可用。requireExamAccess 不能缓解，因为攻击者可以使用合法范围内的考试。区间数量应独立于数据封顶，分值需要服务端有限性和合理上限检查，分布计数最好采用一次分组 SQL，而非逐桶同步查询。

## 验证

1. 普通已认证教师可以提交并保存极大的有限答题卡分值，没有服务端数值上界。
2. 生产重判将答题卡分值写入关联考试的 max_score。
3. 同一教师可以请求总览，fullScore 由持久化数值派生且未封顶。
4. 源码及两次有界测量确认，每 10 分分配一个区间，并执行一次同步计数 SQL。
5. 包含 score=1000000000 的小型已认证输入，使真实总览路径因堆耗尽而终止；较小数值也展示数秒同步放大。

## 证据注释

1. 答题卡更新接受规范化后的请求答题卡，不限制题目分值。

## 攻击路径分析

最终策略不予排除：影响不限于本人，前提现实，攻击者是威胁模型明确包含的普通低权限教师，而不是管理员、运维、开发者或主机用户。尽管直接绑定回环地址，HTTPS／Nginx 文档支持远程访问。可控持久数据能够使共享运行时崩溃或阻塞，因此影响高；标准教师权限下的完整 HTTP 流程已经演示，因此发生可能性高。矩阵结果为高危，没有达到严重：需要教师认证及写入权限，只影响一个服务而非整个服务群，没有持久数据失陷、代码执行或管理员接管。

### 路径

普通教师 → 使用正常写入权限 PUT 答题卡，提供超大有限 score → 规范化没有有限性或上界限制 → 仓储保存 → 答题卡关联考试 → PUT /api/exams/:examId/answers 触发重判 → 更新或插入 grade.maxScore → question_scores.max_score 可控 → SUM 得到 fullScore → GET 总览 → 请求同步调用仓储 → 无界区间及逐桶同步 SQL → 产生 O(fullScore/10) 个对象、查询和响应项 → 堆耗尽或事件循环长时间阻塞。

攻击过程：教师修改答题卡，将一道客观题设为 1000000000 分。normalizeCard 不限制，仓储写入 SQLite。随后正常执行答案重判，将答题卡满分写入题目成绩表。请求总览后，服务求和，每 10 分建立一个桶，并为每桶同步查询一次。真实认证 HTTP 验证中，1000000 分产生 100000 个桶、6.16 MB 响应、约 3.8 秒同步延迟及 370.1 MiB RSS；1000000000 分尝试创建一亿个桶，使限制堆大小的 Node 内存耗尽。除普通会话外无需秘密，也不泄露秘密，影响共享可用性。回环绑定是范围反向证据，但 deploy-guide.md 明确介绍公共 HTTPS Nginx。角色权限和 requireExamAccess 是授权反向证据，但标准教师已经拥有全部所需权限，攻击发生在合法考试内。空考试提前返回是真实缓解条件，但至少一名已判分学生是普通状态。崩溃使用 128 MiB 堆，没有证明默认堆的精确失效点；无界源码、查询循环及有界 370.1 MiB 测量独立证明重大放大。

## 发生可能性

高。文档中的公共代理允许远程访问，真实认证 HTTP 流程已经执行。普通教师使用正常答题卡、重判和分析功能，不需要管理员或主机权限。请求很小，大数值可持久化，没有困难的竞争或用户交互。关联答题卡考试及至少一条成绩都是常规前提。攻击向量为远程网络。

## 影响程度

高。无界分配和同步查询发生在共享 Node 内，堆耗尽会终止进程；较大但未导致崩溃的数值也消耗数百 MiB，阻塞数秒或更久，可能使所有教师、学生和扫描端在判分期间无法使用服务。没有证明机密性或完整性影响。

## 假设条件

- 生产环境按威胁模型开启 PROJECTX_AUTH_ENFORCE。
- 攻击者控制拥有默认权限的普通教师账号。
- 可写答题卡关联合法范围内考试，且至少有一条 student_scores。
- 学校可以使用文档中的公共 HTTPS 代理暴露回环 Node。
- 精确阈值取决于堆和内存，但工作量始终随 fullScore 线性增长。

原文另列前提：

- 已认证教师拥有 grade:write、exam:write 和 grade:read。
- 可写答题卡关联可访问考试。
- 至少存在一名学生成绩，否则提前返回。
- 判分或答案重判将题目分值复制到 max_score。
- 请求总览 GET。

## 控制措施

- PROJECTX_AUTH_ENFORCE 可以强制生产认证。
- 答题卡、考试及分析前缀设有角色权限检查。
- 总览执行 requireExamAccess。
- JSON 8 MB 上限不限制数值大小。
- gradedCount=0 时提前返回。
- 默认绑定回环地址，但文档支持 Nginx 暴露。
- 没有分值上限或独立的桶数量上限。
- 未见分析限流，单次请求已足以造成所演示影响。

## 盲点

- 存在部署指南，但没有环境清单证明某个具体公网实例。
- 内存耗尽验证有意使用 128 MiB V8 堆，生产堆和进程监管下的阈值及恢复取决于部署。
- 验证使用 SQLite；其他数据库的逐查询成本可能不同，但查询完成前的区间仍无界。
- 主机内存、代理超时及重启策略没有确定。
- 该代码路径默认关闭认证，分析保守采用所给生产认证开启假设。

/** 按 10 分一段动态生成分数段，末段截止于满分 */
function generateDistributionRanges(fullScore: number): Array<{ range: string; min: number; max: number }> {
  const step = 10;
  const ranges: Array<{ range: string; min: number; max: number }> = [];
  for (let min = 0; min < fullScore; min += step) {
    const max = Math.min(min + step - 1, fullScore);
    ranges.push({ range: `${min}-${max}`, min, max });
  }
  return ranges;
~~~~
