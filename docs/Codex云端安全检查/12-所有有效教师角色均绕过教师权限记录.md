# 12 所有有效教师角色均绕过教师权限记录

- 原标题：Teacher permission rows are bypassed by every valid teacher role
- 云端级别：High
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/2257767ad06881919166100ae73f557d?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=)
- 关联提交：[992332c](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/992332c315ba5240d19044d07a10842a54d0e829)

## 概要

本提交添加管理员教师权限矩阵 teacher_permissions，含 can_view_scores、can_view_charts、can_view_students，却把执行逻辑放在所有受支持教师角色的提前返回之后。getVisibleExamIds 对无子类型教师（第 53 行）、年级负责人（55）、班主任（59—69）、学科教师（72—82）均先返回；85 行后的权限查询仅可能到达非法或遗留非空子类型。查询本身也只看 can_view_scores，其他两字段没有任何服务端授权消费者。

管理员通过受认证 API 设置全局或年级拒绝后，教师仍可请求 /api/analysis/exams/:examId/overview、/students。普通兼容教师和年级负责人获得无范围访问，可读全校身份、成绩、排名及分析；班主任／学科教师仍受旧班级／学科限制，却绕过新拒绝。原报告建议先计算角色范围，再与权限记录求交，并在对应路由落实图表／学生能力限制。

## 验证及证据

云端以 PROJECTX_AUTH_ENFORCE=1，真实管理员 API 保存三个能力拒绝后，四种合法教师身份的真实 HTTP 请求仍返回 200 及学生／总览数据。仓库追踪确认图表和学生标志无独立服务端校验。账号 API 只允许 subject_teacher、head_teacher、grade_leader 三种非空角色，全部提前返回。

分析路由依赖 requireExamAccess；null 或旧范围成员被视为允许。AnalysisRepository 排名返回学号、姓名、分项和总分、错误统计及排名。管理员配置 API 自身是有效保护的，问题在消费路径。

## 攻击路径与分级

持合法教师令牌选择 examId → grade:read 通用分析门禁 → requireExamAccess/getVisibleExamIds 提前返回 → 仓储查询 → 管理员已禁止的学生身份、成绩、排名和分析响应。

发生可能性高：一个认证 GET，无竞态、解析器漏洞或额外跳板；管理员设拒绝是正常功能使用，不是攻击者要先取得的特权。影响程度高：绕过显式管理边界，可披露大量可识别教育记录；普通教师／年级负责人范围可达全校。非仅自身或运维专属；只读、不改分、不接管身份或整库，因此高危而非严重。

## 假设条件、控制与盲点

生产认证开启；攻击者有有效教师账号但无管理员权限；管理员已配置全局／年级拒绝；目标有成绩且属于旧角色范围；远程入口按仓库 Cloudflare 文档可达。班主任和学科教师仍须符合旧范围。

现有门禁要求 grade:read；管理权限 API 要求 USER_MANAGE；学生被普通分析路由拒绝；旧班主任班级和学科教师班级／学科限制仍有效；Node 回环绑定。上述控制都不能落实新矩阵，can_view_scores 对合法状态不可达，图表与学生标志没有授权读取。

动态验证仅 SQLite，MariaDB 未跑；使用了与受影响链无关的最小 expr-eval 加载桩。具体教师能接触多少考试依生产数据而定；公网隧道支持不等于所有实例或历史 URL 仍在线。三个能力的精确政策区别没有正式规范，但 schema、API、UI 标签及注释明确将它们表述为限制。
