## 概要

本提交引入安全缺陷：新增管理权限矩阵，但执行代码被放在所有受支持教师子类型的无条件返回之后；另有两个已保存能力标志从未被任何服务端授权检查读取，形成无效安全控制。

新增 teacher_permissions 行独立保存 can_view_scores、can_view_charts、can_view_students，并有认证管理 API 设置。但 getVisibleExamIds() 对账号 API 允许的每种角色都先返回：无子类型教师第 53 行，年级负责人第 55 行，班主任第 59—69 行，学科教师第 72—82 行。因此第 85 行起的新限制只对无效或旧版非空子类型可达。且该逻辑只查询 can_view_scores；图表与学生控制从未被读取。管理员设置全局或年级拒绝后，认证教师仍能调用 /api/analysis/exams/:examId/overview、/students 等分析端点。年级负责人或兼容普通教师获得无限制考试访问，在明确拒绝下仍可披露全校成绩、身份、排名和分析；班主任/学科教师也能在旧班级范围内绕过拒绝。认证及通用 grade:read 仍有效，需教师账号，但不执行新管理边界。应先计算角色范围，再与权限行限制取交集后返回；对应路由还需专用中间件执行图表与学生能力标志。

## 验证

1. schema 和认证管理 API 可保存三类能力的明确教师拒绝。
2. 所有支持的教师身份都在评估 teacher_permissions 前从 getVisibleExamIds 返回。
3. 真实成绩/学生分析路由依赖被绕过控制，并到达返回受保护记录的仓储。
4. 认证 HTTP 专项复现显示管理员保存拒绝后仍可访问并披露。
5. 全仓追踪确认无独立服务端 can_view_charts / can_view_students 执行。

## 攻击路径分析

不适用强制排除：非本人影响、前提现实，攻击者为低权限教师而非管理员/主机操作者，权限增益为绕过管理员定义的数据访问边界。部署资料支持 Cloudflare 远程到达，尽管服务回环监听。可披露广泛可识别成绩/排名，影响高；一次认证请求，真实 HTTP 已复现，可能性高。矩阵仍为高危，没有管理员接管、RCE、完整数据库失陷或规模改分等严重条件。

### 路径

恶意/失陷认证教师 → 有效令牌及自选 examId → 经公开隧道的分析端点 → 挂载分析路由 → 通用 analysisGate 要求 grade:read → 默认教师满足 → requireExamAccess / getVisibleExamIds → null 或旧范围结果被视为授权 → AnalysisRepository 成绩/学生查询 → 数据库结果序列化给教师 → 披露受保护身份、成绩、排名、分析。

产品创建独立成绩、图表、学生可见标志，提供认证管理员 API 与 UI 管理。生产分析 API 在通用 grade:read 门禁后，每个教师都有此权限。逐考试请求委托 getVisibleExamIds；普通教师/年级负责人返回 null，班主任/学科教师返回旧班级/学科列表，均在新查询之前。requireExamAccess 将 null 或旧列表成员解释为授权。唯一服务端权限查询只读 can_view_scores，全仓没有另两字段授权读取。请求到达 AnalysisRepository，排名查询返回可识别学号、姓名、分项分、总分、错误统计和排名。可执行验证以 PROJECTX_AUTH_ENFORCE=1 经真实 HTTP，通过管理员 API 保存拒绝，四种受支持教师身份仍获 200 和敏感学生/总览数据。现有认证、通用读权限及旧班主任/学科范围有意义，但不执行新增边界。回环是直接暴露的反证，不过仓库文档及脚本提供到该端口的公开 HTTPS Cloudflare 隧道。

## 发生可能性

**高。** 直接认证 GET、自选 examId，无竞态、解析器利用或推测跳转。教师明确是部分可信威胁，每名教师都有 grade:read，文档用公网 HTTPS 隧道暴露。权限拒绝是新增管理功能正常使用，不是攻击者控制的特权准备。认证/教师要求缩小攻击群体，却不使路径罕见。**攻击向量：远程网络。**

## 影响程度

**高。** 绕过管理员明确拒绝后可披露他人的身份、学号、总分/分项分、排名、错误指标及表现分析。普通教师/年级负责人无考试限制，可能全校泄露；班主任/学科教师仍限旧范围。只读、不改分或接管管理员，不达严重标准。

## 假设条件

- 按威胁模型及验证，生产 PROJECTX_AUTH_ENFORCE=1。
- 攻击者有有效 teacher 账号，无需管理员凭据或改权限行能力。
- 管理员通过权限管理为其设全局或年级 teacher_permissions 拒绝。
- 目标考试有已判分记录且在旧角色范围内；普通教师/年级负责人旧范围无限。
- 远程暴露依据文档 Cloudflare；未用隧道/代理时网络暴露更低。

原文另列前提：

- 有效教师 Bearer 令牌。
- 管理员配置的 teacher_permissions 拒绝。
- 自选含受保护分析/学生成绩的 examId。
- 班主任/学科教师目标也须在原班级/学科范围。

## 控制措施

- 认证开启时通用门禁拒匿名并需 grade:read。
- 管理权限 API 本身需认证及 USER_MANAGE。
- 班主任旧范围仍限制分配班级。
- 学科教师旧范围仍限制分配班级和学科。
- requireExamAccess 单独拒绝学生普通分析端点。
- Node 监听回环，但文档部署有意通过 Cloudflare 发布。
- 图表/学生标志无有效后端执行，成绩标志对支持身份不可达。

## 盲点

- 动态验证仅 SQLite，未执行 MariaDB。
- 资料记录公网隧道，但不证明每部署或历史示例 URL 当前可达。
- 具体教师可访问规模依数据、子类型、班级/学科分配及拒绝配置。
- 三标志准确区别无正式政策文件，但 schema、管理 API、UI 标签和注释明确表明它们是限制。
- 验证用与此无关的最小 expr-eval 加载桩；受影响认证、权限、中间件、分析路由、仓储不依赖该服务。

export function getVisibleExamIds(user: express.Request["user"]): number[] | null {
  if (!user || user.role_name === "admin") return null;
  if (user.role_name !== "teacher") return null;
  if (!user.teacher_role) return null; // plain teacher: all visible (back-compat)

  if (user.teacher_role === "grade_leader") return null;

  const db = getDatabase();

  if (user.teacher_role === "head_teacher") {
    const classIds = db.prepare(
      "SELECT class_id FROM teacher_classes WHERE teacher_id = ?"
    ).all(user.id).map((r: any) => r.class_id) as number[];
    if (classIds.length === 0) return [];
    const rows = db.prepare(
      `SELECT DISTINCT e.id FROM exams e
       JOIN classes c ON c.id = e.class_id
       WHERE e.class_id IN (${classIds.map(() => "?").join(",")})`
    ).all(...classIds) as Array<{ id: number }>;
    return rows.map((r) => r.id);
  }

  if (user.teacher_role === "subject_teacher") {
    if (!user.subject) return [];
    const classIds = db.prepare(
      "SELECT class_id FROM teacher_classes WHERE teacher_id = ? AND (subject = ? OR subject IS NULL)"
    ).all(user.id, user.subject).map((r: any) => r.class_id) as number[];
    if (classIds.length === 0) return [];
    const rows = db.prepare(
      `SELECT DISTINCT e.id FROM exams e
       WHERE e.subject = ? AND e.class_id IN (${classIds.map(() => "?").join(",")})`
    ).all(user.subject, ...classIds) as Array<{ id: number }>;
    return rows.map((r) => r.id);
  }

  // Check teacher_permissions for additional restrictions
  if (user.role_name === "teacher") {
    const db = getDatabase();
    if (hasTable(db, "teacher_permissions")) {
      const restrictions = db.prepare(
        "SELECT grade_id, can_view_scores FROM teacher_permissions WHERE teacher_id = ? AND can_view_scores = 0"
      ).all(user.id) as Array<{ grade_id: number | null }>;
      // If any restriction forbids all grades (grade_id = null), deny everything
      if (restrictions.some((r) => r.grade_id === null)) return [];
      // Filter out exams from restricted grades
      if (restrictions.length > 0) {
        const restrictedGrades = restrictions.map((r) => r.grade_id).filter(Boolean) as number[];
        const db = getDatabase();
        return (db.prepare(
          `SELECT DISTINCT e.id FROM exams e
           JOIN classes c ON c.id = e.class_id
           WHERE e.grade_id NOT IN (${restrictedGrades.map(() => "?").join(",")})`
        ).all(...restrictedGrades) as Array<{ id: number }>).map((r) => r.id);
      }
    }
  }

  return null;

      INSERT INTO teacher_permissions (teacher_id, grade_id, can_view_scores, can_view_charts, can_view_students, updated_at)
      VALUES (?, ?, ?, ?, ?, CURRENT_TIMESTAMP)
      ON CONFLICT(teacher_id, grade_id) DO UPDATE SET
        can_view_scores = excluded.can_view_scores,
        can_view_charts = excluded.can_view_charts,
        can_view_students = excluded.can_view_students,
        updated_at = CURRENT_TIMESTAMP
    `).run(
      teacher_id,
      grade_id ?? null,
      can_view_scores ? 1 : 0,
      can_view_charts ? 1 : 0,
