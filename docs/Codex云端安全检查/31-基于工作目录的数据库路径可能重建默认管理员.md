# 31 基于工作目录的数据库路径可能重建默认管理员

- 原标题：CWD-based database path can recreate the default admin
- 云端级别：Medium
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/1f3af219e4748191ad0142001775b891?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=&page=2)
- 关联提交：[0642990](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/064299034b261ac0f738b2652f21178f749b45b5)

## 概要

本提交把默认 SQLite 路径从数据库模块 import.meta.url 相对位置改为 process.cwd()/data/projectx.db。esbuild 单文件 dist/server/index.mjs 下旧路径按模块位置解析，新路径按启动工作目录，未设 PROJECTX_DB_PATH 的独立部署升级后可能换库，没有兼容查找／迁移。better-sqlite3 自动创建新文件，初始化空 schema 并生成已知 admin/admin123。

已公开代理继续转发时，攻击者可抢先登录新管理员；旧用户、考试、成绩在当前服务中不可见。Electron 显式设置路径，不受影响；仓库根目录源码启动通常一致。受影响重点是依赖默认路径的独立生产 bundle／异常源码启动方式。

## 验证及证据

证明固定安装位置与不同 cwd 的前后默认路径分歧，观察两个数据库、新库初始化、已知管理员、真实 HTTP 登录 200、通配符权限及管理员 /api/users 200，没有有效首次改密门禁。

重要限制：直接执行 bundle 因 cleanup.ts 主入口判断被折叠而退出，不监听；可执行复现用额外启动器 import 导出的 startServer。Electron 使用这一导出但固定路径，仓库没有随附有风险的非 Electron import 启动器。因此可实现性已证明，普及度未证明。

## 攻击路径与分级

运维跨版本升级且路径未固定 → cwd 选到空新库 → 初始化 admin/admin123 → 已存在公网代理 → 匿名登录 → role 1 通配符令牌 → 受保护管理 API。

影响程度高：匿名到管理员已验证，并丢失运行中旧库可见性；但旧数据库本身没有通过新库直接泄露，初期管理影响可能只在新空实例。原可能性字段写 High，说明再因升级、未设置路径、目录分歧、受影响启动器、对外代理等联合条件调整中；原严重判断被降为最终中危。

## 假设、控制与盲点

既有 SQLite 跨此提交升级；无 PROJECTX_DB_PATH；cwd/data/projectx.db 与旧位置不同；非 Electron 的受影响启动器实际运行；代理可达；运维未发现并修复重建账号。

现有显式路径环境变量、Electron 用户目录覆盖、根目录源码启动、回环监听、HTTPS 指南、bcrypt、32 字节随机令牌、管理员 user:manage 检查，都不能阻止新建合法管理员通过；此版本无首次改密门禁和登录限流。

没有非 Electron 生产 manifest、工作目录清单或使用统计；实验只放旧管理员哨兵，未填代表性历史考试／成绩／学生。真实网络入口、运维发现日志和抢先改密概率未知。
