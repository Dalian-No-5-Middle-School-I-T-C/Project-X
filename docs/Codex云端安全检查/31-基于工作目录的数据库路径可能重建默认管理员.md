## 概要

此问题由本次修改引入。新的相对于 process.cwd() 的默认路径，与旧打包独立服务相对于模块的路径不兼容。新选择的数据库为空时会自动创建使用已知凭据的管理员，因此问题不只是路径失效，还可能在升级时暴露管理账号。

此前默认路径来自数据库模块的 import.meta.url；在 esbuild 单文件产物 dist/server/index.mjs 中，相对 dist/server 解析。本次提交改为 cwd/data/projectx.db。对于没有显式设置 PROJECTX_DB_PATH 的独立包，如果工作目录与此前模块相对路径的基准不同，升级会选择另一个数据库，且没有旧库兼容查找或迁移。better-sqlite3 创建新文件，初始化空数据库结构，ensureDefaultAdmin 创建 admin/admin123。如果既有代理自动公开服务，匿名用户可在操作者发现数据库切换之前登录，取得完整管理员权限。同时，旧用户、考试和成绩在运行服务中不可见。Electron 显式设置路径，因此不受影响；从仓库根目录启动源码时，通常也仍使用相同位置。受影响的是依赖默认路径、受支持的独立生产包。

## 攻击路径分析

分别评估影响和发生可能性后再应用矩阵。可执行验证证明，匿名用户能够获得通配权限管理员身份并访问受保护端点，因此影响高。只有升级、未设置路径、工作目录分歧、使用受影响启动器及外部代理同时存在，远程利用才会变得简单，所以整体发生可能性为中。Electron 覆盖、仓库根目录源码启动说明、直接运行打包文件失败等强反向证据，不会使路径完全不可达，但不支持保留原来的严重级别。高影响与中等可能性得到中危。

### 路径

匿名远程用户 → HTTPS 公共代理或 Cloudflare → 回环 5174 Express 服务 → 启动按工作目录解析路径 → 新 data/projectx.db → better-sqlite3 创建数据库并初始化管理员 → 新结构及 admin123 → 已知凭据通过 bcrypt → 登录签发 role 1 通配权限令牌 → 认证和权限检查接受 → 控制管理 API 及学校服务。

操作者未设置 PROJECTX_DB_PATH，升级了已经配置代理的服务。如果新工作目录与父版本隐含路径不同，就会选择新数据库，完成创建、初始化及 role_id=1 管理员生成。匿名攻击者提交已知凭据，取得通配权限令牌并访问 GET /api/users。验证确认存在两个独立数据库，重建账号登录返回 200，具有通配权限，管理端点也返回 200。认证和授权真实有效，却把重建管理员视为合法用户；本提交在签发令牌之前没有强制改密。最强反向证据来自部署：回环监听；文档服务启动器从仓库根目录运行源码；Electron 提供稳定路径覆盖；直接执行打包文件会因 cleanup.ts 主入口检查被合并入包而退出。回环监听不足以否定问题，因为文档支持 Nginx／Cloudflare 公开访问。主流启动方式不受影响则是更实质的限制：演示需要独立启动器导入已导出的包，仓库没有提供非 Electron 的导入包启动器，因此降低可能性。受影响实例中的通配权限接管已经证明，影响仍高，但旧数据库只是不可见，不会由新数据库直接泄露。

## 发生可能性

原栏标注 High（高），正文将整体可能性校准为中。受影响服务运行后，源码中的固定凭据、公开登录及代理使远程利用容易；但需要没有设置路径、工作目录发生分歧，并采用非 Electron 的导入包启动方式或不常见的源码启动位置。出厂 Electron 设置路径，文档从源码根目录启动，直接运行当前打包文件则会退出。验证证明路径可达，但没有证明这类部署普遍存在。攻击向量为远程网络。

## 影响程度

高。匿名用户取得 role 1 通配权限令牌，可广泛控制新活动数据库中的身份、配置、判分和记录；旧数据不可见造成可用性损失。不评为严重，是因为旧数据库不会直接暴露，即时影响可能首先限于新初始化服务，而非全部历史数据。

## 假设条件

- 已有 SQLite 实例从父版本升级。
- 启动时没有设置 PROJECTX_DB_PATH。
- 工作目录不同于父版本模块相对数据库位置的基准。
- 使用导入包或等效的受影响源码方式启动，而不是 Electron。
- 文档中的代理或 Cloudflare 向攻击者公开服务。
- 操作者尚未发现新空数据库，并更改或禁用重建账号。

原文另列前提：

- 跨越该路径变更进行升级。
- 环境路径变量保持未设置。
- cwd/data/projectx.db 不同于旧模块所用数据库。
- 受影响的非 Electron 启动器运行 HTTP 服务。
- 代理或隧道公开回环服务。
- 攻击者在重建初始化凭据被修改之前访问登录接口。

## 控制措施

- startServer 只绑定 127.0.0.1。
- 文档推荐 HTTPS 代理。
- PROJECTX_DB_PATH 可固定绝对路径。
- Electron 在导入服务之前设置用户目录路径。
- 使用 bcrypt 验证密码。
- 登录令牌由 32 个随机字节生成。
- 用户管理要求认证和 user:manage。
- 通配权限由集中角色访问控制执行。
- 文档中的源码启动先切换到仓库目录，通常使新旧默认位置相同。
- 此提交没有强制改密入口来阻止立即使用新管理员。
- 此提交的登录路由没有限流。

## 盲点

- 没有清单或遥测说明真实的自定义导入包或非根目录源码部署数量。
- 没有 systemd、容器或 Kubernetes 配置，能够确定非 Electron 工作目录及环境路径。
- 验证使用独立启动器导入 startServer；该接口确实导出且被 Electron 使用，但仓库没有受影响的非 Electron 启动器。

- 验证证明旧管理员哨兵记录不可见，没有填入代表性的历史考试、成绩及学生数据。

export function getDatabase(): Database.Database {
  if (!dbInstance) {
    const dbPath = resolveProjectDbPath();
    mkdirSync(path.dirname(dbPath), { recursive: true });
    dbInstance = new Database(dbPath);
    dbInstance.pragma("journal_mode = WAL");
    dbInstance.pragma("foreign_keys = ON");
    dbInstance.pragma("synchronous = NORMAL");
    dbInstance.pragma("busy_timeout = 5000");
    console.log(`[DB] Connected to: ${dbPath}`);

export function initializeDatabase(): void {
  const db = getDatabase();
  const hasTables = db.prepare("SELECT COUNT(*) as cnt FROM sqlite_master WHERE type = 'table'").get() as { cnt: number };

  if (hasTables.cnt === 0) {
    const schema = readFileSync(schemaPath(), "utf8");
    db.exec(schema);
    console.log("[DB] Schema created successfully");
  }

  runMigrations(db);
  seedDefaultData(db);

export async function ensureDefaultAdmin(): Promise<void> {
  const db = getDatabase();
  const existing = db.prepare("SELECT id FROM users WHERE username = ?").get("admin");
  if (existing) {
    return;
  }

  const passwordHash = await hashPassword("admin123");
  db.prepare(
    `INSERT INTO users (username, password_hash, name, role_id, is_active)
     VALUES (?, ?, ?, ?, ?)`
  ).run("admin", passwordHash, "系统管理员", 1, 1);
  console.log("[DB] Default admin created: username=admin, password=admin123");
~~~~

export function resolveProjectDbPath(): string {
  const envPath = process.env.PROJECTX_DB_PATH;
  if (envPath) return path.resolve(envPath);
  return path.join(process.cwd(), "data", "projectx.db");
}
