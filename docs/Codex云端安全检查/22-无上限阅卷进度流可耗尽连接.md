## 概要

本次提交新增存在问题的进度监听映射，以及可以无限保持打开的 SSE 路由。此前没有这种能够保留任意响应对象和连接的判分进度流。

新的 GET /api/cards/:cardId/grading/progress/:batchId 不检查答题卡是否存在、批次是否活动或是否属于请求用户，就开始 SSE。每个自选 batch ID 都在全局 gradingProgressListeners 中保存一个捕获 Express response 的闭包。如果该 ID 没有判分请求发送 done／error，服务没有超时或其他清理，只在客户端断开时清理。拥有通用 card:read 的教师可以打开大量 /api/cards/nonexistent/grading/progress/unique-N 并保持连接，消耗 Node 和代理套接字、文件描述符及堆，直到合法扫描判分被拒绝。默认不强制认证的安装也允许匿名调用，尽管生产指南要求开启认证。应只接受绑定到用户和答题卡的服务端活动作业 ID，拒绝未知作业，设置逐用户／IP 流数量上限和有界空闲寿命。

## 验证

1. 生产中间件接受低权限调用方自选 cardId 和 batchId；强制认证模式下已测试教师令牌，默认不强制认证的行为由源码确认。
2. 不存在的答题卡或未知批次，在没有活动作业、归属或答题卡验证时仍被接受。
3. 每个保留请求都注册捕获响应的全局闭包，没有服务端超时、数量上限或空闲到期。
4. 请求复现保持 2,000 个未知 ID 连接 15 秒，文件描述符精确增加 2,000，RSS 约增加 59 MiB。
5. 攻击者保持连接时资源持续保留，断开后文件描述符回到基线；从未创建的批次永远不会产生 done／error。

## 攻击路径分析

不适用强制排除：共享部署中的影响不限于本人，前提现实，最多需要普通教师，而非管理员、运维、开发者、物理访问或受保护写入。已经证明通用答题卡读取能够越界控制共享资源。套接字、文件描述符、响应、闭包和堆无界保留，测得 2,000 个文件描述符及约 59 MiB 消耗，因此影响高。威胁模型支持远程访问，ID 简单，默认教师或关闭认证时的匿名用户均可使用，因此发生可能性高。矩阵为高危，不达到严重：只涉及可用性，有界验证没有完全中断服务，耗尽阈值依赖部署和代理。保留原级别。

### 路径

远程调用方或教师 → 建立多个长期 HTTP 连接 → 公共代理或隧道连接回环服务 → GET 进度 → 可选身份解析及通用 card:read → 默认放行，或教师满足权限 → 任意 SSE → 为未经验证的 batchId 注册捕获响应闭包 → 全局映射及打开的响应保留 → 一直持续到攻击者断开 → Node／代理连接、文件描述符及堆耗尽。

这是产品判分真实运行路径中的可用性漏洞，而非仅正确性问题。正常客户端自行创建进度 ID，在提交任务之前打开 EventSource，服务端却不维护或验证服务端作业。cardId 未被使用，safeId 只是移除字符；任何可达调用方都控制两个 ID。每个批次加入捕获 response 的闭包，没有流上限、空闲或绝对寿命，也不拒绝未知 ID。未知 ID 没有终止事件，清理由攻击者控制。强制认证时拒绝匿名用户，默认教师具有 card:read；默认关闭认证的兼容部署允许匿名访问。不涉及秘密披露，后果为共享资源耗尽。已认证教师的正常 HTTP 验证保留 2,000 个请求，精确增加 2,000 个文件描述符和约 59 MiB，全部直到客户端释放才关闭。最强影响反向证据是测试没有完全中断服务，普通请求仍然快速，断开后描述符恢复；这限制了对特定部署中断阈值的确信，但不否定无界线性保留。回环监听和上游限制也只降低对暴露的确信，不提供应用侧上限。

## 发生可能性

高。普通 GET、任意路径即可，不需要竞争或昂贵前提。生产强制认证时，默认教师可读答题卡；兼容默认配置无需账号。威胁模型包含现实的代理或隧道。完整攻击需要多个连接，未知代理限制及回环绑定带来不确定性，但 2,000 连接 HTTP 验证证明了可达性和稳定保留。攻击向量为远程网络。

## 影响程度

高。影响承载判分、扫描、答题卡、考试和分析的共享 Express。2,000 个请求导致 2,000 个文件描述符和约 59 MiB 持续占用，直到释放；在部署限制下，可能在敏感业务窗口拒绝合法业务。没有机密性或完整性影响，测试也没有强制中断，但威胁模型明确将持续的低权限资源耗尽视为高影响。

## 假设条件

- 共享 Express 通过威胁模型中的代理或 Cloudflare 暴露，仓库没有入口配置。
- 正确生产部署强制认证，主要情景为合法或失陷的 card:read 教师。
- 攻击者能够维持多个 TCP 连接，没有未知上游限制在实质资源消耗之前阻止。
- 所需连接数取决于生产文件描述符、内存及代理容量。

原文另列前提：

- 通过威胁模型中的代理或隧道能够访问 API。
- 开启认证时，需要有效 card:read 账号，默认教师包含该权限。
- 关闭认证时无需身份。
- 能够打开并有意保留大量并发 HTTP 连接。
- 应用或上游限制足够高，允许达到实质资源影响的流数量。

## 控制措施

- optionalAuth 解析有效 Bearer 或查询令牌，不拒绝匿名请求。
- 配置开关可以启用 401／403 检查。
- 强制认证时，GET 答题卡需要 card:read。
- safeId 只保留字母、数字、下划线和连字符。
- done／error 删除对应监听集合。
- req close 删除单个监听和空集合。
- 终止快照在 60 秒后删除。
- Node 监听 127.0.0.1。
- 没有应用流限流、并发上限、作业验证、归属检查、空闲或绝对寿命。

## 盲点

- 没有代理、隧道、负载均衡或网络配置，公开性依据所提供威胁模型。
- 生产代理的连接限制、超时、逐 IP 控制和缓冲未知。
- 生产文件描述符上限、容器或服务内存、Node 设置及主机容量未知。
- 验证证明线性保留及清理，没有用 2,000 连接强制导致完全拒绝服务。
- 通过回环测试 Express，没有测量真实代理的额外资源消耗或更早限制。
- 纯 Electron 临时回环部署可能只产生本地或本人影响，不构成远程可报告情形。

  app.get("/api/cards/:cardId/grading/progress/:batchId", (req, res) => {
    const batchId = safeId(paramValue(req.params.batchId));

    res.writeHead(200, {
      "Content-Type": "text/event-stream",
      "Cache-Control": "no-cache",
      Connection: "keep-alive",
      "X-Accel-Buffering": "no"
    });

    const handler = (event: GradingProgressEvent) => {
      res.write(`data: ${JSON.stringify(event)}\n\n`);
      if (event.type === "done" || event.type === "error") {
        res.end();
      }
    };

    if (!gradingProgressListeners.has(batchId)) {
      gradingProgressListeners.set(batchId, new Set());
    }
    gradingProgressListeners.get(batchId)!.add(handler);

    const snapshot = gradingProgressSnapshots.get(batchId);
    if (snapshot) {
      handler(snapshot);
    }

    req.on("close", () => {
      const listeners = gradingProgressListeners.get(batchId);
      if (listeners) {
        listeners.delete(handler);
        if (listeners.size === 0) gradingProgressListeners.delete(batchId);
      }
    });
~~~~
