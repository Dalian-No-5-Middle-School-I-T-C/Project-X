## 概要

此问题由本次提交引入：提交新增可导入的种子数据和备份流程，安装使用公开文档所载固定密码的活动账号。尤其是新建教师没有设置细分教师角色，因而触发应用的向后兼容分支，获得所有考试的可见性，并同时拥有教师角色的写入权限。

新增种子命令默认针对应用当前数据库执行，并无条件创建使用硬编码密码 teacher123 的 demo-teacher。文档公开了该凭据，并建议直接向当前数据库写入种子数据，或恢复附带数据库。账号被创建为教师，但没有 teacher_role；已有授权逻辑将这类旧版教师视为能够访问每一场考试，而默认教师角色包含答题卡、考试及成绩写入权限。因此，一旦操作者将数据集导入能够从互联网访问的实例，了解仓库内容的未认证攻击者就能使用公开凭据登录，读取全校考试数据，并修改或删除答题卡、考试和成绩。整库恢复路径还打包了一个数据库，其中已经初始化文档公开的 admin/admin123 引导账号。利用依赖操作者明确导入这个测试包，但两种导入方式均未强制使用隔离的开发数据库，也未禁用账号、生成一次性凭据，或警告导入后的实例不得对外暴露。演示教师应默认禁用，或使用随机生成且必须更换的凭据，并配置仅限演示班级的 subject_teacher 角色；生产数据库或非空数据库应要求显式开启不安全操作覆盖选项。

### 路径

特权操作者导入测试／演示包 → 种子写入或恢复创建账号 → 运行数据库中安装活动的固定密码演示教师 → 通过 bcrypt 验证的活动账号完成认证 → 服务签发教师 Bearer 令牌 → 会话身份中的 teacher_role = NULL → NULL teacher_role 激活旧版不受限制的考试可见性 → 对象范围过滤返回无限制可见范围 → 教师读写权限授权考试和成绩路由 → 考试及成绩 API 执行已授权读写 → 学生记录泄露，学业数据被修改或删除。

没有指定其他路径时，演示种子选择 data/projectx.db，对其初始化，并使用仓库文档公开的固定密码创建活动教师，同时省略 teacher_role。UserRepository 将省略的角色保存为 NULL。认证接受该凭据，并签发包含默认教师广泛答题卡、考试及成绩权限的令牌。考试可见性函数有意为 NULL 角色旧版教师返回无限制范围，所以导入账号可以跨越学科和班级边界。提供的可执行验证启用认证，通过真实 API 登录，读取账号名义上的数学范围以外的考试及可识别个人身份的成绩，修改单题成绩、重命名考试，并删除考试。最强反向证据涉及适用范围，而不是导入后的可利用性：该文件明确属于测试数据，导入从不自动执行；种子模式要求特权 shell 访问，恢复要求 USER_MANAGE，服务本身也绑定回环地址。不过，文档中的 Nginx 部署支持公开访问。因此，导入后的安全影响真实且较高，但触发问题状态需要特权操作者将测试数据安装到可访问的运行环境。所提供的强制排除策略据此认定该问题不可报告，尽管条件性影响已经得到证明。

## 发生可能性

原栏标注高（High）。导入后的网络利用很直接，使用仓库公开凭据，并已通过真实 API 复现。然而，创建问题状态需要特权操作者主动向运行数据库执行测试种子命令，或使用管理员保护的恢复操作，之后保留导入账号不变并暴露服务。该包是明确隔离存放的测试数据，并非自动生产迁移。按所提供的“仅操作者可执行或受保护写入路径前提”强制排除规则，最终可报告性中的发生可能性归为 ignore。攻击向量为远程网络。

## 影响程度

高（High）。测试包一旦导入含有现有数据的运行数据库，该账号不受限制的旧版范围与教师写入权限，允许广泛泄露可识别身份的考试成绩，并对考试和成绩实施完整性或可用性攻击。可执行验证证明了跨学科读取、修改成绩、重命名考试及删除考试。由于学业记录属于敏感数据，且成绩完整性是主要受保护资产，因此条件性影响为高。

## 假设条件

- 具备 shell 能力的操作者向应用当前数据库执行演示种子命令，或已认证管理员恢复附带演示备份。
- 导入的演示账号保持活动，在服务可访问前没有修改仓库公开的固定密码。
- 尽管 Node 进程绑定回环地址，API 仍通过文档中的 HTTPS 反向代理部署对外暴露。
- 已启用认证强制执行；否则，相同数据路由本就可以访问，无需依赖导入凭据。
- 通过种子模式造成全校范围的高影响泄露或修改，需要当前数据库除演示数据外还包含真实考试或学生记录。

- 导入的固定密码账号保持活动且未被修改。
- 导入后的服务仍可通过反向代理或同等入口访问。

## 控制措施

- 运行 users 表中的密码使用 bcrypt 哈希，并非明文存储。
- 启用 PROJECTX_AUTH_ENFORCE 时，业务路由入口拒绝未认证请求，并检查角色权限。
- 恢复端点独立要求认证及 USER_MANAGE 权限。
- 服务绑定 127.0.0.1，需要代理或隧道才能远程访问。
- 成功验证密码后，系统随机生成 Bearer 令牌。
- 存在对象级考试授权，但其有意设置的 NULL teacher_role 兼容分支会为该账号放开范围。
- 导入教师没有被设置明确的受限教师角色、禁用状态、随机凭据，也没有已证明有效的强制更换密码要求。

## 盲点

- 仓库证据无法确定是否有真实部署导入了这个包、保留固定凭据，或暴露了导入后的服务。
- 未检查具体部署的入口、防火墙或云配置；远程范围判断依据所提供的威胁模型及文档中的 Nginx 部署。
- 附带备份中的活动凭据状态，部分依赖提供的验证对归档的直接检查；本分析没有展示或复现密码哈希材料。
- 验证服务器需要临时的仅启动阶段依赖桩，不过实际测试的认证、考试及成绩路径都不使用该依赖。
- 可执行验证使用预置的演示记录，而非真实学校的完整数据库；对真实记录的更广泛影响，由源码确认的无限制可见性行为推导而来。

/**
 * 根据当前用户的教师角色和所教班级，返回可见的考试ID列表。
 * - admin / grade_leader → 全部可见（返回 null）
 * - head_teacher → 只看自己班级的考试（全科目，本年级）
 * - subject_teacher → 只看自己教的科目 + 自己教的班级
 * - 普通 teacher（无 teacher_role）→ 全部可见（向后兼容）
 */
function getVisibleExamIds(user: express.Request["user"]): number[] | null {
  if (!user || user.role_name === "admin") return null;
  if (user.role_name !== "teacher") return null;
  if (!user.teacher_role) return null; // 普通教师向后兼容，全部可见
~~~~
