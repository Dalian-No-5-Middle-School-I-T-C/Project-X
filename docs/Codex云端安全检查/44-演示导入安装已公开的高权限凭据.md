# 44 演示导入安装已公开的高权限凭据

- 原标题：Demo import installs published privileged credentials
- 云端级别：Informational
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/867e924db2e88191b1e3645e156bbeac?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=&page=3)
- 关联提交：[27cc247](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/27cc24717245f56688e5f7b47799e3559defad2d)

## 概要

新增测试种子和备份导入会创建具有公开固定口令的活动账号。种子默认写入当前 data/projectx.db，创建 demo-teacher / teacher123，未设置 teacher_role。旧兼容分支将 NULL teacher_role 的教师视为可见全部考试，而默认教师拥有答题卡、考试和成绩读写权限。文档公开凭据并介绍当前数据库导入及整库恢复；打包备份还包含 admin / admin123 初始化账号。

如果运维人员导入到含真实业务数据且可远程访问的运行库，并保留这些凭据，外部人可登录并跨学科读取成绩、修改或删除考试和成绩。建议默认禁用演示账号，或使用随机且强制更换的凭据，并赋予仅限演示班级的 subject_teacher；生产/非空库应要求显式危险操作开关。

## 验证与证据

原测试验证教师及打包管理员口令的哈希匹配、教师角色为空且无班级分配、实际登录无需强制改密，以及真实权限检查授予全局考试可见性。在强制认证的隔离环境中，复现跨学科读取、题目改分、考试改名及删除。种子/恢复无生产或非空库安全门槛。

## 路径与等级判断

高权限操作者主动导入测试包 → 活动固定口令教师写入运行库 → 外部人以公开口令取得教师令牌 → NULL 细分角色触发全局兼容范围 → 教师权限允许读取、修改和删除业务数据。

导入后的网络利用简单、条件性影响高；但包被明确标注为测试数据，种子必须由有 shell 权限的操作者运行，恢复需 USER_MANAGE，导入并非自动生产迁移。最终策略先排除这种依赖管理员主动安装测试数据的前提，故为信息提示，不否认导入后的高影响。

## 前提与防护

需操作者主动导入、固定口令保持活动且未更换、通过代理暴露服务；涉及真实学校记录的广泛影响还需将种子写入已有真实数据的库。若认证本来关闭，相同业务路由已不依赖该口令。

运行库使用 bcrypt、随机登录令牌、业务认证和权限检查；恢复单独检查 USER_MANAGE；Node 监听 127.0.0.1，文档支持 Nginx HTTPS 暴露。但 NULL 角色兼容逻辑为此账号开放全局范围，未设置随机口令、禁用态、限定角色或已证明的强制轮换。

## 盲点

未证明真实部署导入或保留了这些账号，未检查部署防火墙/入口。备份凭据状态部分依赖原验证对归档的直接检查；未展示哈希材料。验证服务器使用临时启动依赖桩，所测认证、考试与成绩路径不调用它。测试使用演示记录；真实记录的扩展影响来自已确认的全局权限逻辑。
