## 概要

此问题由本次修改引入。此前演示种子属于开发者测试工具；本次变更新增服务端 DemoDataService、管理员生产端点和 Web 操作，将固定凭据写入实际数据库。账号继承普通教师授权，而不是被限制在演示范围内。

SQLite 管理员现在可从正常界面或 API 导入。流程创建 demo-teacher 和 demo-teacher-2，密码为 teacher123，省略 teacher_role 和 password_change_required，因此成为活动普通教师，无需改密。API 响应及仓库文档公开凭据。影响不限于演示考试：没有细分角色的教师，其 getVisibleExamIds 有意返回无限制范围，默认教师又拥有答题卡、考试及成绩写入权限。管理员执行看似无害的导入后，匿名互联网用户可用公开凭据登录，读取全校记录，修改分数或答案，或删除真实考试。管理员权限入口只保护导入发起，不能保护随后出现在公开登录面上的高权限账号。应使用随机一次性凭据、强制更换密码、严格限制演示考试和班级，或只在明确隔离的演示模式中允许这些账号认证。

## 攻击路径分析

内在技术严重性仍高，已经验证匿名用户取得教师身份后，可以读取非演示记录并进行破坏性修改。不能强制排除：虽然管理员创建账号，但权限提升正是问题所在——导入样例不等于授权任意远程用户取得教师身份。它不是只影响本人、只能由操作者利用，或不可达的受保护写入问题。不过，管理员交互、SQLite、开发菜单、清除能力、回环监听及实际代理依赖，使发生可能性为中。高影响与中等可能性得到中危。

### 路径

管理员在 SQLite 导入 → 种子写入固定教师 → 活动 demo-teacher／teacher123 → bcrypt 接受凭据 → 登录返回无需改密的令牌 → 普通教师且细分角色为 null → 可见范围为 null → requireExamAccess 允许全部考试 → 真实考试读改删及成绩／答案路由 → 读取、修改、删除真实学业记录 → 影响全校数据机密性、完整性和可用性。

React 管理界面对应 Express 及 SQLite／MariaDB 后端。SQLite 的实际导入调用服务，对固定密码执行 bcrypt，并插入两个活动教师；省略字段默认 NULL 和 0。API 及 README 公开凭据，网络用户可登录而无需强制更换。身份获得默认写入权限，旧版普通教师的 null 范围被考试入口视为全部授权。真实考试端点能够读取结果、修改和删除考试，改分路由能够修改成绩及答案。隔离的可执行复现确认登录和非演示 GET／PATCH／DELETE。反向证据有实质意义：仅管理员、开发菜单、拒绝 MariaDB、登录限流、回环监听，以及管理员可以清除。这些降低概率，却不能消除文档代理部署中导入后的匿名到教师身份提升。

## 发生可能性

原栏标注 High（高），正文最终校准为中。账号存在后，远程利用复杂度低，攻击者无需已有账号，凭据公开且复现已确认。但必须由管理员先在开发模式导入，使用 SQLite，账号未清除或更换密码，实际入口也依赖部署，因此降低为中。攻击向量为远程网络。

## 影响程度

高。取得的身份跨越演示范围，进入真实学校记录，可以读取考试结果、修改元数据、删除考试、修改学生分数及答案，对单学校的机密性、完整性和潜在可用性产生高影响；它不直接授予管理员身份，也不导致整个安装群失陷。

## 假设条件

- 远程分类依据文档中的 Nginx HTTPS 部署，Node 本身绑定回环 5174。
- SQLite 管理员已经导入，没有清除数据、禁用账号或修改密码。
- 保持默认教师权限和兼容语义；管理员可以定制这些设置。
- 攻击者可通过代理或同等入口访问。

原文另列前提：

- 使用 SQLite，生产端点拒绝 MariaDB。
- 拥有 USER_MANAGE 和 SYSTEM_MANAGE 的管理员直接或通过开发界面导入。
- 演示账号活动，固定密码未变。
- Express 通过文档中的代理或其他入口可达。
- 没有收窄教师权限及普通教师可见性。

## 控制措施

- 导入路由要求认证及 USER_MANAGE，端点额外要求 SYSTEM_MANAGE。
- 仅允许 SQLite，拒绝 MariaDB。
- 非管理员看不到界面入口，操作放在开发／高风险区域。
- 导入之前要求确认。
- users 表中保存 bcrypt 哈希，而非明文密码。
- 登录限制为每 IP 每 15 分钟 10 次。
- 使用随机不透明令牌，支持 HttpOnly／SameSite=Lax。
- 存在强制改密中间件，但默认标记为 0，不会触发。
- 考试存在范围检查，但没有细分角色时全部授权。
- 只有管理员可以通过 clear-demo 删除 is_demo 账号和数据。
- 绑定回环地址，指南推荐 HTTPS 代理。

## 盲点

- 文档不能证明某个具体实例公网可达。
- 实际角色可以定制，静态分析无法确定。
- 复现覆盖登录及非演示数据读取、修改和删除；改分和答案仅进行了源码追踪。
- 没有运行日志证明导入频率及账号保留时间。
- 指南建议 HOST 设置，代码却明确绑定回环地址，因此远程访问依赖代理。
- 不知道操作者是否独立更换密码、禁用账号，或通过防火墙限制访问。
