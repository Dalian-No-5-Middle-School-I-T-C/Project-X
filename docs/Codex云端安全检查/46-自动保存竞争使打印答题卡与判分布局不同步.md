# 46 自动保存竞争使打印答题卡与判分布局不同步

- 原标题：Autosave race can desynchronize printed cards and grading layout
- 云端级别：Informational
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/4823f95f748c8191b21e657152e10cf2?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=&page=3)
- 关联提交：[014cef0](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/014cef038f8716e26b85754ab4a128aacd38d709)

## 概要

新增异步自动保存及先保存再导出流程存在竞争。PDF 导出保存快照 A 时，教师仍能编辑成 B；persistCardSnapshot 检测到更新只安排下一次自动保存，仍向导出返回旧响应 A。导出立即打开未绑定不可变版本的 PDF URL，约 1.2 秒后 B 保存并重建服务端布局，可能出现打印 A、扫描判分用 B。

应在导出期间禁止编辑，或持续保存直到 savedRevisionRef 与 editRevisionRef 一致，并将 PDF 绑定到该不可变版本。

## 验证与证据

通过真实 PUT/PDF 接口和渲染器复现：A 生成 9,508 字节、单面、五列学号 PDF；随后服务端 B 为双面、九列。标题、单双面与学号几何存在差异。旧响应不会覆盖新 React 状态，但仍被导出消费；忙碌时仅 PDF/保存按钮被禁用，编辑输入仍可用。

## 路径与等级判断

有权教师导出脏卡 A → 请求未结束时编辑 B → 保存响应仅延后保存 B → PDF GET 在 B 写入前读取可变记录 A → B 随后成为扫描布局。

原报告技术校准段采用高影响、中等可能性，得到中危；单列可能性栏目写为 High，同时说明需特定时序与后续打印判分。最终因仅有已获授权的卡片编辑者参与、无权限增益，按策略排除为信息提示。教师原本即可主动保存/打印两种布局，未证明学生、未登录者、扫描密钥或较低权限教师能迫使他人会话触发竞争。

## 影响、前提与防护

批量打印旧版并按新版扫描时，可能影响多个学生并需重扫/重判；未实际验证物理扫描或错误成绩。新编辑不会丢失，操作者可检查并重新生成 PDF。

需合法设计权限，第二次编辑发生于首次 PUT 返回前，PDF 读取先于延后保存，旧 PDF 被使用且后续按最新布局判分。身份/RBAC、设计入口权限、版本比较、最终自动保存、分数校验和 PDF 禁缓存均有效，但未保证导出版一致性。

## 盲点

结果依赖 refreshCards 与网络时序，若 B 先写入则 PDF 可能已为 B。Electron 完整 UI 自动化因宿主 GUI 库缺失未运行，实际服务接口与渲染器已执行。未验证真实认证及代理配置；部署指南建议 HOST=0.0.0.0，但代码硬编码 127.0.0.1，远程依赖另设代理。
