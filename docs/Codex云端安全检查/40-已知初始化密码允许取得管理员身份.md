## 概要

本次提交新增自动创建固定密码管理员及网络登录功能，引入了该漏洞。应改为为每个实例生成密码学随机的初始化秘密，通过受保护渠道交付，并在签发完整特权会话之前要求一次密码更换。

每个新数据库都会创建活动的 admin 账号，密码固定为 admin123。账号在开始监听之前创建，登录路由公开挂载；提交已知凭据后，即可获得关联通配权限角色的有效八小时 Bearer 令牌。该版本没有首次随机密码、must_change_password 状态、改密路由或强制检查，因此在操作者通过带外数据库操作修改密码之前，凭据一直有效。回环服务可能通过所提供威胁模型中的代理或隧道公开，匿名攻击者可以在合法操作者保护全新或恢复实例之前取得初始化身份。

## 验证

1. 确认新数据库确定性地创建活动的 admin/admin123 账号。
2. 确认匿名登录路由已挂载，真实 HTTP 请求接受该凭据。
3. 确认成功签发八小时令牌，没有首次强制改密状态或路由。
4. 确认账号角色权限保存为 ["*"]。
5. 没有证明已有受保护 API 使用该令牌，也没有证明服务无需运维代理就能公开访问；由于没有挂载 authMiddleware，/auth/me 返回 401。

### 验证输出结果

原页面提供验证输出入口；附件内容未包含在已归档的页面正文中。

## 证据注释

1. 每次启动都会确保默认管理员存在，并挂载匿名认证路由。
2. 缺少 admin 记录时，会自动创建使用硬编码密码的活动账号。
3. 账号使用通配权限角色和公开固定凭据，数据库结构没有强制改密状态。
4. 网络登录接受该凭据，并返回管理员 Bearer 令牌。
5. 密码验证成功后立即创建八小时会话，不检查是否需要更换初始密码。

## 攻击路径分析

原始严重级别假设服务公开可达，并且通配权限会话能够立即使用。证据确认固定凭据和令牌签发，却反驳了两个主导假设：index.ts:446–455 只监听本机，且没有外部入口；auth.ts:28–73 定义的授权中间件从未挂载，令牌没有已证明的特权消费者。仍保留该发现而不排除，因为公开登录是真实产品功能，可执行证据证明匿名身份转为 admin 身份，运维转发在威胁模型下也现实可行。按矩阵，低影响与低发生可能性得到低危。

### 路径

本地可达或经转发可达的匿名用户 → 使用已知用户名和密码登录 → 对活动账号执行 bcrypt 验证 → 新数据库中的固定管理员凭据通过验证 → 返回不透明令牌及 admin 用户对象 → 获得八小时 role 1 令牌 → 由于没有挂载的高权限路由使用它进行认证，攻击链在此停止 → 本版本没有已挂载的特权消费者。

没有 admin 记录时，启动会使用文档和启动日志公开的确定性凭据创建 role 1 账号。能够访问登录接口的匿名用户会得到随机八小时令牌和用户对象，验证复现了这一身份转换。最强反向证据是该确切版本的服务绑定回环地址，README 只记载本地访问，且没有任何已提交入口。更关键的是，authMiddleware 和 requireRole 只是定义，未被挂载；/me 也因没有填充 req.user 而返回 401。因此，该版本令牌除了带有 admin 标签的会话之外，没有已证明的能力。答题卡和扫描端点本来就独立允许匿名访问，不是由令牌解锁。这些事实决定性地反对原先的严重接管影响，但并不否认真实认证流程中的固定初始化凭据漏洞。

## 发生可能性

低。凭据利用简单且已复现，新安装自然没有 admin 记录。但仓库服务绑定回环地址，Electron 使用临时回环端口，文档只有本地 URL，没有公共入口。远程利用依赖威胁模型中的运维转发，该确切提交没有相应证据，因此默认部署下发生可能性低。

## 影响程度

低。匿名用户取得 admin 身份已经证明，但直接影响只有内存令牌、除密码外的用户对象披露，以及上次登录状态更新。没有已挂载端点使用该令牌提供受保护数据或管理操作，/me 因缺少中间件也不能成功。将独立匿名答题卡或扫描功能算作令牌后果，会虚构攻击链。因此该提交的实际影响为低。

## 假设条件

- 攻击发生在运行全新或恢复数据库、且其中没有 admin 账号的实例上。
- 远程访问需要运维代理或隧道；该提交绑定回环地址，没有入口或负载均衡配置。
- 所提供威胁模型认为转发现实可行，但该确切版本的资料没有记载或实现它。
- 概念验证因缺少原生 bcrypt 而使用 bcryptjs；初始化、路由、凭据、角色及令牌逻辑仍来自仓库代码。

原文另列前提：

- 应用正在运行。
- 数据库没有 username=admin 的记录。
- 攻击者通过本地或运维转发能够访问服务。
- 默认凭据尚未通过带外方式修改。

## 控制措施

- 使用成本参数为 10 的 bcrypt，而非在数据库中保存明文密码。
- 未知用户及错误密码使用通用错误响应。
- 检查 is_active=1。
- 已有 admin 时不再新建。
- 令牌由 32 个随机字节生成，有效期八小时。
- 生产入口绑定回环地址。
- Electron 使用临时回环端口、上下文隔离、禁用 Node 集成及沙箱。
- 没有限流。
- 没有持久化的强制改密要求。
- 本版本高权限产品路由没有挂载认证或角色中间件。

## 盲点

- 仓库之外可能存在代理，没有清单能够确认或排除。
- 没有受保护的下游令牌消费者；外部组件共享内存令牌的可能性较低，但缺少资料，无法评估。
- 验证使用 API 和哈希行为兼容的 bcryptjs。
- 不知道操作者是否在公开服务之前手工修改数据库凭据。
- 答题卡和扫描广泛缺少认证属于另一个问题，没有归入这条固定凭据攻击路径。

export async function ensureDefaultAdmin(): Promise<void> {
  const db = getDatabase();
  const existing = db.prepare("SELECT id FROM users WHERE username = ?").get("admin");
  if (existing) {
    return;
  }

  const passwordHash = await hashPassword("admin123");
  db.prepare(
    `INSERT INTO users (username, password_hash, name, role_id, is_active)
     VALUES (?, ?, ?, ?, ?)`
  ).run("admin", passwordHash, "系统管理员", 1, 1);
  console.log("[DB] Default admin created: username=admin, password=admin123");
  console.log("[DB] 请登录后立即修改默认密码");
~~~~

    const { identifier, password } = req.body;

      res.status(401).json({ message: result.message });

      user: result.user,

  async login(identifier: string, password: string): Promise<LoginResult> {
    // 查找用户（支持 username 或 student_number 或 email）
    let user = this.userRepo.findByUsername(identifier);

    if (!user && /^\d+$/.test(identifier)) {
      // 纯数字，尝试学号
      user = this.userRepo.findByStudentNumber(identifier);
    }

    if (!user) {
      return { success: false, message: "用户名或密码错误" };
    }

    // 验证密码
    const valid = await verifyPassword(password, user.password_hash);
    if (!valid) {
      return { success: false, message: "用户名或密码错误" };
    }

    // 更新最后登录时间
    this.userRepo.updateLastLogin(user.id);

    // 生成 token
    const token = randomBytes(32).toString("hex");
    const expiresAt = Date.now() + TOKEN_EXPIRE_MS;
    tokenStore.set(token, { userId: user.id, expiresAt });

    // 清除敏感信息
    const { password_hash, ...safeUser } = user;

    return {
      success: true,
      user: safeUser,
      token,
      message: "登录成功"
    };
