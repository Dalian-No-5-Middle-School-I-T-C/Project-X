# 20 无上限分数区间可耗尽整个服务资源

- 原标题：Unbounded score ranges allow server-wide resource exhaustion
- 云端级别：High
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/dd5dd007f3f881919c180f726e2e25f6?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=)
- 关联提交：[31d0800](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/31d080039fce59f6d10699e9bc63a109707b3939)

## 概要

本历史提交把固定五区间改为按未限 SUM(question_scores.max_score) 每十点生成对象并逐区间查询。schema、卡片规范化和判分不限制题目满分；教师设置巨大有限客观题分并判一次已有学生，即可使总览分配一亿对象（fullScore=1000000000），阻塞事件循环或耗尽堆。恶意满分留在数据库，重启后仍可再次触发。客户端收到响应后的过滤不限制服务端工作。

建议校验并限制每题及总满分，拒非有限数，限制固定最大桶数，优先单次聚合 SQL。该项独立于另一相近标题历史提交保留。

## 验证及证据

云端使用真实认证卡片更新路由、真实判分函数及生产持久化 SQL 形状、认证总览接口，在 128 MiB 有界堆中得到 V8 OOM，并证明重启后仍可由保存值重触发。未完整运行原生图像识别，代以现实的成功识别结果。代码证据包括主客观题数字未经幅度／有限性校验、grade.maxScore 入库、无界求和、同步构造对象和每桶 COUNT。

## 攻击路径与分级

普通教师写卡 score=1000000000 → CardRepository → 客观题判分复制为 maxScore → question_scores → SUM → 认证总览同步生成一亿对象和查询 → 共享 Node 退出；数据库中的值使问题跨重启存在。

发生可能性高：正常教师卡片／阅卷／分析权限、可访问考试、正常已有考生，无竞态、秘密提取、原生漏洞或受害者交互。影响程度高：所有共享 API 用户受影响，可重新触发停机。受保护写权限是正常内容入口，不能合理授权服务级拒绝服务。需教师和判分前提，单实例可用性，没有接管、窃密、RCE 或永久成绩破坏，故高危。

## 假设、控制与盲点

生产认证开启，教师有 CARD_WRITE／GRADE_WRITE／GRADE_READ 所需默认能力，卡片与可判考试关联，至少一名成功识别学生入分，再请求总览。实际 cardGate 写门禁要求 GRADE_WRITE。旧普通 teacher_role 为空教师可见全部考试，专门角色仍受 requireExamAccess 限制。

optionalAuth、makeGate、分析 GRADE_READ、考试范围、回环监听和未判分考试提前返回均存在；没有满分幅度／汇总上限和通用并发或限速。文档支持公网 Nginx，实际实例未知。历史代码认证环境开关默认关闭，测试保守开启。

SQLite 动态验证，MariaDB 未跑；原生 OCR 未端到端运行。128 MiB 堆下的确切崩溃时间不能外推默认堆，但一亿对象分配仍有明显放大。外部副本、监管、重启、熔断和内存限制未由仓库基础设施确立。
