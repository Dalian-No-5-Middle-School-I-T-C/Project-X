# 29 缺页可将下一名学生页面归入前一名学生

## 概要

此问题由本次修改引入。此前没有识别出学号的页面会保持无身份状态；本次提交按扫描序号循环分组，并无条件在组内继承身份，把缺页转化为跨学生归属，而不是未识别状态。

mapScanPageToLayout 仅凭物理扫描序号和预期纸张数派生学生组及布局页，不验证学生边界，也不检测缺失、重复或乱序。runOcrOnSession 将没有自身学号的页面赋予计算分组中先前的学生 ID，并给出 0.9 置信度。所选布局没有学号格时，原生程序有意不查找学号，因此错配可以在不触发身份失败的情况下完成。例如，两页单面答题卡依次扫描 A 的第一页、漏掉 A 的第二页、接着扫描 B 的第一页，则 B 页面会被当作组 0 的布局第 2 页；该布局没有学号格，于是继承 A 的身份，识别结果和裁图都保存在 A 名下。学生提交不完整纸包或自动进纸器双张进纸都可能触发，损坏 A 的成绩、丢失 B 的答案，并影响后续批次，却没有明确的页数或身份边界错误。应失败后拒绝继续，或在经过验证的首页身份处重新同步，不能只按序号推导身份；持久化成绩和裁图前，应验证纸包边界或机器可读的页面／学生标识。

## 验证

1. 生产映射只按序号分组及选择布局，缺页可以使映射移位。
2. 移位后的首页被当作没有身份栏的后续页，可以在不触发身份失败的情况下完成。
3. OCR 继承计算分组中的先前 ID，并据此保存识别及裁图。
4. 使用生产服务及数据库专项框架，复现两页单面 A1／B1 情景；原生程序在文档规定的进程边界处由替身代替，相关限制已记录。
5. 下游分组、HTTP 结果合并及主数据库成绩持久化使用错误身份，没有纸包边界拒绝检查。

## 证据注释

1. 所选布局没有学号格时返回 not_present，而不是失败，使物理上不同的首页可以通过非首页布局处理。
2. 会话按已保存身份分组、合并成绩、缓存，并转发到主考试数据库。
3. 新映射只依赖序号和预期张数，没有纸包边界或缺页验证。
4. 没有独立 ID 的页面盲目继承组 ID，以 0.9 置信度持久化。
5. 继承后保存识别分数及裁图，裁图得到可能错误的学号。

## 攻击路径分析

攻击链跨越学生身份，影响答案、裁图、合并成绩，并在条件成立时进入权威记录，因此影响高。漏交或自动进纸器丢页现实可行，学生提交纸包无需软件权限；但依赖布局、扫描顺序、错误布局仍能注册成功，以及问题未被发现，因此发生可能性为中。高影响与中等可能性得到中危。不适用强制排除：影响不限于本人，不是开发问题，也不需要宿主机或扫描特权；虽然已授权操作者执行扫描，恶意输入却来自低权限学生按预期提交的纸张，产生已证明的跨身份及成绩完整性违反。因此保持中危。

### 路径

A 提交缺少预期页面的纸包 → 合法操作流程接收遗漏 → 操作者通过 TWAIN 连续扫描 A 后扫描 B → 驱动序号成为唯一纸包位置依据 → B 的实体页映射到组 0、A 的后续页布局 → 原生程序没有学号格可读，not_present 不算失败 → 允许组内身份继承 → 继承 A，置信度 0.9，标记 done → ID 传入识别及裁图保存 → B 的答案归到 A 名下 → 已保存 student_id 决定分组及用户查找 → 可能写入 A 的关联考试成绩。

学生可以在连续扫描前从多页纸包中漏交一张。服务只按驱动序号计算分组和布局；当 B 首页占据 A 后续页槽位，且后续页没有学号栏时，原生程序有意返回 not_present。服务继承 A 的身份，设置 0.9 置信度和 done，将 B 答案及裁图保存到 A 名下，分组和后续成绩又信任该 ID。执行框架覆盖生产映射、扫描存储、判分、裁图、分组、结果端点及主成绩保存，将包括 B 实体页在内的两条记录都保存为 11111。最强技术反向证据是没有运行 Windows 识别器，而是在文档边界使用确定性程序替代；这降低确信程度，但不否定问题，因为确切 C++ 分支在没有学号格时返回 not_present，生成布局的注册标记也相同。另一限制是结果端点使用旧文件式答题卡读取；没有副本时，这条主数据库转发路径会返回 404。不过，错误扫描身份、识别、置信度、答案和裁图更早发生，仍然可达。认证、回环监听及禁用扫描开关保护操作 API，却不验证已授权扫描接收的恶意纸包。

## 发生可能性

中。学生可能提交不完整答卷，自动进纸器也可能漏页，不需要应用访问。故意利用需要多页答题卡、仅首页有身份栏、合适扫描顺序、错误布局仍能注册，以及操作者未发现。回环、认证和服务包默认设置不防止恶意纸张，但物理及配置依赖使可能性不达到高。集成框架演示全部编排及持久化入口，识别替身仍留下有限的原生图像可行性验证缺口。

## 影响程度

高。可能静默地将一名学生的答案、手写裁图及成绩归给另一名学生。身份控制合并判分，能够更新关联考试的两类权威成绩。一次缺页还可能使后续纸包持续移位。即使能够发现后重扫，部分安装中的旧答题卡依赖也会阻断一条主数据库路径，仍属于高完整性影响。

## 假设条件

- 每名学生有多页或多张答题卡，首页有学号，至少一张后续页没有。
- A 首页成功扫描，A 的下一张预期纸张缺失，B 首页在同一连续批次中紧随其后。
- 标记和答案几何布局允许 B 首页按后续页处理；验证中的两页标记相同。
- 教师或操作者正常扫描，在 OCR 或合并之前没有手工发现问题。
- 主数据库路径另外需要可读取答题卡、关联未关闭考试，以及继承学号对应用户；更早的错误扫描和裁图不需要所有下游条件。

原文另列前提：

- 多页答题卡的后续页有答案格，没有学号格。
- A 首页有效识别 ID。
- A 后续纸张因故意漏交、乱序或自动进纸器原因缺失。
- B 首页紧接缺失位置。
- 错配实体页在后续页布局下通过标记及识别。
- 操作者完成正常扫描和合并。

## 控制措施

- 启用认证时，扫描要求 scanner 范围密钥或 GRADE_WRITE 用户。
- 默认绑定回环地址。
- Ubuntu 纯服务包默认 PROJECTX_ENABLE_SCANNER=0。
- 显式禁用后，/api/scanner 返回 404。
- 原生程序要求注册标记角色；如果所选页实际有学号格却无法读取，会失败。
- 超出配置页数的页面被视为未使用面。
- OCR 异常标记失败，没有分配 ID 时显示待复核。
- 这些措施不能检测纸包缺页；继承 ID 得到 0.9 置信度，界面将其视为 done。

## 盲点

- 环境没有 Wine 或 Linux OpenCV 开发文件，没有运行 Windows PE，而是在 ANSWER_CARD_RECOGNIZER_EXE 边界替换为确定性程序。
- 没有真实 TWAIN 端到端验证，证明某个具体实体首页可通过后续页识别，尽管 C++ 分支及相同标记支持这一点。
- 主数据库验证提供旧文件式答题卡，因为结果端点调用 readCard；没有副本的仓储安装可能在合并转发前返回 404。
- 实际模板只有首页有学号栏的频率未知，现有证据仅为验证所用的生产生成布局。
- 手工清点页数、视觉分包、扫描核对或强制重扫流程未知。
- 文档存在可选 Cloudflare，但具体入口、扫描开关及认证状态未知；物理输入路径不需要这些事实成立。

export function mapScanPageToLayout(
  physicalPage: number,
  side: "front" | "back",
  layoutPageCount: number,
  sided: "single" | "double"
): ScanPageMapping {
  const sidesPerSheet = sided === "single" ? 1 : 2;
  const sheetsPerStudent = Math.max(1, Math.ceil(layoutPageCount / sidesPerSheet));
  const sheetIndex = Math.max(0, physicalPage - 1);
  const groupIndex = Math.floor(sheetIndex / sheetsPerStudent);
  const sheetWithinGroup = sheetIndex % sheetsPerStudent;
  const sideOffset = sidesPerSheet === 1 || side === "front" ? 1 : 2;
  const layoutPage = sheetWithinGroup * sidesPerSheet + sideOffset;
  return { groupIndex, layoutPage, unusedSide: layoutPage > layoutPageCount };
~~~~
