# 29 缺页可将下一名学生页面归入前一名学生

- 原标题：Missing sheets can bind another student's page to the prior student
- 云端级别：Medium
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/e4876018b58c819183dd38df7c718cf8?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=&page=2)
- 关联提交：[62ed9dc](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/62ed9dc221bb1d5a69fb1a93334c489b4e089882)

## 概要

此前未识别到学号的页保持未知，本提交新增按物理扫描序号推导学生分组／布局页，再无条件在组内继承学号。mapScanPageToLayout 不确认真实学生边界，也不检测缺失、重复或乱序；runOcrOnSession 把无本页学号的页面归给计算分组中已有学号，置信度置 0.9。

两页单面卡示例：A1 成功，A2 缺失，下一页 B1 被当作第 0 组布局第 2 页。若第 2 页没有学号框，原生识别按设计返回 not_present 而不失败，B1 于是继承 A 学号，识别结果与答案裁图写到 A。学生故意少交页或 ADF 双张漏扫都可触发，可能影响后续整批。建议缺页关闭式失败，或在验证过的首页身份处重新同步，入分／裁图前验证包边界或机器可读页码／学生标识。

## 验证与证据

生产映射、扫描存储、判分、裁图、分组、结果 HTTP 及主库分数持久化测试中，A1/B1 两记录都存为 11111。原生进程边界使用确定性替身，未运行 Windows PE；C++ 明确在无学号框布局返回 not_present，生成的两页定位标记相同，支持但不替代真实图像验证。

主库结果接口仍调用旧文件式 readCard，测试提供了该副本；没有副本的仓储式安装可能 404，阻止这一条后续主库转发。但更早错误扫描身份、答案、0.9 置信度和裁图落库不依赖该副本。

## 攻击路径与分级

学生 A 缺页 → 合法操作员连续扫描 A、B → 仅用序号选错布局 → 无学号区域返回 not_present → 继承 A／标记 done → B 答案及裁图归 A → 按保存身份合并，并在满足条件时写关联考试成绩。

影响程度高：跨学生身份和成绩完整性，可波及后续批次。发生可能性中：需多页卡、后页无学号、正确顺序、错页仍能定位及操作员未察觉。攻击者不需主机或扫描权限，输入来自学生正常交卷，因此不能因操作员有权限而排除；高影响×中可能性为中危。

## 假设、控制与盲点

A 首页识别成功、下一预期页缺失、B 首页紧随；错误布局可定位并识别；操作员继续。主考试入分另需可读卡片、关联未关闭考试、继承学号对应用户；错误扫描及裁图无需全部这些条件。

认证开启时扫描需 scanner 密钥或 GRADE_WRITE；回环监听，Ubuntu 服务端默认禁原生扫描，显式禁用时 404；原生检查定位标记，有学号区域但识别失败会报错；超布局页当空闲面，异常标 failed、无学号待复核。这些不识别缺页，继承成功则显示 done。

未用真实 TWAIN 或 Windows 识别器；Linux 缺 Wine/OpenCV 开发环境。未知真实模板首页唯一学号普及度、人工点页、分包、核对或必重扫制度。网络入口不构成物理输入链必需条件。
