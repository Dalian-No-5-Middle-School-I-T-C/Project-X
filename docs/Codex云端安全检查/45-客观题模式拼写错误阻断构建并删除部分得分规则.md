# 45 客观题模式拼写错误阻断构建并删除部分得分规则

## 概要

ObjectiveMode 的正确值为 indefinite，提交在标题映射和题型切换判断中误用 indeterminate。类型检查报 TS2367，正常 npm run build 因先执行 tsc --noEmit 而失败；若绕过类型检查，选择合法的不定项模式会删除全部题目的 scoringRule，并使用通用客观题标题。

应将两处拼写改为 indefinite，删除规则的条件应保留 multiple 与 indefinite 模式。

## 验证与路径

已确认拼写由该提交引入并复现编译错误。动态复现题目规则被删除，追踪 1.2 秒自动保存 PUT /api/cards/:cardId → CardRepository 将 scoring_rule_json 写为 NULL → 判分/重算使用零分或旧回退规则；配置的部分分由 1 变 0，修正拼写的对照仍为 1。

## 等级判断

条件性数据完整性影响中等，安全利用可能性低，初步低危；最终按受保护写入且无权限增益排除为信息提示。现实触发者需 grade:write，本来就可修改或删除同一评分规则。默认关闭认证的兼容模式不是所假定加固生产环境，且无需此拼写错误也能任意改卡。

这是应修复的发布阻断及判分正确性缺陷。普通构建会在发布前阻断；运行影响需开发转译、预构建或其他绕过类型检查的路径，卡已有题级部分得分规则，后续保存并判分，且没有旧块级 multipleScoring 完全掩盖。

## 防护与盲点

认证开启时非 GET 答题卡请求检查身份与 grade:write，学生无写权限，设计界面受模式与 CARD_READ 控制。归一化不会重建被删规则；旧规则可能缓解部分卡的后果。服务监听回环地址，远程依赖代理。

复现执行了等价的小段 React 修改逻辑，未驱动完整浏览器与实时 HTTP/数据库集成；没有证明实际生产包含此无法正常构建的提交，未确定实际受影响规模或入口配置。不涉及秘密、代码执行或身份接管。
