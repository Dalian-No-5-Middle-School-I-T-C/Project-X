# 03 扫描端载荷可注入任意主观题成绩

## 概要

**由本次变更引入。** 在这一变更范围之前，远程扫描端端点只上传图像，并不会接收客户端识别结果并将其作为最终成绩持久化。本提交新增识别结果接收和自动持久化，却没有依据权威定义验证主观题身份或满分。

本提交在远程扫描上传 API 中加入客户端提供的识别数据。Zod schema 只要求主观题分数及满分为有限非负数，没有要求 questionId 或 questionNumber 必须存在于所选答题卡。载荷原样存储，之后交给 gradeSessionStudentResults。客观题虽然根据权威卡片定义重新判分，但 gradeSubjectiveRecognition 遇到未知 questionId 时会回退到攻击者提供的 maxScore，并将提交分数计入学生总分。所得总分及虚构题目行随后写入 student_scores 和 question_scores。因此，持有扫描 API 密钥的攻击者可以针对关联唯一活动考试的答题卡创建会话，上传任意有效图像，并附带未知主观题、将 score 与 maxScore 设为任意数值的载荷，最后完成会话来覆盖在册学生成绩。具有 GRADE_WRITE 和足够考试范围的教师也能到达同一问题。服务端应拒绝卡片中不存在的主观题条目，仅从卡片派生题号与满分，强制唯一性及权威题目覆盖，并绝不在这一远程接收路径中以客户端满分作为回退值。

## 验证

1. 远程识别输入由攻击者控制，接收时没有将主观题 ID、题号或满分绑定到所选答题卡。
2. 未知主观题会使用客户端提供的 score/maxScore，并贡献到汇总判分总分。
3. 会话完成会为符合条件的活动考试及在册学生写入伪造总分与虚构题目行。
4. 在所声称的扫描密钥前提下，认证、考试解析、名单、页面完整性以及重复/会话控制均不能阻断此路径。
5. 通过真实 HTTP 接口进行的针对性复现展示了最终数据库影响。

## 证据注释

1. 已存储客户端识别数据被解析并交给判分逻辑，没有权威主观题覆盖检查。
2. 新识别 schema 接受任意主观题 ID、题号、分数及客户端控制的满分，不对照答题卡验证。
3. 不可信主观题识别数组直接序列化进数据库，供后续判分。
4. 伪造主观题分数进入持久化总分，虚构主观题行被写入 question_scores。
5. 对未知主观题 ID，判分信任识别载荷的 maxScore，并以攻击者提供的上限限制攻击者提供的分数。

## 攻击路径分析

影响为高，因为攻击者任意定义的总分和虚构题目行被持久化为另一用户的权威成绩。对相关范围内攻击者，可能性为高：文档中的扫描端—服务端模式支持远程调用，只需预期的扫描机器凭据，复杂度低，且已端到端复现。不适用强制排除规则：影响不限于自身；前提现实；路径并非仅限开发者、物理访问或主机操作者；权限差异正是核心问题——原本仅允许提交 OCR 结果的扫描身份可以重新定义权威题目身份和满分，而非受答题卡约束。最有力的反向证据包括默认关闭功能、回环监听、范围化认证、完整页面检查、考试解析和名单限制，它们降低了受影响部署比例，但不能阻断预期远程扫描生产流程中已复现的路径。按矩阵，高影响与高可能性得到高危而非严重，因为利用需要有效的限定范围凭据，已证明的是数据完整性破坏，而非整个实例失陷或代码执行。

### 路径

恶意或被攻陷的扫描 API 密钥客户端 → 使用 X-Api-Key 认证并提供有效图像及虚构主观题 score/maxScore → 远程扫描会话与 multipart 页面上传 API → schema 检查数值形状而不检查权威卡片成员关系，载荷原样序列化 → twain_recognition_results 保存客户端识别 JSON → 解析已存 JSON 并传入判分 → gradeSessionStudentResults / gradeSubjectiveRecognition → 未知题目使用攻击者 maxScore 并计入总分 → 扫描结果持久化事务 → upsert 伪造总分和题目行 → student_scores、question_scores 产生伪造成绩。

攻击过程：控制已配置或被窃取扫描 API 密钥的攻击者，使用文档远程扫描 API，为关联一场活动考试的答题卡创建会话。其上传有效图像，同时提交例如 questionId=invented-question-id、questionNumber=FORGED-999、score=777777、maxScore=777777 的虚构主观题，再完成会话。请求 schema 只检查基本结构与有限非负数，原样保存主观题数组，随后传给判分。由于 gradeSubjectiveRecognition 对未知题目 ID 回退使用提交的 maxScore，虚构分数计入汇总并写入两张成绩表。可执行 HTTP PoC 观察到完成接口返回 200，总分 777777 被保存，而权威答题卡仅包含另一道满分 10 分的题。反向证据相当充分：远程 API 默认关闭；进程仅直接监听回环；需要 scanner/full 密钥或 GRADE_WRITE 用户；密钥有范围检查，通常哈希存储；完成时检查令牌、图像、页面覆盖、唯一考试解析、学生存在及名单归属。但这些控制不足以否定漏洞，因为远程扫描是明确记录的生产流程，仓库注释预期存在代理/隧道入口，PoC 也满足了认证、会话、图像、考试与名单控制。扫描身份虽然原本就被信任提交 OCR 成绩，但重新定义考试题目 schema 与满分是已证明的权限和信任边界变化。无需依赖另一个教师路径即可确认漏洞。

## 发生可能性

**高。** 启用文档中的扫描流程并控制 scanner/full 密钥后，利用为远程且复杂度低。不需竞态、受害者交互、解析器利用或推测的第二漏洞；可执行 PoC 穿过真实 HTTP 路由和持久化层。可选功能、直接回环监听、有效机器凭据以及合法考试/学生/页面上下文限制了可能性。不过扫描密钥是远程扫描工作站预期的生产身份，其余前提均为正常业务状态，而非高度不现实条件。**攻击向量：远程网络。**

## 影响程度

**高。** 攻击者可将既有在册学生的权威总分覆盖为任意有限非负值，并引入虚构题目记录。这些记录供学业成绩、排名重算及下游分析使用。影响不限于本人，可对其他可达学生和活动考试重复执行。这严重破坏威胁模型主要资产的完整性，但不会直接提供代码执行、机密性损失或管理员接管。

## 假设条件

- 受影响部署设置 PROJECTX_ENABLE_SCANNER_CLIENT_API=1，启用文档中的远程扫描流程；仓库不证明所有部署均启用这一可选模式。
- 攻击者控制合法配置或被攻陷的 scanner/full API 密钥；报告未声称存在独立密钥窃取机制。
- 所选卡片恰好解析到一个合格活动考试，提交学号对应既有学生，启用名单约束时该学生在考试名单内。
- 未动态执行另一个已认证教师路径，因此可达性与分级主要依据扫描 API 密钥路径。

原文另列的利用前提：

- 通过 PROJECTX_ENABLE_SCANNER_CLIENT_API=1 启用远程扫描客户端 API。
- 有效 scanner/full API 密钥，或具备 GRADE_WRITE 且具有足够整卡考试范围的认证用户。
- 答题卡只关联一个符合条件的活动考试。
- 目标学生存在，且在名单已知时属于考试参与者。
- 有效图像、会话上传令牌、完整页面布局，以及每个上传页面的识别数据。

## 控制措施

- 未启用 PROJECTX_ENABLE_SCANNER_CLIENT_API 时，远程扫描路由关闭。
- Node 直接监听 127.0.0.1，远程访问需运维人员提供代理、隧道或等效转发。
- dualAuth 要求有效 scanner/full API 密钥，或具备 GRADE_WRITE 的认证用户。
- API 密钥检查活动状态和 scanner/full 范围，新签发密钥以 SHA-256 哈希保存。
- 教师认证写入要求考试访问权及整卡判分范围。
- 会话上传令牌必须对应所选会话中的记录。
- 上传文件必须通过图像魔数检查。
- 完成要求所有预期页面、识别数据及可唯一解析的考试。
- 持久化要求学生存在，并在名单已知时强制名单归属。
- 总分及题目写入在事务中执行。
- 上述控制均未验证主观题身份、权威题号、权威满分、唯一性或覆盖情况。

## 盲点

- 没有部署清单或反向代理配置证明某个具体实例是否经局域网、公开隧道或互联网域名暴露 5174。
- 仓库不能证明某生产部署是否启用 PROJECTX_ENABLE_SCANNER_CLIENT_API。
- 可执行 PoC 使用 SQLite；脆弱判分逻辑与数据库无关，但未另行执行 MariaDB 持久化。
- 未动态复现已认证 GRADE_WRITE 教师路径。
- 未声称存在独立密钥获取或工作站攻陷链。
- 已演示的是每会话一名学生的持久化；大规模利用需要针对更多学生或考试重复正常扫描流程。
