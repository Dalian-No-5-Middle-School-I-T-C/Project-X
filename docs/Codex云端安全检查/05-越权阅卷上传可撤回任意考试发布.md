## 概要

**由本次变更引入。** 判分端点缺少考试对象授权的问题早于这一变更，但本提交在行验证之前新增自动 score_published=0 状态转换。因此，即使越权上传完全失败或为空，也会新增一次未授权发布状态修改，而且恢复考试此前状态时仍保留这一修改。

POST /api/cards/:cardId/grading 只受通用答题卡门禁保护，POST 请求需 GRADE_WRITE。它从 multipart 请求体读取目标考试 ID，直接交给 persistGradingResults，没有调用 requireExamAccess、检查 getVisibleExamIds，或确认考试关联 URL 中的 cardId。修改后的持久化逻辑在判断任何上传行是否识别成功或被接受之前，先将所选考试设为 grading，并把 score_published 从 1 改为 0。这使利用尤其简单：对于已知单面卡，攻击者上传一个带 B 面后缀的任意文件就可令 gradingFiles 为空，也可以上传畸形文件产生失败识别行。批次随后状态为 error，并恢复此前考试状态，却不恢复 score_published，受害考试因此保持未发布。教师默认具有 GRADE_WRITE，考试 ID 又是数字，学科教师或班主任因此能反复撤回超出其班级、学科或考试范围的成绩。审计会记录操作者，授权教师也能重新发布，但两者都不能阻止规模化干扰成绩发布。路由应依据请求者考试可见性授权请求体 examId，验证 exam.card_id 与 URL cardId 相等，在至少一条已授权行将持久化前不改变发布状态，失败回滚也必须恢复发布状态。

1. 验证普通认证教师可通过通用 GRADE_WRITE 答题卡门禁访问判分端点。
2. 确认提交的考试不在攻击者正常 requireExamAccess 范围内，也不关联 URL 中的卡片。

5. 展示持久且用户可见的影响：零行成绩被保存，写入归属于攻击者的审计事件，学生失去对此前已发布成绩的访问。

## 证据注释

1. 持久化加载任意数字考试 ID，将其改为 grading，并在验证是否能保存任何判分行之前新增撤回已发布成绩的行为。
2. 失败或空批次恢复此前考试状态，却不恢复 score_published，因此越权撤回持续存在。
3. /api/cards POST 门禁仅检查角色级 GRADE_WRITE，不确立对随后 multipart 请求体中考试的访问权。
4. 判分路由接收文件并直接从 req.body 取 examId，不检查考试可见性或与 cardId 的关联。
5. 攻击者控制的请求体 examId 直接交给 persistGradingResults。
6. 教师账号默认授予 GRADE_WRITE，因此普通认证教师即可到达，不只管理员。

## 攻击路径分析

不适用强制排除：影响不限于本人，前提现实，攻击者是越过对象范围边界的低权限教师，而非行使预期权力的管理员。仓库控制要求认证及 GRADE_WRITE，但权限扩大恰恰在于这些角色级权限转化为对 requireExamAccess 明确拒绝的考试的修改权。影响为高，因为可以跨无关考试撤回发布，且已演示学生失去访问。可能性为高，因为正常网络端点接受简单请求体 ID，仅文件名即可触发，无需识别成功或推测攻击链。按矩阵，高影响乘高可能性为高危而非严重；没有破坏或泄露分数，操作可审计，授权人员能恢复发布，因此不满足严重条件。

### 路径

具有默认 GRADE_WRITE 的认证教师 → multipart 请求通过通用权限门禁 → POST /api/cards/:cardId/grading → 提供与 cardId 无关的自选 examId → 请求体 examId 未经考试范围或卡片关联授权即接受 → 单面卡丢弃 B 后缀文件 → 得到 rows=[] → 空行仍传入持久化 → persistGradingResults 清除 exams.score_published → 错误回滚只恢复 status → 受害学生无法查看考试结果。

现实攻击者可以是合法学科教师，其具有默认 GRADE_WRITE，但所分配学科和班级不包含受害考试。教师使用任意可访问单面卡调用该端点，将受害考试自增 ID 放入请求体，并上传带 B 面后缀的任意文件。通用门禁只凭 GRADE_WRITE 放行。处理函数滤掉 B 面文件，得到空 rows，将未经验证的 examId 交给持久化；后者先清除发布状态再检查行，错误路径仅恢复 exam.status。所提供的可执行验证确认同一教师访问正常考试端点返回 403，随后判分返回 422，但仍把无关考试从已发布改成未发布，并使其从受害学生成绩视图消失。审计记录操作者，授权教师可重发，这限制隐蔽性与永久性，但不能阻止教师反复跨范围干扰发布。既有安全测试只对预期授权行为提供反向证据：它直接调用持久化，断言空行重判会撤回发布，却没有测试路由级考试授权或卡片关联。

## 发生可能性

**高。** 利用需要合法教师账号，但教师默认拥有 GRADE_WRITE，正常判分就使用这一 multipart 端点。攻击者控制 examId 与文件名，不需要原生识别成功，一个很小的 B 后缀上传即可触发。可执行 HTTP 验证演示了完整路径，而正常考试访问为 403。公网入口依部署而定，但产品设计用于教师经学校服务或代理访问，无需本地主机或运维权限。**攻击向量：远程网络。**

## 影响程度

**高。** 攻击者可跨明确班级/学科/考试授权边界，持久修改无关考试发布状态。学生立即失去结果访问。自增 ID 和没有路由限流使反复干扰多场已发布考试具有现实性。原始成绩未改，操作有审计，授权教师可重新发布，因此不达严重完整性失陷门槛；但学校运行期间规模化干扰正式成绩发布，对可用性和业务流程完整性影响重大。

## 假设条件

- 部署按文档中的学校服务、反向代理或隧道模式供教师浏览器访问；仓库不证明某个实际公网入口。
- 攻击者已有合法认证教师账号及默认 GRADE_WRITE，不假设凭据窃取或管理员权限。
- 至少一场受害考试已发布，攻击者知道或能猜测自增数字 ID。
- 教师可使用某个单面卡 ID；卡片只有角色级权限保护，并有意在实例内共享。
- 可执行验证使用 SQLite。授权缺失、发布更新、审计写入及不完整回滚均位于共享应用代码，预计也影响 MariaDB。

原文另列的利用前提：

- 有 GRADE_WRITE 的有效教师会话。
- 已发布、且超出教师班级/学科/考试范围的受害考试。
- 知道或猜到考试数字 ID。
- 可访问任意既有单面卡 ID。
- multipart 上传至少含一个文件名匹配 B 面后缀模式的文件。

## 控制措施

- 认证默认开启，makeGate 拒绝未认证请求。
- 路由要求角色级 GRADE_WRITE，默认权限映射下排除学生。
- 正常考试路由的 requireExamAccess 和 getVisibleExamIds 提供强考试范围控制，但此路由遗漏。
- Multer 限制每个识别上传文件为 20 MiB。
- 撤回发布写入 exam_publish_events，含操作者 ID 与原因。
- 授权教师发现后可以重新发布。
- 参与者检查阻止名单外成绩行保存，但它发生在撤回发布之后。
- 没有路由级限流阻止反复撤回尝试。
- CSP、CORS 与 React 转义不能缓解有效认证的直接 API 请求。

## 盲点

- 没有仓库部署清单证明具体实例是公网、仅局域网，还是经某代理/Cloudflare 隧道暴露。
- 可执行验证覆盖 SQLite，而非实时 MariaDB，尽管应用流程和 SQL 操作共享。
- 仓库无法确认生产教师获知每个正式考试 ID 的难易程度；ID 自增可猜，但猜错可能留下运行证据。
- 仓库外告警可能发现重复审计事件，但不能阻止未授权状态变化。
- 分析不声称通过不匹配识别数据破坏分数；已证明影响为零接受行情况下未授权撤回发布。
