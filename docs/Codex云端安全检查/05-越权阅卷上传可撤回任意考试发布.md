# 05 越权阅卷上传可撤回任意考试发布

- 原标题：Out-of-scope grading upload can unpublish any exam
- 云端级别：High
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/2e411e2dc828819181445528bc2dadce?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=)
- 关联提交：[336964f](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/336964f1e839dfd897ef2faaf16217e397c36777)

## 概要

缺少考试对象授权的问题早已存在，本提交新增的是：在验证任何成绩行之前自动将 score_published 置 0。于是即使越权上传完全失败或为空，也会撤回发布；错误恢复只恢复考试状态，不恢复发布标志。

POST /api/cards/:cardId/grading 仅通过通用 GRADE_WRITE 门禁，直接把 multipart 的 examId 传给 persistGradingResults，未调用 requireExamAccess、getVisibleExamIds，也未确认考试关联 URL 中的 cardId。持默认权限的教师可选一张单面卡，上传名称带 B 面后缀的任意文件，使过滤后的 gradingFiles 为空；或上传识别失败文件。持久化先将考试置为 grading 并撤回发布，再发现无可接受行。批次最终 error，考试状态恢复，发布仍被撤回。

原报告建议先检查请求者对 body examId 的可见／写入范围，确认 exam.card_id 与 URL 一致，至少有授权成绩将要入库后再改变发布，失败时同时恢复发布状态。

## 验证及证据

真实认证 HTTP 验证中，同一普通教师访问受害考试的正常端点得到 403，却可通过无关单面卡及 B 面后缀文件得到阅卷 422，同时使已发布考试变为未发布。没有一行成绩入库，仍记录了带攻击者身份的审计事件，学生成绩视图中的考试随之消失。

证据链包括：默认教师拥有 GRADE_WRITE；卡片 POST 仅检查角色功能权限；路由未校验考试范围和卡片关联；持久化接受任意数值 examId，在行校验前更改状态／发布标志；错误路径仅恢复 status。已有测试直接调用持久化并断言空行重阅卷会撤回发布，仅证明授权场景预期行为，没有覆盖入口授权。

## 攻击路径与分级

普通教师会话 → 通用阅卷上传权限 → body 中填写无关考试 ID → 单面卡过滤 B 面文件，rows=[] → persistGradingResults 撤回发布 → 错误回滚遗漏 score_published → 学生不能查看成绩。

发生可能性高：仅需正常教师账号、可用单面卡、可知或可猜的递增考试 ID 和一个小文件，不依赖识别成功、竞态或原生程序。影响程度高：跨班级／学科／考试边界持续干扰多个考试发布，且无路由限流。影响不限于自身，普通教师越过对象范围是问题本身，不属于管理员执行授权操作。审计可追踪且合法教师能重发，底层分数未改、未披露，故为高危而非严重。

## 假设条件及已有控制

学校 Web 服务对教师可达，认证默认启用；攻击者有默认 GRADE_WRITE；目标考试已发布且超出其范围；能够获取单面卡 ID。卡片在同一实例内有意共享。云端使用 SQLite，共享应用代码及 SQL 预期也影响 MariaDB。

makeGate 拒绝匿名，默认学生无 GRADE_WRITE；正常考试路由有有效 requireExamAccess／getVisibleExamIds，此处遗漏。Multer 单文件上限 20 MiB；exam_publish_events 记录原因和操作者；合法人员可重发；名册校验阻止非考生分数，但发生在撤回之后。CSP、CORS、React 转义不能防止合法认证的直接 API 请求；没有阻止重复撤回的专属限流。

## 盲点

未确认具体公网／局域网入口，未在真实 MariaDB 重跑；未知教师能实际获知多少考试 ID，猜错也可能留下痕迹。外部告警可能发现重复审计，但不能阻止变更。已证明的影响只是不接受任何成绩行时仍越权撤回发布，不主张通过错配识别数据改分。
