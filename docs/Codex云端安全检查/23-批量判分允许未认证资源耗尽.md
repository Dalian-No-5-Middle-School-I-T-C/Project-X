## 概要

此问题由本次修改引入。新的批量客观题判分将原单文件允许量乘以 200，没有总字节、认证、频率、并发或临时文件清理控制。上传中间件在答题卡验证之前运行，即使答题卡不存在，也会留下攻击者文件。

新增 POST /api/cards/:cardId/grading/objective 使用 recognitionUpload.array("files",200)。共享 Multer 单文件上限为 20 MiB，没有合理的总请求限制，一次可以写入约 4 GiB。全部 multipart 处理并落盘后才检查答题卡，因此匿名攻击者使用任意 cardId 即可，无需发现有效答题卡。成功、识别失败、无效答题卡或客户端断开时，路由均没有清理上传。有效答题卡还会逐文件串行运行原生识别器，每进程超时 30 秒，一批最多约 100 分钟。并发批次可以耗尽磁盘、CPU、进程槽和请求容量，持续干扰扫描判分。旧单文件识别已有相关保留弱点，但本次提交新增独立的 200 文件放大路径。

## 验证

1. 路由无需认证即可访问，执行顺序使 multipart 在答题卡查询之前保存。
2. 生产 Multer 最多接收 200 个、每个 20 MiB 的磁盘文件，没有总字节控制。
3. 通过 HTTP 证明，无效答题卡也会保存可控文件，然后返回 404。
4. 确认已经完成的上传在无效答题卡及相关成功／失败路径中不被清理；另外区分 Multer 在上传阶段中断时的清理。
5. 追踪有效答题卡到串行原生识别，确认 30 秒进程超时及缺少路由并发控制。

## 证据注释

3. 每个文件交给原生识别，成功或失败都不删除，没有批量或并发配额。

## 攻击路径分析

对于范围内代理或隧道部署，事实评估为高影响、高发生可能性。矩阵得到高危，没有独立满足严重条件：影响为单服务或宿主机文件系统可用性，没有远程代码执行、管理员接管、敏感数据提取或隐蔽改分。因此保留高危。评级依赖所提供远程部署；严格本地 Electron 会大幅降低可能性，可能因仅限本机而被排除，但该反例不覆盖所给生产模型。

### 路径

匿名远程用户 → 不带凭据的 multipart → 运维代理或 Cloudflare → 回环 Express → 批量客观题判分 POST → 上传先于答题卡查询 → Multer 将最多 200×20 MiB 写入磁盘 → 没有总字节约束 → 持久识别目录 → 404、成功或识别错误后仍保留 → 磁盘、进程、CPU 和请求容量耗尽。

这是真实产品批量判分路径中的资源漏洞，而非纯正确性问题。React 正常提交多张图片，确立了运行用途。路由没有认证，在 readCard 之前安装数组上传中间件；磁盘单文件上限 20 MiB，没有总量限制，一次完成请求接近 4 GiB。HTTP 验证在无凭据情况下向不存在答题卡发送两个 11 MiB 文件，得到应用 404，关闭服务后文件仍在；另一请求证明 200 个文件部分被接受并保留。有效答题卡验证显示串行识别，以及 HTTP 200 后文件留存。最强反向证据是单文件及单请求数量有限、单批串行而非并行，以及 Multer 解析期间中断会删除部分文件。但这些不覆盖已完成请求、重复请求或已经交给处理函数的上传。最强暴露反向证据是 127.0.0.1 监听及本地桌面文档。因此，远程可报告性依赖威胁模型中的代理或隧道；在这种部署下，持续磁盘消耗不需要凭据、有效答题卡、竞争条件或特权前提。

## 发生可能性

高。在所给公网代理或隧道下，普通匿名 multipart 即可触发。已证明的磁盘路径不需要有效答题卡，真实路由会在无凭据情况下保留完成文件。没有限流、配额或并发控制，重复操作简单。主要不确定性来自部署：仓库绑定回环地址，并有本地桌面模式；永不代理的实例可能性低或不可报告。攻击向量为远程网络。

## 影响程度

高。反复完成请求可以持续存储数据，直到服务或宿主机文件系统耗尽，使设计、扫描和判分不可用。单请求不计 multipart 开销可接近 3.91 GiB。有效答题卡最多触发 200 次串行 30 秒调用，约 100 分钟，并消耗 CPU 和进程资源。已证明的是可用性问题，没有泄露、改分、代码执行或整个设备群影响证据。

## 假设条件

- 按所给生产模型，通过代理或 Cloudflare 发布回环服务。
- 仓库之外的代理没有新增认证、总请求限制、配额或限流。
- Node 具有正常工作所需的 ANSWER_CARD_DATA_DIR 写入权限，该目录所在存储容量有限。

原文另列前提：

- 经部署代理或隧道能够通过 HTTP 访问。
- 能发送一个或多个完整 multipart 请求。
- 只有可选的原生处理放大需要有效答题卡；持久磁盘消耗使用任意不存在 ID 即可。

## 控制措施

- 直接监听回环地址，远程访问需要代理或隧道。
- 单个识别文件限制为 20 MiB。
- files 字段每请求最多 200 个文件。
- 构造上传目录前，safeId 移除字母、数字、下划线和连字符之外的字符。
- Multer 2.0.2 在 multipart 仍处于解析阶段时中断，会清理部分上传。
- 原生调用使用参数数组而非 shell，每进程 30 秒超时。
- 单请求内文件串行处理，最多一个活动识别子进程。
- 没有认证、授权、总字节限制、完成上传清理、频率限制、存储配额或全局识别并发控制。

## 盲点

- 该提交没有代理、Cloudflare、容器、Kubernetes 或负载均衡清单，无法确认实际公开暴露及外部体积／频率限制。
- 生产文件系统容量、配额、分区及影响范围未知。
- Linux 没有 Windows 原生识别器；100 分钟由已确认的串行逻辑和 30 秒超时源码推导，没有完整执行 200 进程压力测试。
- 已验证 Multer 上传中断清理作为反向证据；multipart 完成后才断开的留存，没有单独压力测试。
- 并发批次、宿主机进程限制、代理超时及仓库之外的监控或自动清理未知。

        const cardId = safeId(paramValue(req.params.cardId));
        const dir = path.join(dataDir, "recognition", "uploads", cardId);
        await mkdir(dir, { recursive: true });
        cb(null, dir);
      },
      filename: (_req, file, cb) => {
        const ext = path.extname(file.originalname).toLowerCase() || ".png";
        const name = `scan_${Date.now()}_${Math.random().toString(36).slice(2, 8)}${ext}`;
        cb(null, name);
      }
    }),

  });
