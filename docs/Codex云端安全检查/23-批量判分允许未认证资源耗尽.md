# 23 批量判分允许未认证资源耗尽

- 原标题：Batch grading enables unauthenticated resource exhaustion
- 云端级别：High
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/8551b3c86768819195fc15f6bff0a1bc?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=&page=2)
- 关联提交：[4f92791](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/4f927912a33e88e1f0baa82e10eef8647faa3649)

## 概要

本提交新增 POST /api/cards/:cardId/grading/objective，recognitionUpload.array("files", 200) 将原单文件额度放大为 200 份，每份 20 MiB，单请求近 3.91 GiB。没有认证、请求总量、限频／并发或完成后文件清理。Multer 先处理完整 multipart 才检查卡片，所以不存在 cardId 也会落盘。旧单文件识别已有相关遗留问题，本提交新增独立批量放大。

有效卡片还会串行调用原生识别器，每进程超时 30 秒，200 份理论约 100 分钟原生工作；多批次并发可占磁盘、CPU、进程和请求容量。初始概述笼统提及断连遗留，后续验证明确：Multer 上传解析期间中止会清理部分文件，已完成并交给 handler 的上传不受该控制保护。

## 验证及证据

无凭据对不存在卡片上传两个 11 MiB 文件，真实 HTTP 返回 404，关服后文件仍在；另一请求接受并保留 200 个部分。有效卡片测试确认顺序识别及 200 响应后遗留。代码证明磁盘上传、无 MIME／魔数或总量限制、先上传后 readCard、成功／识别失败路径不删文件。

## 攻击路径与分级

匿名攻击者 → 运维公开代理／隧道 → 批量路由 → 每份 20 MiB、最多 200 份落盘 → 之后才检查卡片 → 404／成功／识别异常均遗留完成文件 → 累计磁盘及可选原生工作耗尽。

按提供的公网部署模型，发生可能性高：无需账号、有效卡片或竞态即可耗盘。影响程度高：共享服务／主机有限存储可能耗尽，识别额外占用计算。单文件和单请求有限、单批串行不能限制重复及并发批次。未证明 RCE、接管、泄密、改分或跨实例影响，故高危。严格本地 Electron 模式会降低远程可利用性，可能仅为本地问题。

## 假设、控制与盲点

回环服务经反代公开，没有仓库外认证、总量／配额／限速；数据目录可写且容量有限；磁盘路径只需完成上传，原生工作分支才需有效卡片。

现有控制是回环绑定、20 MiB／200 文件、safeId、Multer 2.0.2 上传解析中止清理、原生参数数组而非 Shell、30 秒子进程超时、单批顺序执行。无完成上传清理、权限、累计配额、全局识别并发上限。

历史提交没有具体代理／容器／负载均衡配置，真实公开和外部限制未知。Linux 验证没有 Windows 原生识别器，100 分钟由已核对循环和超时推导，不是 200 个真实进程压力测试。multipart 完成之后断连的遗留未独立压力验证；主机卷范围、并发批次、监管和外部清理也未知。
