# 41 恢复扫描端皮肤选择后未持久化

- 原标题：Reverting a scanner skin change is not persisted
- 云端级别：Informational
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/40eaaef423848191ae26118ccd7fffe1?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=&page=3)
- 关联提交：[715f158](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/715f158a4e6911bcad0a49011e9e42d834109165)

## 概要

该提交新增登录后的皮肤切换入口，但成功 PATCH 后未同步比较基准。登录时为 paper-edge，改成 flat 后数据库已更新；再改回 paper-edge 时，仍与旧 user.themeSkin 比较，skinPatchDecision 返回 patch: false。界面与本地存储显示 paper-edge，数据库却仍为 flat，重新登录或换设备后恢复为 flat。

应记录最近成功持久化的皮肤，更新登录用户对象，或重新读取设置。

## 验证与证据

原报告确认 CardSelectPage 的 onSkinChange={setSkin} 使连续切换可达，并通过生产决策函数和已认证设置接口复现第一次保存成功、恢复操作被跳过。现有验证脚本只覆盖一次登录后切换，未覆盖两次切换。

## 路径与等级判断

普通登录用户连续切换皮肤 → ScannerApp 与登录快照比较 → 首次 PATCH 更新本人设置 → 第二次请求被错误抑制 → 本地与服务端偏好不一致。

触发可能性高，影响低；最终按“仅影响本人”的策略排除出安全漏洞报告，因此显示为信息提示。这是已确认的功能正确性问题，不涉及其他用户、考试成绩、权限、秘密、执行能力或服务可用性。

## 前提、防护与盲点

前提是首次 PATCH 成功，且恢复皮肤前没有刷新用户上下文。认证与首次强制改密正常启用；接口仅使用 req.user.id，不能指定他人，皮肤只接受 flat / paper-edge，映射固定 ui_style，并使用参数化更新。服务监听回环地址，远程暴露依赖代理；CORS 使用允许列表。

未执行完整浏览器点击流程，但执行了生产函数和 HTTP 接口。未检查实际代理、HTTPS、认证或部署自定义刷新逻辑；仓库没有具体入口部署清单。
