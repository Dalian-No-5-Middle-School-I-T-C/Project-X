## 概要

此问题由本次修改引入。提交新增登录后的皮肤控制，但 PATCH 成功后没有同步比较基准，造成可恢复的偏好不一致；它没有越过授权边界，也不影响敏感考试数据。

登录后 serverSkin 来自 user.themeSkin，但成功 PATCH 不会更新或刷新用户对象。如果初始皮肤为 paper-edge，选择 flat 会保存 flat；随后再次选择 paper-edge 时，系统仍与登录时的旧快照比较，skinPatchDecision 返回 patch:false，因此界面和本地状态显示 paper-edge，数据库却仍为 flat。退出后重新登录或换设备时又会恢复为 flat。本次新增的登录后切换功能使问题可达。应跟踪最后成功请求或保存的皮肤，在成功后更新身份对象或刷新设置，而不是始终与不变的登录快照比较。

## 验证

1. 已认证扫描页面通过 onSkinChange={setSkin} 提供登录后的受控切换。
2. ScannerApp 与登录时的 themeSkin 比较，成功后不修改或刷新用户对象。
3. 动态验证证明，在第一次修改后，生产判断逻辑会抑制恢复初始皮肤的请求。
4. 真实认证设置端点确认首次保存成功，而恢复请求被抑制，使数据库与可见／本地状态不一致。
5. 确定前提及范围：只涉及本人外观，不跨越安全信任边界。

## 证据注释

1. 正常决策假设 serverSkin 是当前已保存值，但 ScannerApp 仍传入旧登录快照。
2. 每次切换都与 user.themeSkin 比较；不同则发出 PATCH，却从不更新该字段，因此恢复原值时被错误跳过。
3. 新接入已认证 CardSelectPage 的事件，使重复切换及旧基准失败可以通过界面触发。

## 攻击路径分析

策略调整前为低危：影响低，即使容易触发，矩阵结果仍低。最终适用仅影响本人的强制排除。index.ts:774–784 使用 req.user.id，第 807–814 行验证 themeSkin，第 831–835 行只修改同一用户的外观。没有现实的低权限攻击者能够因此影响他人身份、敏感考试数据、授权或服务。因此，虽然正确性缺陷已确认，但不可作为安全漏洞报告，调整结果为 ignore。

### 路径

普通已认证扫描用户 → 先选择另一皮肤，再选择原皮肤 → SkinSwitcher 记录明确选择并触发 onSkinChange → ScannerApp 及会话／本地状态更新 → effect 与旧身份快照比较 → 决策使用登录时 themeSkin → 允许首次请求，抑制恢复请求 → 首次设置 PATCH 只使用验证过的枚举修改 req.user.id → 本人的 theme_skin／ui_style 留在中间值 → 可见及本地偏好与持久化偏好不同。

普通用户进行两次正常切换。第一次成功保存，但异步请求不更新或刷新身份对象；下一次决策把返回登录值误认为已保存状态，因此不发送请求。生产判断逻辑及已认证 Express 验证表明，浏览器可见值为 paper-edge，而数据库为 flat。最强反向证据是服务端第 774–814 行要求认证，目标只能是 req.user.id，且只接受两个不具有执行含义的枚举值。这些控制决定性地排除了跨用户修改、授权绕过、秘密泄露、代码执行和考试完整性影响，但不否认功能不一致。已有验证能够反驳更简单的登录过渡回归，却只覆盖登录后切换一次，没有覆盖已证实的两次切换情形。

## 发生可能性

高。普通已认证界面中，先选择另一皮肤，再在未刷新身份对象时恢复原值即可触发。概念验证通过生产决策逻辑和端点复现了状态分歧。但较高的功能触发率不产生攻击者优势。

## 影响程度

低。只对发起用户造成可恢复的外观不一致，没有跨用户写入、提权、敏感信息披露、考试完整性损害、代码执行或实质可用性损失。

## 假设条件

- 生产环境按威胁模型启用认证。
- 扫描 Web 界面可能通过运维代理或隧道访问，但工作区没有具体入口配置。
- 第一次 PATCH 成功，恢复原皮肤之前身份对象未刷新。
- 情景仅涉及普通用户操作自己的主题。

原文另列前提：

- 存在有效认证会话。
- 登录时皮肤为两个支持值之一。
- 用户选择另一个值，且 PATCH 成功。
- 不刷新用户对象，同一用户再次选择登录时的初始值。

## 控制措施

- 强制认证开启时，authMiddleware 要求有效会话。
- 首次强制改密完成前，普通 API 被阻止。
- PATCH 目标为 req.user.id，不能选择其他用户。
- themeSkin 只允许 flat 或 paper-edge，并映射到固定 ui_style。
- 使用参数化更新，不将输入作为可执行内容解释。
- CORS 使用允许列表，不通过通配配置暴露凭据。
- Node 绑定回环地址，远程访问需要运维入口。
- 修改只涉及外观，不改变成绩、扫描、考试、权限、凭据或发布状态。
