# 42 演示导入可能静默修改真实答题卡

- 原标题：Demo import can silently modify a real answer card
- 云端级别：Informational
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/eaefc6f1683c81919dd846200f51363c?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=&page=3)
- 关联提交：[721fb40](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/721fb40d005711cbd507accbfadc857f57cdbac9)

## 概要

提交将答题卡创建由 INSERT 改为 INSERT OR IGNORE。固定演示 ID（如 88000001、88000002）与真实卡冲突时，旧逻辑会报唯一性错误；新逻辑忽略冲突后继续将真实卡当作演示卡使用，未检查 is_demo 或插入结果。

seedExam 可将演示考试关联到真实卡，ensureDemoObjectiveBlock 加入演示客观题块及固定答案；seedFillBlankDemo 向 88000001 加入主观题块、题目、图像记录与资源。后者仍保留“占用 ID 会使前序操作失败”的过时注释。清理仅删除 is_demo=1 的答题卡，因此真实父记录及注入的子记录、资源可残留。

应检查插入结果，只有确认演示归属与身份后才能复用，否则终止或分配无冲突 ID。

## 验证与证据

使用实际服务与 schema 的隔离测试复现 ID 冲突、真实卡被修改、清理后残留，以及 CardRepository 仍读取这些内容。已确认生产管理员入口调用该服务；测试直接调用 seedDemoData，并未重放 HTTP，也未完整执行导致已发布成绩变化的判分流程。

## 路径与等级判断

最高权限管理员在开发者模式调用 POST /api/db/import-demo → SQLite 固定 ID 插入被忽略 → 演示考试与题块等写入真实卡 → 清理保留非演示父卡及注入数据 → 普通答题卡和成绩编辑流程继续消费修改后的定义。

技术影响中等、可能性低，矩阵初步为低危；最终因需受保护的管理员写入且未证明权限提升，按策略不作为安全漏洞报告。原报告确认这是实际的数据完整性与管理安全缺陷，而非误报。

## 前提与已有防护

仅适用于 SQLite，路由明确拒绝 MariaDB。需真实卡恰好占用固定 ID，并由同时具备 USER_MANAGE 与 SYSTEM_MANAGE 的用户主动导入；当前只有通配管理员满足。正常创建/导入会生成新八位 ID，碰撞少见；界面需开发者模式并确认。认证、强制改密和两层权限检查有效，服务直接监听回环地址。

教师通过可写答题卡 API 布置固定 ID 的准备路径看似可行，但未动态验证，且教师已有广泛共享卡写权限，仍不能自行触发管理员导入。

## 盲点

未检查实际生产导入频率、ID 碰撞频率或入口代理；远程可达来自提供的威胁模型。影响限于碰撞卡，可检查修复；测试未证明真实成绩直接改变。
