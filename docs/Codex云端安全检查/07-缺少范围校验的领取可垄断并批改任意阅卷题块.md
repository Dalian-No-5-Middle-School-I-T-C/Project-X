# 07 缺少范围校验的领取可垄断并批改任意阅卷题块

## 概要

本提交引入持久化试卷领取，并以领取归属作为提交分数的授权条件，但新增领取操作没有执行已有题块或学生分配约束。结果是出现新的持久锁定垄断路径，以及批改教师分配范围之外试卷的授权路径。

新的阅卷池领取端点只检查 requireExamAccess 和通用 GRADE_WRITE，不验证调用者是否有目标题块的 review_assignments 记录、所选学生是否在 assigned_student_ids 内，或未完成领取数是否在分配工作量以内。claimNextPaper 因而从调用者指定考试/题块的全部未领取裁图中选择，并直接把归属设为调用者。能访问考试的教师可以反复调用直至池被取空，包含分配给其他教师的题块。领取没有租约到期或陈旧领取回收，通常只有领取者可释放，仅管理员可强制释放。修改后的提交逻辑因 claimed_by 属于攻击者而拒绝合法分配阅卷人，却接受攻击者提交。攻击者可在阅卷窗口让所有试卷锁住，或提交其自选且范围合法的分数；单评模式可能成为最终分，多评可被操纵或强制进入争议。原子更新只能防止两人领取同一份，不能提供对象授权。应在领取事务内执行题块和学生分配范围，按授权工作量限制未完成领取数，并对遗弃领取加入到期/回收。

## 验证

1. 验证有考试访问和 GRADE_WRITE 的非管理员教师，可在没有阅卷分配、题块或学生范围检查时访问领取端点。
2. 验证服务对 review_assignments、assigned_student_ids 以外裁图持久化领取，且无分配工作量配额。
3. 验证可反复领取耗尽池，claimed_at 不触发过期，合法分配教师无法释放。
4. 验证领取归属拒绝合法阅卷者，却允许未分配领取者提交范围合法分数并成为记录的阅卷人。
5. 经已认证生产 HTTP 路由复现链路并确认数据库结果。

## 证据注释

1. claim-next 只检查广义考试可见性与 GRADE_WRITE，将调用者及任意题块/班级参数传入服务，不验证分配或配额。
2. 指定试卷领取同样允许任何通用成绩写权限教师，领取可访问考试/题块的任意裁图。
3. 他人领取只能由管理员强制释放，无遗弃或恶意领取过期机制。
4. 服务从指定考试/题块所有未领取裁图选择并写入调用者 claimed_by，不按分配记录、学生列表或未完成领取限制筛选。
5. 提交权现在来自 claimed_by，未授权领取者可提交，合法分配教师反而被拒绝。

## 攻击路径分析

不适用强制排除：影响不限本人，普通低权限教师能达成前提，受影响路径是正常生产阅卷流程，不限管理员、操作者、开发者、物理访问或只能受保护写入触发。攻击越过明确的教师/题块/学生分配边界，且已端到端复现。持久的题块级可用性丧失和未授权评分记录使影响为高；默认教师权限、低复杂度认证 HTTP、无受害者交互或竞态使可能性为高。矩阵得到高危，未达严重：需要有考试可见性的教师账号，没有广泛泄密或实例接管，单评最终分破坏也未被演示。

### 路径

有考试可见性和 GRADE_WRITE、但未被分配的普通教师 → POST 自选 examId/blockId/cropId → Express 阅卷池领取端点 → 考试级访问与通用权限检查通过 → ReviewPoolService claimNextPaper/claimSpecificPaper → 未验证阅卷分配/工作量即写攻击者 ID → answer_block_crops.claimed_by 与 claimed_at → claimed_by 被接受为判分权 → 评分提交端点 → 保存攻击者分数、拒绝分配阅卷人 → 未授权评分历史、合法阅卷者被锁在外及题块不可用。

攻击过程：恶意或失陷普通教师可访问考试，但未被指派批改 BLOCK-A 或其中学生。其反复调用正常已认证领取端点。Express 检查考试可见性与 GRADE_WRITE，服务随后从指定考试/题块选择任意未领取裁图，不查 review_assignments 即写入教师 ID。没有领取配额或租约到期，教师便可耗尽题块并保持锁定。其他普通教师释放被拒，强制释放仅管理员可用。ReviewService 随后把 claimed_by 当作提交授权，因此拒绝合法分配教师，允许攻击者提交范围合法分数。所提供 PoC 开启认证并执行真实 Express 接口：分配 API 显示 isSelected=false、assignedToMe=0 的攻击者领取了专门分配给另一教师的全部三份，导致合法教师领取/释放/提交均失败，并在双评模式下以阅卷人身份保存分数。除攻击者合法会话外，不需或不会披露凭据和应用秘密。原子领取、分数范围、既往评阅检查及 CAS 更新限制竞态和畸形分数，却未确立对象授权。最强影响反向证据是没有证明单评最终分产生，因为本提交默认 review_round 与单评提交逻辑冲突；这一较窄主张被排除。整个题块持续拒绝阅卷和未授权多评分数持久化均已独立证明。

## 发生可能性

**高。** 对定义的内部威胁，教师默认拥有 GRADE_WRITE，只需考试级可见性，利用普通 HTTP 端点和可控 ID，不需竞态或受害者交互，重复请求可耗尽池。真实已认证 Express 复现成功。直接监听仅本机，隧道随启动方式/部署变化；这降低对暴露面的确信程度，但不使路径不现实，因为产品是 Web 流程，仓库启动器支持公开隧道。**攻击向量：远程网络。**

## 影响程度

**高。** 普通教师跨越明确阅卷人—题块/学生授权边界，可影响目标题块全部可领取裁图。已证明效果为：在攻击者或管理员处理前持久的题块级阅卷不可用，拒绝合法分配教师，以及在双评流程中保存攻击者自选但范围合法的分数和阅卷身份。这威胁学业结果完整性与阅卷窗口可用性。分级不依赖机密性影响或自动单评定稿。

## 假设条件

- 生产认证保持开启；除显式 PROJECTX_AUTH_ENFORCE=0/false 外默认如此。
- 攻击者有普通教师账号、GRADE_WRITE 和考试可见性，但没有目标题块/学生 review_assignments。
- 目标考试与题块存在可领取 answer_block_crops，且明确分配给其他教师。
- 存在分配记录时，显式分配意在约束阅卷；UI 开放池回退只在没有分配记录时适用。
- Express 经正常客户端、代理或仓库 Cloudflare 启动器可达。

原文另列的利用前提：

- 已认证普通教师账号。
- 默认或显式授予的 grade:write。
- requireExamAccess 下考试级可见性。
- 知道目标 examId、blockId。
- 至少一张分配给他人的可领取裁图。

## 控制措施

- 除显式关闭外认证默认开启。
- 挂载的分析门禁要求 GRADE_READ，领取/提交另需 GRADE_WRITE。
- requireExamAccess 拒绝学生和看不到所选考试的教师。
- 领取更新要求 claimed_by IS NULL，防止并发重复归属。
- 阅卷历史通常阻止同一教师重新领取并重复评阅同一裁图。
- 提交验证题目成员关系、数值有限性、分数范围、评分模式及权威满分。
- 事务领取复查及比较交换评阅更新降低竞态覆盖。
- 通常只有领取者可释放，只有管理员能强制释放他人领取。
- 领取或提交均未验证 review_assignments、assigned_student_ids、student_count。
- 没有未完成领取配额、租约到期、陈旧领取回收或通用限流。

## 盲点

- 检出代码证明回环监听且提供 Cloudflare 启动器，但不确定各实际部署入口。
- 可执行复现使用 SQLite；SQL 简单且经 DbAdapter 共享，但未在 MariaDB 重跑相同端到端利用。
- 证明了双评未授权分数持久化，未证明该提交新建单评裁图必然得到最终分。
- 仓库未完整规定每所机构是否把分配当作强制授权；但复现场景存在显式分配，威胁模型将题块/学生阅卷边界视为安全边界。
- 未包含裁图机密性影响，因为本发现已演示路径涉及领取归属、成绩完整性与可用性。

~~~~typescript
export async function claimNextPaper(
  examId: number,
  blockId: string,
  teacherId: number,
  db: DbAdapter = getMysqlDb(),
  options: { classId?: number } = {}
): Promise<ReviewPoolEntry> {
  const cropId = await db.transaction(async (tx) => {
    const classFilter = options.classId
      ? `AND EXISTS (SELECT 1 FROM class_students cs WHERE cs.student_id = answer_block_crops.student_id AND cs.class_id = ?)`
      : "";
    const classParams = options.classId ? [options.classId] : [];
    const candidates = await tx.all(
      `SELECT id, score_breakdown FROM answer_block_crops
       WHERE exam_id = ? AND block_id = ? AND ${statusClause()} AND claimed_by IS NULL ${classFilter}
       ORDER BY student_number, page_number, segment_index`,
      examId,
      blockId,
      ...classParams
    ) as Array<{ id: string; score_breakdown: string | null }>;
    const candidate = candidates.find((item) => {
      try {
        const history = item.score_breakdown ? JSON.parse(item.score_breakdown) as Array<{ reviewerId?: number }> : [];
        return !history.some((review) => review.reviewerId === teacherId);
      } catch { return true; }
    });
    if (!candidate) throw new ReviewPoolError("试卷池暂无可用试卷");

    const now = new Date().toISOString();
    const result = await tx.run(
      `UPDATE answer_block_crops
       SET claimed_by = ?, claimed_at = ?, claim_count = claim_count + 1
       WHERE id = ? AND claimed_by IS NULL AND ${statusClause()}`,
      teacherId,
      now,
      candidate.id
    );
    if (result.changes === 0) {
      throw new ReviewPoolError("试卷刚被其他教师领取，请重试");
    }
    return candidate.id;
  });
  return getPoolEntry(examId, blockId, cropId, db);
~~~~
