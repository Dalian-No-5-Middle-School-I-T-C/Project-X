# 07 缺少范围校验的领取可垄断并批改任意阅卷题块

- 原标题：Unscoped claims let teachers monopolize and grade any review block
- 云端级别：High
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/4e2b2b0bf3bc81919798177834a2ad92?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=)
- 关联提交：[7d7ff51](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/7d7ff51d1951570ca37836dc0c80311f2039a88a)

## 概要

本提交引入持久化试卷领取，并以 claimed_by 归属决定能否提交分数，但新增领取操作不检查既有题块／学生分配。新接口仅要求 requireExamAccess 和 GRADE_WRITE，不核对 review_assignments、assigned_student_ids 或未完成领取数量。claimNextPaper 可从指定考试／题块的所有未领取裁图中取出并归给调用者。

能访问考试的教师可反复领取他人题块直至池为空。没有租约到期或陈旧领取回收，通常仅领取者可释放，只有管理员能强制释放。提交逻辑反而拒绝真正被分配的教师，允许攻击领取者提交范围合法的分数。概述提出单评可能进入最终分、多评可能被操纵或制造争议；但云端验证未证明该提交的单评自动定分，已明确不将此更强主张作为分级依据。

原报告建议在领取事务内强制题块与学生分配范围，按授权工作量限制待完成领取，并增加到期／回收。原子领取防止重复所有权，不等于对象授权。

## 验证及证据

真实认证 Express PoC 中，分配 API 显示攻击者 isSelected=false、assignedToMe=0，但他仍领取了专门分给另一教师的全部三份卷。合法教师领取、释放、提交都失败；攻击者在双评模式下持久化了自己选择的合法范围分数及阅卷人身份。

claim-next 和指定裁图领取都只验证考试与通用阅卷权限；服务直接写 claimed_by、claimed_at，没有工作量限制。非所有者释放需管理员；claimed_at 不用于到期。ReviewService 把 claimed_by 视为提交权，形成“未经授权领取 → 获得判分权”的链条。

## 攻击路径与分级

有考试可见性但无题块／学生分配的教师 → 传入 examId/blockId/cropId → 领取服务写攻击者 ID → 耗尽整个题块可领取池 → 合法教师被拒 → 攻击者提交多评成绩或长期占锁。

发生可能性高：默认教师已有 GRADE_WRITE，只需普通 HTTP 和 ID，无竞态或受害者交互。影响程度高：整个题块阅卷可持续不可用，须攻击者或管理员干预，同时存在未经授权的多评分数与阅卷者记录。该链跨越明确分配边界，非仅自身影响或管理员／运维／开发／物理路径。需要教师身份和考试可见性，没有广泛泄密、实例接管，也未证明单评最终分篡改，故高危。

## 假设条件及已有控制

认证默认开启；存在给其他教师的明确分配和可领取裁图；攻击者有考试可见性及 grade:write，知道考试和题块 ID，但没有相应分配。原报告假设有分配记录时应强制遵守；UI 的开放池回退只适用于没有分配记录的情况。入口通过正常 Web、反代或仓库 Cloudflare 启动器可达。

挂载的分析门禁要求 GRADE_READ，领取／提交另需 GRADE_WRITE；requireExamAccess 拒绝学生及不可见考试；条件 claimed_by IS NULL 防并发重领；历史通常防止同一教师再次评同卷。提交校验题目归属、有限数值、范围、评分模式及权威满分；事务重检与 CAS 减少竞态覆盖。仅领取者普通释放、管理员强制释放，这反而延长恶意锁持有。领取和提交均无 review_assignments、assigned_student_ids、student_count 授权校验，无领取额度、租约、回收或通用限流。

## 盲点

未确认每个部署入口，SQLite 端到端已验证，MariaDB 未重跑。该提交默认 review_round 与单评提交逻辑冲突，未证明新单评裁图必然产生最终分；仅依赖双评持久化与长期阻断。学校是否将所有分配都视为强制授权，仓库未完整定义，但复现中存在明确分配且威胁模型包含该边界。本项不主张裁图泄密。
