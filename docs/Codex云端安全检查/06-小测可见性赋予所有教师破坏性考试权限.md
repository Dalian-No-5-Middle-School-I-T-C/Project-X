## 概要

本提交把所有小测考试并入通用可见范围，却没有将读取可见性与写入、判分、模式管理和删除授权分离，从而引入授权漏洞。已有破坏性路由立即继承了扩大的范围。

本提交将每个 exam_mode='quiz' 考试加入所有有范围限制教师的 getVisibleExamIds 结果，不考虑班级、学科或显式限制。然而 requireExamAccess 把进入该列表视为对所有 HTTP 方法的授权，而不仅是读取。默认教师同时拥有考试和判分写权限，多个破坏性路由只使用这种不区分方法的检查。因此，与某小测毫无关系的学科教师或班主任也能在考试列表枚举它，调用 PUT /api/exams/:examId/student/:studentId/scores、PUT /api/exams/:examId/answers 或 DELETE /api/exams/:examId。答案端点改写关联答题卡并自动重算每名学生客观题成绩；删除会移除逐题分数、总分、扫描批次和考试。新增模式更新也只由 requireExamAccess 保护，尽管客户端只向管理员展示该控制；教师因此可以把可访问正式考试改为小测、扩大暴露，或把任意小测改为正式考试。小测读取可见性可能出于设计，但使用同一范围作为修改授权，越过了班级、学科及阅卷边界。

## 攻击路径分析

不适用强制排除：影响不限于本人，前提现实，所需教师权限正是授权边界被绕过的较低权限身份。受保护写入路径不能缓解，因为默认教师拥有 exam:write，而有缺陷的对象检查接纳全部小测。文档中的反向代理部署支持远程访问，因此可能性高。可达操作会修改或删除跨边界权威学业数据，包括整场重算，影响高。按矩阵得到高危而非严重，因为需认证教师，范围仍限于单个实例及小测，没有证明管理员接管、未认证失陷、远程代码执行或完整实例失陷。

### 路径

已认证的受范围限制教师 → 正常 Web API GET /api/exams 枚举无关小测 → 得到可选择的小测 ID → 全局小测 ID 进入 getVisibleExamIds → 可见性被复用为写授权 → requireExamAccess 对所有 HTTP 方法放行 → 进入分数、答案、模式或删除端点 → 持久化越权修改/删除 → 跨班级、跨学科学业数据损坏或删除。

攻击过程：恶意或失陷数学学科教师通过正常 Web API 登录。withQuizExamIds 无条件加入所有小测 ID，所以 GET /api/exams 返回其他教师拥有的历史学科小测。教师把其中 ID 提交到改分、改答案、PATCH 考试或 DELETE 考试端点。出厂教师角色有 exam:write，因此能力门禁放行；requireExamAccess 不区分可见性与修改权，也会放行。可执行验证使用开启认证的真实 Express 应用，证明跨学科改分、修改模式，以及删除无关小测和依赖记录；同等正式考试返回 403。除了攻击者合法会话，无需或不会暴露应用秘密；受到影响的是敏感学生成绩、排名、答案、扫描批次关联和考试记录。最强反向证据为注释、schema 文本及引入变更将小测描述为全局可见或完全权限，暗示某些广泛访问是有意的。但在给定威胁模型下，这不能直接否定漏洞：同一函数被用于破坏性授权，正式考试教师范围仍存在，模式切换界面仅管理员可见而后端无此检查。其他反向证据为 Node 只监听回环、部署可以定制教师权限；然而仓库明确记录公开 HTTPS 代理部署，默认教师确有写权限。问题限于一个实例且主要为小测，但越过了真实教师、班级、学科与阅卷边界。

## 发生可能性

**高。** 使用正常认证 HTTP 请求、全局可枚举的小测 ID 和默认教师权限。只需现实的恶意/失陷教师账号及一场小测，不需管理员、竞态、本地 shell、秘密提取、匹配班级或学科。仓库记录 Nginx HTTPS 远程部署，可执行验证确认生产 Express 路径。**攻击向量：远程网络。**

## 影响程度

**高。** 教师越过考试、班级、学科、所有权及阅卷边界，修改权威成绩和排名、替换答案并重算全部考生，或删除无关考试及成绩/扫描批次记录。这对教育记录完整性和可用性影响重大，但限于单个 Project-X 实例和受影响小测集合。

## 控制措施

- 默认开启认证，接受不透明 Bearer 令牌或 HttpOnly、SameSite=Lax Cookie。
- 登录每 15 分钟每 IP 最多 10 次。
- /api/exams 能力门禁对 PUT/PATCH/POST/DELETE 要求 exam:write。
- requireExamAccess 阻止受范围限制教师访问无关正式考试，但错误接纳全部小测。
- 分数与答案请求体经过结构验证。
- 改分、改答案使用事务，记录 modified_by 或 answer_overrides，并重算排名。
- 客户端隐藏非管理员模式切换，但不构成服务端授权。
- 操作者可定制角色去掉 exam:write，但默认教师角色授予此权限。

## 盲点

- 实际实例可能仅监听回环或在学校私网，不使用文档公网 HTTPS 部署。
- 操作者可能移除教师 exam:write，降低相应部署可利用性。
- 仓库注释明确称小测全局可见或完全权限，保留部分政策意图歧义；但给定威胁模型和管理员专属模式界面不支持将所有破坏性操作都视为普遍授权。

- 直接证明了改分、改模式和删除；由答案更改触发整场重算依据可达源码确认，未在所提供 PoC 中另行执行。
