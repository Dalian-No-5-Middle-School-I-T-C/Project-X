## 概要

此问题由本次修改引入：从前一个打包版 v0.1.0 升级的实例，将看不到此前保存的所有答题卡，除非操作者手工把 `<old-data>`/cards、`<old-data>`/layouts 和 `<old-data>`/assets 移入新的 answer-card 目录。依赖默认数据路径的独立服务部署同样受到影响。需要启动迁移或旧路径回退机制。

本次提交之前，Electron 应用把答题卡、布局和资源保存在 `<userData>`/data 下，独立服务默认使用 `<cwd>`/data。提交无条件将这些位置改为 answer-card 子目录。升级后第一次启动时，ensureDataDirs() 会在新位置创建空目录树，因此应用列不出已有答题卡，也无法找到关联资源。没有迁移、复制、重命名或旧路径回退。原始文件仍保留在旧位置，可以恢复，因此这是可恢复的可用性／数据发现退化，而非破坏性数据丢失。

## 攻击路径分析

未调整的操作严重性仍为低，因为该退化造成可恢复的单服务可用性及数据发现损失，没有删除文件。最终策略阶段适用强制排除，因为触发完全属于可信操作者升级／启动条件，不存在攻击者控制的输入，也没有跨越信任或授权边界。将 impact=low 和 likelihood=ignore 代入所要求矩阵，得到 adjusted_criticality=ignore。回环绑定、可能的外部转发以及未认证答题卡路由，都不会改变结论，因为它们均不提供对启动数据路径的控制。

### 路径

可信操作者升级或重启含有旧数据的实例 → 升级后的正常产品启动 → Electron 或独立服务启动选择新的 answer-card 数据根目录 → 初始化创建缺失目录 → ensureDataDirs() 在新根目录创建空目录树 → 存储模块导出的路径仅指向新根目录 → 答题卡和资源消费者只查询新目录树 → 列表、读取和静态请求不检查旧根目录 → 旧答题卡及资源不可见，但仍可恢复。

提交 81afe4de 将打包 Electron 根目录从 `<userData>`/data 改为 `<userData>`/data/answer-card，将独立服务默认目录从 `<cwd>`/data 改为 `<cwd>`/data/answer-card。启动创建新目录后，答题卡枚举、单卡查询及静态资源服务只检查新目录树。提供的可执行复现确认，启动后答题卡结果为空，相关请求返回 404，而哈希表明所有旧文件保持完整；明确选择旧根目录后，HTTP 200 响应恢复。这是真实的产品正确性退化，但不是现实攻击情景。所需触发是可信升级或启动操作，网络请求及低权限身份均不能控制存储根目录决策。反对影响的最强证据是：ANSWER_CARD_DATA_DIR 可以选择旧根目录，旧文件得到保留，布局也可以根据迁移后的答题卡重新生成。这些控制使恢复具有可操作性，但不能防止默认路径退化。反对仅限 localhost 暴露分类的最强证据，是威胁模型允许反向代理或隧道；然而即使存在外部转发，远程调用方也无法触发这一次特定路径迁移，或从中获得安全优势。

## 发生可能性

忽略（Ignore）。含有旧数据的正常升级很可能遇到这一操作退化，但范围内没有现实攻击者可以触发或利用它。存储根目录选择由可信启动代码及操作者控制的环境状态决定，而不是网络请求或低权限用户。按要求的策略，仅操作者能够触发、且没有额外提权收益的路径，在安全可报告性上将发生可能性设为 ignore。

## 影响程度

低（Low）。升级后，此前默认位置中的所有答题卡及关联资源，都可能从应用视图中消失，影响答题卡设计流程的可用性。影响仅限受影响实例及存储服务；源文件保持完整，显式环境变量覆盖能够恢复访问，答题卡及资源也可手工移动。没有证明机密性、完整性、身份或权限影响。

- 操作者没有显式将 ANSWER_CARD_DATA_DIR 设为旧根目录，也没有手工迁移文件。
- 仓库之外没有具体部署的封装程序在应用启动前执行迁移。

## 控制措施

- 独立服务接受操作者控制的 ANSWER_CARD_DATA_DIR 覆盖值，可指向旧根目录。
- 服务直接绑定 127.0.0.1；Electron 也使用动态回环端口。
- 初始化采用递归创建目录，不删除、覆盖或重命名旧文件。
- 答题卡标识符及资源基本文件名会被规范化，但这些检查不能解决根目录选择的向后兼容问题。
- 没有迁移、旧路径回退或启动兼容性警告。
- 相关答题卡 API 路由不实现认证，但远程请求输入不会影响本次存储根目录退化。

## 盲点

- 无界面环境没有动态执行打包 Electron 图形界面和 MSI 升级过程，不过打包入口明确在启动同一服务之前设置了变更后的路径。
- 所检查文件未能确定具体部署的封装程序或外部反向代理；外部转发会改变 API 暴露，但不会改变该迁移由非攻击者控制的触发条件。
- 仓库没有体现文件系统 ACL 及特定安装的用户数据路径行为。
- 提供的可执行复现执行了独立服务 HTTP 接口，而不是实际包管理器升级。
