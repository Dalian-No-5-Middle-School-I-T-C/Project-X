# 52 数据目录迁移使既有答题卡不可见

- 原标题：Data-directory relocation hides existing answer cards
- 云端级别：Informational
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/f65bd4f7e1d481918e982f16f3846238?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=&page=3)
- 关联提交：[81afe4d](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/81afe4de2515f6fe3b01ea72f711df6c0a3b94f6)

## 概要

提交将 Electron 数据根从 <userData>/data 改为 <userData>/data/answer-card，将独立服务默认根从 <cwd>/data 改为 <cwd>/data/answer-card，却未迁移或回退。升级启动时 ensureDataDirs() 创建空 cards、layouts、assets，新路径读取不到旧卡及资源。

旧文件仍存在，属于可恢复的可用性与数据发现回归，不是破坏性数据丢失。需要启动迁移或旧路径回退；管理员可迁移三类目录，或为独立服务指定旧 ANSWER_CARD_DATA_DIR。

## 验证与路径

确认紧邻前版本及打包 v0.1.0 使用旧默认路径。原测试通过真实存储与独立服务 HTTP 复现列表为空、资源 404、新目录创建；哈希证明旧文件完好，显式选择旧根后恢复 HTTP 200。

可信操作者升级/启动 → 选新子目录 → 只创建空树 → 卡枚举、读取与静态资源只查新根 → 旧数据隐藏但可恢复。

## 等级判断

运行影响低，最终为信息提示：触发由可信升级和启动环境决定，没有攻击者输入或新增权限。外部代理与无认证卡 API 不会使远程请求控制此启动路径。影响限于该安装，文件可搬迁，布局可从迁移后的卡重建。

## 前提、防护与盲点

需旧默认根已有数据，升级后沿用相同 Electron 用户数据位置或独立服务工作目录，未设旧根覆盖、手动迁移或外部迁移包装。目标提交为 81afe4de2515f6fe3b01ea72f711df6c0a3b94f6。

初始化递归建目录但不删、覆盖或重命名旧文件；服务监听 127.0.0.1，Electron 使用动态端口。ID/资源名归一化不能解决根路径兼容。没有迁移、回退或启动兼容警告。

无头环境未验证打包 Electron GUI 或 MSI 真实升级，执行的是独立 HTTP 接口；入口源码明确在启动同一服务前设置新根。外部包装迁移、ACL 和安装特定用户目录行为未知。
