# 09 多页试卷可耗尽磁盘和堆内存

- 原标题：Multi-page papers enable disk and heap exhaustion
- 云端级别：High
- 原始报告：[打开报告](https://chatgpt.com/codex/cloud/security/findings/a535a22db0008191abde49272868dd8a?repo=https%3A%2F%2Fgithub.com%2FDalian-No-5-Middle-School-I-T-C%2FProject-X&sev=)
- 关联提交：[7d5086d](https://github.com/Dalian-No-5-Middle-School-I-T-C/Project-X/commit/7d5086dae08e9d7b056321e31ccfa817c993ecf7)

## 概要

本提交将原先单文件、固定 original.* 覆盖存储改为每次最多 40 文件，并从现有最大页码后无限追加。Multer 只有单文件 50 MiB 限制，因此单请求可写入约 2000 MiB 临时数据；无跨请求页数、字节额度或限流。AI 路径也由读取一份文件后返回，改为读取所有累计图像／PDF，将全部 base64 留在数组中，再 JSON.stringify 形成额外大型对象。磁盘耗尽不需要 AI；多模态路径可进一步使共享 Node 进程堆溢出。

原报告建议限制请求总量及每卡页数／总字节，在持久化前拒绝超额，所有失败路径清理临时文件，并流式处理或严格限制 AI 输入。

## 验证与证据

真实登录证明普通教师拥有 grade:write，匿名上传返回 401。两次 HTTP 请求各上传 40 个 1 MiB PDF，依次追加 1—40、41—80 页，形成 80 文件、80 数据行，总计 83886080 字节。生产分析端点读取全部文件为 base64 后，在有意限制为 128 MiB 的 Node 堆中 JSON 序列化导致致命内存不足，尚不需要外部模型响应。未做不安全的真实填满磁盘测试，也未发送完整 40×50 MiB 请求。

代码证据显示：仅限单文件大小；接受 40 文件；从 MAX(page_index) 后分配独立文件名；所有页累计读取；多模态请求整体 JSON 序列化。

## 攻击路径与分级

教师会话 → Nginx／Cloudflare 入口 → POST /api/cards/:cardId/paper → 无界累计 original-N.pdf 和 original_paper_pages → 知识点分析读取所有页 → base64 数组及 JSON 放大 → 持久磁盘耗尽或 Node 退出。

发生可能性高：普通业务权限，正常 HTTP，无竞态或解析器技巧；持久增长已直接复现。影响程度高：共享卷耗尽影响试卷、扫描、阅卷、数据库写入；多模态分支可终止共享服务。授权上传不等于授权耗尽共享资源，非仅自身影响。需认证，限单实例，可通过删除恢复，未证明泄密、接管、RCE 或隐蔽改分，故高危。

## 假设条件、已有控制与盲点

认证开启；攻击者有普通教师 grade:write、可用或自建卡片；通过受支持入口访问；外部反代或文件系统没有更小额度。堆耗尽分支需要 OpenAI／Gemini 多模态提供商，磁盘分支不需要。

现有控制包括认证、cardGate、40 文件／单份 50 MiB、扩展名检查、事务内分配页码及插入、授权删除一页或全部页、回环监听与 CORS。事务防重复索引而不限制累积；删除是事后恢复，不是配额。未发现请求总字节、每卡累积配额或上传限流。

真实 Nginx/CDN/Cloudflare/WAF 限额、磁盘容量、配额、进程监管与重启策略未知。崩溃在 --max-old-space-size=128 下证明，默认堆所需页数随环境变化。测试只用 1 MiB 文件限制资源消耗。人工清理和告警响应速度也未由仓库建立。
