## 概要

**由本次变更引入。** 基线端点只接收一个文件，以固定 original.* 名保存，AI 分析加载一个图像/PDF 后返回。本提交改为 40 文件数组，以唯一编号无限追加页，并使 AI 保留全部页，没有总资源限制。

卡片路由允许有 grade:write 的用户写入，教师默认获得它。修改后每次最多 40 文件，Multer 唯一大小控制为单文件 50 MB，所以一个请求可在临时目录放入约 2 GB。处理函数从当前最大页号之后继续编号，每页使用不同文件名。没有总字节配额、跨请求最大页数或限流，重复请求永久扩大试卷目录，不再覆盖基线单个有界原始文件。新 AI 路径进一步放大：getPaperFiles 读取所有累积图像/PDF，把 base64 表示保留在数组中，JSON.stringify 又为辅助服务请求构建一份大表示。配置多模态提供商后，数量不多的最大文件页即可超过 Node 堆并终止进程；独立地，上传也可填满数据卷，干扰扫描、判分和数据库写入。应设小的请求总量限制和单卡页数/字节配额，超限时在持久化前拒绝，所有失败路径清理临时文件，AI 输入改为流式或严格大小上限，而非收集所有页 base64。

## 验证

1. 攻击者可达：普通默认教师通过真实登录认证，具有卡片门禁要求的 grade:write。
2. 请求控制不足：允许 40 个各 50 MiB 文件，无请求总字节、路由频率或单卡配额。
3. 跨请求持久化：两个真实 HTTP 请求追加 1—40、41—80 页，保留全部 80 文件与数据库行，而非覆盖旧试卷。
4. AI 放大与可用性入口：全部 80 PDF 页读为 base64，JSON 序列化在 128 MiB 有界堆下造成致命 Node 堆耗尽。
5. 有界测试展示现实影响：认证 HTTP 复现精确保留 83,886,080 字节；源码计算证明每请求最高 2,000 MiB，同时避免不安全的宿主磁盘填满测试。

## 证据注释

1. Multer 只有单文件 50 MB，没有请求总字节限制。
2. 修改路由每请求最多接收 40 个最大文件。
3. 每次从 MAX(page_index) 后开始并保存独立页文件，无总页数/字节配额。
4. 多模态分析收集文件，把所有 base64 序列化为一个 JSON 请求。
5. 所有已存图像/PDF 都读入并保留为 base64，总页大小可耗尽 Node 堆。

## 攻击路径分析

已确认事实对应高影响乘高可能性。攻击者是现实范围内默认教师，权限差异为服务级资源耗尽，而不只是获授权上传仅影响本人。可执行验证确认跨请求持续增长和有限堆进程崩溃。按矩阵仍为高危，未达严重：需认证、目标单服务、可恢复删除，没有机密性、身份接管、RCE 或隐蔽成绩完整性失陷。因此保留原高危，不排除也不提升。

### 路径

有 grade:write 的默认教师 → 有效会话访问远程 Web 服务 → 文档 Nginx HTTPS 或 Cloudflare → multipart 转发回环 5174 → POST /api/cards/:cardId/paper → 接收 40×50 MiB 并跨请求追加唯一页 → 无上限 original-N.pdf 与 original_paper_pages → 累积页成为分析输入 → POST /api/cards/:cardId/knowledge-points/analyze → 读取全部页、base64 编码、序列化整数组 → 所有页及 JSON 同时分配 → 可超过 V8 堆 → 共享磁盘耗尽或 Node 终止。

普通教师通过正常认证上传 API，可消耗超出 grade:write 预期权限的资源。Multer 单文件 50 MiB、最多 40 文件，单请求约 2,000 MiB。函数从最大现有页号后分配，每页独立命名，后续请求累积而非替换；PDF 不压缩直接复制。可执行验证使用真实登录/HTTP：匿名上传 401，默认教师两次各上传 40 个一 MiB PDF，产生 80 行、80 文件、83,886,080 持久字节。可选多模态路径把全部页读成 base64，再 JSON 序列化；对生产端点使用特意限制为 128 MiB 的堆测试，未等任何外部 LLM 响应即以致命 OOM 终止 Node。最强反向证据为回环、认证与 grade:write、每文件/请求有限、显式删除端点、演示崩溃用了受限堆。这些并不能决定性否认可达性或磁盘问题：文档/脚本通过 Nginx/Cloudflare 暴露回环端口，默认教师有权限，40×50 MiB 仍是极大许可，重复请求无累计配额，删除是事后授权操作而非自动预防。AI 配置和默认堆精确阈值依部署，但持续磁盘增长不依赖 AI，已直接复现。

## 发生可能性

**高。** 文档生产 HTTP 接口，只需默认教师，无竞态或专门解析器利用，已通过认证和生产路由复现。明确支持 Nginx/Cloudflare 公网部署。磁盘增长无需 AI，可无限重复。实际上游请求限制、磁盘与堆依部署，但仓库未确立有效限制。**攻击向量：远程网络。**

## 影响程度

**高。** 可消耗应用持久卷，干扰全部用户的上传、扫描、判分和数据库依赖操作。多模态分支可经 base64/JSON 累计分配终止共享 Node。未证明直接泄密或成绩完整性失陷，限于一个部署服务，因此为高可用性损失而非严重系统失陷。

## 假设条件

- 生产认证保持开启。
- 攻击者控制普通教师或等价带默认 grade:write 的账号。
- 安装使用文档 HTTPS 代理/Cloudflare，使回环 Node 远程可达。
- 仓库外代理请求大小或文件系统配额没有施加显著更小总量限制。
- 可选堆耗尽分支需要配置多模态 OpenAI 或 Gemini；持续磁盘耗尽不需要 AI。

原文另列前提：

- 有 grade:write 的有效默认教师会话。
- 有效或教师创建的答题卡 ID。
- 磁盘耗尽需重复 multipart 上传。
- 堆耗尽需配置多模态提供商并调用知识点分析。

## 控制措施

- PROJECTX_AUTH_ENFORCE 开启时需认证，验证确认匿名 401。
- /api/cards 写操作经 cardGate 要求 grade:write。
- Multer 单文件上限 50 MiB。
- Multer 单请求最多 40 文件。
- 文件验证拒绝不支持扩展名和超大单文件。
- 页号分配/数据库插入有事务，防止重复编号竞态，但不防资源累积。
- 授权删除端点可删单页或全部页。
- Node 监听 127.0.0.1，但文档代理/隧道提供远程可达。
- CORS 允许列表不是针对直接认证 HTTP 客户端的服务端防御。
- 未发现仓库层总上传字节、单卡累计页数/字节或试卷路由限流。

## 盲点

- 检出代码无法确定特定部署外部 Nginx/CDN/Cloudflare/WAF 是否有小于约 2,000 MiB 的请求上限。
- 空闲磁盘、文件系统配额、进程监管和重启行为依部署。
- 堆崩溃用 --max-old-space-size=128 证明，默认 Node 堆所需页数依版本/配置。
- 多模态内存分支需 OpenAI/Gemini，独立证明的持久磁盘分支不需。
- 为限制消耗，验证使用一 MiB PDF，未提交完整 40×50 MiB 请求。
- 删除端点允许手工清理，但静态证据不证明监控或运维攻击响应时间。

async function getPaperFiles(cardId: string): Promise<Array<{ mimeType: string; base64: string }>> {
  const dir = paperDir(cardId);
  const files: Array<{ mimeType: string; base64: string }> = [];
  let entries: string[] = [];
  try { entries = await readdir(dir); } catch { return files; }

  const imgRe = /^original(-\d+)?\.(jpg|jpeg|png|bmp|tiff|webp)$/i;
  const pdfRe = /^original(-\d+)?\.pdf$/i;

  // 所有页的图片（按页码排序）
  const imgEntries = entries.filter((e) => imgRe.test(e)).sort();
  for (const e of imgEntries) {
    const fp = path.join(dir, e);
    const buf = await readFile(fp);
    files.push({ mimeType: getFileMime(e), base64: buf.toString("base64") });
  }
  if (files.length) return files;

  // 回退：所有页的 PDF
  const pdfEntries = entries.filter((e) => pdfRe.test(e)).sort();
  for (const e of pdfEntries) {
    const fp = path.join(dir, e);
    const buf = await readFile(fp);
    files.push({ mimeType: "application/pdf", base64: buf.toString("base64") });
  }
