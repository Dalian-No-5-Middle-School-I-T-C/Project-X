## 概要

**由本次变更引入。** 基线成绩路由没有学生可调用并触发外部 LLM 的操作。本提交新增学生 AI 路由，将每个接受请求直接转发 /analysis/run，无限流、配额、缓存或在途并发上限。

新 POST /api/scores/me/exams/:examId/ai-analysis 只由普通认证和“调用者在所选考试有成绩”检查保护。通过可重复使用的检查后，学生可无限次、并发提交，并选择任意已配置模型。每次转发到辅助服务，超时 120 秒。每次分析可发生最多八次计费提供商往返，每次允许 4096 输出 token。UI 本地 generating 标志不是安全控制，因为可直接调用 API。一个合法学生因此能消耗学校模型额度或产生大量费用，并占满辅助服务工作池和 Node 未完成请求容量，使学校 AI 分析不可用。内部 Bearer 密钥不提供逐用户限制，因为 Node 是可信调用者。此精确版本还使用与已有 LLMCLIENT_* 不同的环境变量，正确配置内部认证时可能 401；但辅助服务内部密钥未设时明确接收请求，默认配置允许，且修复名称不匹配也会激活同一无界路径。应添加逐用户/IP 配额、全局有界并发、去重/缓存，最好还有显式授权和费用统计。

## 验证

1. 有成绩的认证学生可经生产组合到达 POST；生产挂载静态确认，精确认证/成绩路由经 HTTP 执行。
2. 每个接受请求在并发下启动独立 /analysis/run，无适用限流、配额、去重、缓存或全局在途上限；12 请求产生 12 同时调用。
3. 可控模型传入辅助服务/提供商，一次分析可按声称 token 上限重复调用；gpt-5.5-pro 被转发，真实循环产生 8 次 max_tokens=4096 调用。
4. 确立认证/配置前提：实际 FastAPI 测试确认未设密钥接受、设置后缺 Bearer 拒绝，源码确认变量名不匹配。
5. 经有界现实接口证明行为，不联系外部提供商即评估可信费用/容量影响；HTTP 并发与确定性提供商循环复现成功。

## 证据注释

1. 直接调用的辅助实现每请求最多八次外部提供商迭代，每次 max_tokens=4096。
2. 成绩路由需认证，但无 AI 专用限流或更强能力门禁。
3. 新学生路由只作可复用 hasScore 检查，每调用启动新的 120 秒请求，接受自选模型，无配额/并发控制。
4. 提供商结果直接返回，下一次请求前无缓存、去重、统计或冷却。

## 攻击路径分析

普通学生每请求最多放大为八次计费操作并占用请求最多 120 秒，产生全校费用/额度及可用性影响，故影响高。直接认证 HTTP 循环，无竞态、枚举、特权、受害者交互或长推测链；PoC 十二个并发接受请求及十二个同时辅助调用，故可能性高。回环和变量不匹配是最强反证，但降低部署普遍性而非使利用难达：给定模型包含 Node 远程暴露，未设密钥运行明确受支持。矩阵为高危而非严重，限单实例费用/可用性，无管理员接管、执行代码、数据库失陷或改分。

### 路径

有一条考试成绩的认证学生 → 任意多顺序/并发 POST → Node:5174 学生 AI 端点 → 有任意成绩即接受 → 可重复 student_scores 存在检查 → 每次独立转发，自选模型、120 秒超时 → 回环 8766 Python /analysis/run → 解析已配置模型，最多八次每次 4096 token → 用学校 API 凭据调用外部模型 → 消耗计费资源、长期请求消耗应用容量 → 提供商费用/额度与 Node/辅助可用性耗尽。

一个合法有成绩学生能自动调用正常端点，每 POST 触发一条可信辅助请求。路由在教师 analysisGate 之前挂 /api/scores，只需普通认证加 ScoreRepository.hasScore，接受自选模型并等待最多 120 秒。run_analysis 的 OpenAI 兼容路径允许八次迭代，每次 4096。无适用限流、配额、缓存、请求合并、冷却或并发上限。生产认证/成绩路由加不计费模拟辅助服务的验证中，十二并发全部成功且同时转发；匿名/无成绩对照为 401/403。另一个复现替换网络客户端、执行真实循环，观察到八次 4096 调用。最强反证是配置可达性：Node 与文档辅助命令回环监听；此路由读取 LLM_CLIENT_URL/LLM_INTERNAL_KEY，而既有集成与辅助用 LLMCLIENT_URL/LLMCLIENT_INTERNAL_API_KEY。正确非空辅助密钥因此使该精确路由在修复前 401。但并非不可达：空密钥明确支持，模型含远程 Node，仅修名称不加限制就激活无界路径。学生不会获得提供商秘密；问题是借可信服务计费与执行权进行未授权放大。

## 发生可能性

**高。** 启用学生端部署和可选 AI 后，只需普通会话、一条合法成绩、简单重复/并发 HTTP。验证十二路一对一转发均接受。回环与密钥变量问题是限定，但并非不现实阻碍：模型含代理、未设密钥受支持、只修名称即仍可利用。**攻击向量：远程网络。**

## 影响程度

**高。** 每低权限请求启动新可信分析，可挂起 120 秒，并最多八次各 4096 输出 token。无限并发消耗学校额度/费用，占用 Node 请求与辅助线程拒绝 AI 流程。影响他人和学校资源，不限本人。未证明泄密或改分。

## 假设条件

- 学校让学生在校网直接或经模型所述代理/隧道访问 Node。
- 可选 Python 辅助运行，至少配置一个提供商模型和有效 API key。
- 内部密钥按支持的本地方式未设，或修正 LLM_CLIENT_*/LLM_INTERNAL_KEY 不匹配但未同时限流。
- 提供商使用计费或有限额度，重复调用能耗费。

原文另列前提：

- 有效低权限学生会话。
- 所选考试至少一条 student_scores。
- 已运行、配置提供商的辅助服务。
- 辅助认证接受请求：内部 key 未设或转发配置对齐。
- 可访问学生 Node API。

## 控制措施

- authMiddleware 缺失/无效会话 401。
- hasScore 限定有成绩考试，否则 403。
- 辅助只接受已知配置模型，无提供商 key 则拒绝。
- 120 秒限制单次 Node 等待，不限制请求数/总并发。
- 内部 key 可保护直接调用者，不能在可信 Node 转发时逐学生限额。
- UI 生成中禁按钮，不是后端控制。
- Node/辅助默认回环，远程学生需预期代理/隧道或本地应用访问。

## 盲点

- 无代理、Cloudflare、负载均衡、网络政策清单；公网性依给定部署模型。
- 仅设置既有非空 LLMCLIENT_INTERNAL_API_KEY 的部署，当前此路由因读错变量返回 401。
- 并非每实例启用辅助/凭据。
- 验证未联系真实提供商、产生费用或持续生产中断；外网调用用桩证明放大及并发。
- 八次复现是反复工具调用导致的可达上限，不是每次响应预计次数。
- 实际价格、额度、Node 连接、辅助线程、上游代理与提供商限流不在仓库资料。
- 缺依赖未动态加载完整生产 index；挂载顺序静态验证，真实认证/成绩路由经 HTTP 框架执行。

/** POST /api/scores/me/exams/:examId/ai-analysis — 学生单场考试 AI 分析（绕过教师端 analysisGate） */
router.post("/me/exams/:examId/ai-analysis", async (req: Request, res: Response) => {
  const examId = Number(req.params.examId);
  if (!Number.isFinite(examId) || examId <= 0) {
    res.status(400).json({ message: "无效的考试 ID" });
    return;
  }
  if (!scoreRepo.hasScore(req.user!.id, examId)) {
    res.status(403).json({ message: "你未参加该考试" });
    return;
  }

  try {
    const controller = new AbortController();
    const timeout = setTimeout(() => controller.abort(), 120_000);
    const response = await fetch(`${LLM_CLIENT_BASE}/analysis/run`, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        ...(LLM_INTERNAL_KEY ? { Authorization: `Bearer ${LLM_INTERNAL_KEY}` } : {}),
      },
      body: JSON.stringify({
        examId,
        model: typeof req.body?.model === "string" ? req.body.model : undefined,
        locale: "zh-CN",
      }),
      signal: controller.signal,
    });
    clearTimeout(timeout);

    if (!response.ok) {
      let message = `LLM service returned ${response.status}`;
      try {
        const body = await response.json() as { detail?: string; message?: string };
        message = body.detail || body.message || message;
      } catch {
        const text = await response.text().catch(() => "");
        if (text) message = text;
      }
      res.status(response.status >= 400 && response.status < 500 ? response.status : 502).json({ message });
      return;
    }

    res.json(await response.json());
