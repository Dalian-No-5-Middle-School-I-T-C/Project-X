## 1. 任务一句话

在扫描端（Electron，分支 `扫描端微调`）新增「扫描后处理页」：每批扫完自动进入，页头右上角分段控件切三个视图——扫描结果（小方块网格/列表/多选删除）、卡查看与改分（左卡图点选 + 右 Web 同款成绩表格，并存不切换）、异常处理（队列式：考号/重卡/缺页/存疑四类 + 兜底），处理完自动补传。

## 5. 视觉红线（demo 视图 8 + DESIGN-SYSTEM）

- 网格 `repeat(auto-fill,minmax(128px,1fr))`、`gap-3`、缩略图 `aspect-[3/4]`、恒白纸面（`bg-paper`/`bg-muted` 中性底托）；异常卡 `ring-2 ring-destructive` 置顶。
- 分段控件用 `SegmentedControl`（label 可放 ReactNode，异常计数用内嵌 `Badge`）；表格用 `Table*` 家族（数字右对齐 + `tabular-nums`，禁斑马纹）；危险确认只用 `ConfirmDialog tone="danger"` 且文案说清代价。
- 一屏主按钮 ≤1；`Button` 必须传 `loading`；图标只 lucide-react；禁 emoji 功能图标。
- 禁新建 CSS 文件、禁手写业务 CSS、禁 `--px-*` L1 原始令牌进业务代码；颜色只写语义类。
- 密度：扫描端已全局 `data-density="compact"`（`ScannerApp.tsx:51-54`），**不要写死控件高度**。
- 验收眯眼测试：品牌红只应出现在主按钮/选中态/异常强调。

## 7. 施工协议

1. 严格按 plan 的 Task 1→11 顺序；每个 Task 内的 Step 顺序（先红后绿再 commit）。
2. 每 Task 结束：`npm run typecheck`。Task 3/4 后加跑对应 verify；Task 10/11 后跑 `npm run build:scanner:full`。
3. commit 粒度 = Task（plan 已给 commit 命令与消息风格）；**只 add 该 Task 的文件**，不要 `git add -A`（工作区有垃圾文件与遗留改动）。
4. SQL：本功能新增 SQL 仅 `listActiveReceiptGroups` 一条普通 SELECT（双方言安全）；不要引入方言函数。
5. 上传镜像（Task 6 `queueGroupUpload`）必须保留 `getCorrection` 遇 409 返回 `undefined` 的语义（旧卷无坐标快照）。
6. **通道裁定（施工期已复核定稿）**：后处理页只有本地通道，**不要 reintroduce `remoteChannel`**——本页的本地 TWAIN sessionId 与上传端点的 `job.remoteSessionId` 不通，且 `requestJob` 对已收尾 job 直接 reject「上传任务已关闭」（`scannerUploadManager.ts:551-556, 897-899`）。远端语义只经 `queueGroupUpload`（startUpload 自建会话）承担；删除端点只有本地有，远端模式删除 = 删本地留档，ConfirmDialog 文案已覆盖。
7. **补传护栏（顺序不可调换）**：① 本地模式不上传；② 组已有上传 job → 复用（失败页 `retryFailed`），不新建会话；③ 加载时已上传/已入库 → 不重传，提示走 Web 成绩修改；④ 其余才首传。原因：重复学号二次回执会 conflict → `withdraw()` 删 `student_scores/question_scores` 并把考试打回阅卷态（`scannerSubmissions.ts:121-141`）。`uploadedAtLoad` 基线必须每次 `reload()` 后刷新。
8. `examId` 为 null（卡未绑考试）时花名册联想降级为纯手输 + 「不在名单」提示，不报错。
9. 真机 TWAIN / 扫描仪 / Linux 服务端联调**不在承诺范围**：交付说明里如实写「已完成：typecheck/build/冒烟/隔离数据手工验收；未覆盖：真机扫描与远端联调」。
