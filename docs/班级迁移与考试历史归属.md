# 班级迁移与考试历史归属

正常花名册中，一名学生只有一个有效在读班。高一选科分班、升高年级或个别调班使用现有“移班”操作；批量导入仍为增量补充，不根据重复学号自动删除其他关联。

## 管理操作

1. 建立目标班级及其所属年级。
2. 用“移班”把学生从原班转入目标班。学生账号及学号保持不变。
3. 原班或原年级不再使用时归档，保留历史考试、成绩和教师关联。也支持先归档旧班，再加入新班。
4. 新考试设置新的班级或年级范围；尚未设置名单、尚无成绩的草稿考试不在移班时提前冻结。

“加入班级”及 CSV 重导入保持增量语义。已有多班数据无法仅凭关联行判断是否误留，因此不会自动清理；确认属于调班时明确移出原班。

## 统计口径

- `exam_class_memberships` 保存考试、学生、班级的不可变快照。首次录入成绩或设置显式名单时保存；移班、退班、增量加入和归档前也会保存已有考试的归属及需要保留的应考名单。
- 历史小考及大考分析、成绩表、导出、逐题下钻、成长曲线和网阅班级筛选使用考试时的班级。重算成绩、补录缺考成绩、重新设置名单不会改写已保存的班级。
- 新的年级考试排除已归档班级；班级范围明确指定旧班的历史考试仍使用旧班。无班级时以 `class_id=0` 记录“未知班级”，避免以后入班反向改变旧考试。
- 遗留多班成员在各班统计中各计一次，全体人数与年排按学生去重。大考各科直接使用各科快照；组总分使用该生在组内排序中首个有成绩考试的班级集合，避免跨调班的考试组把该生同时计入新旧班。显示班级仍只选其中一个。
- 新旧班级名称来自原班级记录；这不是班级名称、教学分科或教师任职的完整历史版本系统。

## 数据升级与边界

SQLite 和 MariaDB 的 v59 迁移只增加快照表与索引，不删除班级关联、不修改成绩、不猜测升级前已经丢失的班级历史。尚未保存快照的旧数据继续读取现有花名册，下一次班级变动前保存可恢复的归属。此前已移班且原关联已删除的数据，需要原名册等可信记录才能恢复。

专用回归：`npm run verify:exam-class-memberships`；MariaDB 变体：`npm run verify:exam-class-memberships:mariadb`。后者只允许连接本机空的一次性库 `projectx_exam_classes_test`，CI 使用 MariaDB 10.11。
