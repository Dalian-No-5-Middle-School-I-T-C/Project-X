# PR #276 扫描失败恢复与双面配对复核

2026-09-12；核对基线：`fix/end2end`，`826e548`。本轮仅修改与验证工作区，没有发布生产服务。

## 三条意见的核对结果

1. **批量异常中断属实。** 原来的汇总接口在某名学生判分或保存失败后重新抛错，后续学生不会处理。还存在两个相关问题：识别 JSON 的解析在逐学生异常处理之外；只要出现任何成功缓存，下次请求就提前返回缓存，失败项被遗漏。
2. **“两个 pump 并发上传”不符合当前代码。** 当前全局队列和任务内页循环均为串行。但真实纸张配对确有问题：TWAIN 的同张纸正反面共用 `pageNum`，数据库按 `page_num, side` 排序会把 `back` 放在 `front` 前；旧上传逻辑依赖数组相邻项，也没有处理跨纸张的多页答题卡布局页码。
3. **AI 不可达返回值不一致属实。** 教师和学生 AI 面板实际读取 `available`，没有发现仅凭 `defaultModel` 非空误判可用的当前调用路径。不可达分支仍统一改为 `defaultModel: null`。

## 修改后的操作流程

- 扫描结束后先汇总，列出成功与失败答题卡；汇总本身不写考试成绩。
- 老师可以查看失败图片、填写订正学号并重新识别这一份；缺页、错页或图像损坏需要整理原卷后重扫整份。
- 点击“保存成功部分”时，每份答题卡独立保存，某份失败会保留原因并继续保存其他学生。
- 再次汇总不会因部分成功缓存而漏掉失败项。补存时跳过内容相同的已保存结果，避免重写已保存学生后来调整过的成绩。
- 远程模式按完整答题卡分别加入上传队列，一名学生的上传失败不会挡住其他学生提交。失败上传仍使用原有“重试失败页”入口续传。

GET `/api/scanner/session/:sessionId/results` 现在返回 `{ results, failures }`；同路径 POST 执行明确保存。新增 POST `/api/scanner/session/:sessionId/retry` 处理失败卡的重新识别和学号订正。客户端与其本机服务端应一起更新。

## 配对与原生识别边界

共享映射按物理纸张编号、面和布局页数确定整份答题卡。正面优先排序，上传任务创建时固定首页依赖，重试和慢网络不会改变依赖关系。缺页、重复页、同份卡学号冲突以及同一学号重复出现多份卡会进入失败列表，不自动合并或保存残缺成绩。

三页等跨纸张答题卡使用真实布局页码调用原生 OMR，后续页依赖同份答题卡首页。首页未完成时，背面不会消耗定时重试预算；首页失败后，其他答题卡继续，人工重试时先恢复首页再恢复依赖页。

界面验收还复现了原生识别器的“仅学号失败”：答案已经识别，整体状态仍为 `failed`。人工订正或可靠的同卡继承只恢复明确的 `Student ID recognition failed.`，并要求有定位点质量数据。定位失败、图像读取失败和缺少质量依据的结果仍保持失败。没有修改 C++ 算法。
