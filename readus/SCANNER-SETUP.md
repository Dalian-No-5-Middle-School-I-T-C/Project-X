# Project-X 扫描端使用指南（Windows 桌面版）

> 适用版本：v2.4.1 及以上。安装包形如 `答题卡扫描端-2.4.1-ia32.msi`（32 位，兼容老旧扫描工作站）。
> 扫描端是**独立的 Windows 桌面应用**：自带内嵌服务与本机数据库，扫描、识别、判分全部在本机完成；可选连接主服务器上传阅卷结果。

## 一、安装

1. 双击 MSI 安装包，按提示完成安装（按用户安装，无需管理员权限）。
2. 安装后桌面与开始菜单出现「答题卡扫描端」快捷方式。
3. 原生识别引擎（OMR）与 TWAIN 扫描桥均已随包内置，无需额外安装组件。

## 二、首次启动会发生什么

1. 应用自动拉起内嵌本地服务（`127.0.0.1:5174`，端口被占用时自动换随机端口，无需手动处理）。
2. 本机数据库自动初始化，位置：
   - 数据库：`%APPDATA%\answer-card-designer\data\projectx.db`
   - 答题卡 / 原卷 / 扫描件：`%APPDATA%\answer-card-designer\data\answer-card\`
3. **首次进入会强制选择界面风格**：明澈 Flat 2.0 与纸锋 Paper Edge 二选一（大预览卡片），必须选定后才能进入登录页。该选择保存在本机并会在登录后同步到账号偏好。

## 三、账号登录

| 项 | 说明 |
|---|---|
| 初始账号 | `admin` |
| 初始密码 | 一次性随机口令，写在数据库同目录 `bootstrap-admin.txt`（首次启动时生成；**首次登录会强制要求修改密码**，改密后该文件自动删除）。详见 [管理员引导口令与升级说明](ADMIN-BOOTSTRAP-PASSWORD.md) |

- 扫描端的账号体系是**本机独立的**，与主网站的账号互不相通——主网站的管理员无法直接登录扫描端。
- 登录后请在「用户管理」中创建教师账号供日常使用。
- ⚠️ 若扫描端暴露在公共网络，请登录后立即修改 admin 密码（系统有登录限速兜底：15 分钟内最多 10 次尝试）。
- 忘记 admin 密码时按账号状态分两种处理：
  - **尚未完成首次改密**（仍处引导态）：删除数据目录下的 `bootstrap-admin.txt` 后重启应用，系统会换发一个**新的**随机口令并重新写入该文件，读文件登录即可（数据不受影响；此前的随机口令当场失效）。
  - **已改过密码且无法重置**：关闭应用，将 `%APPDATA%\answer-card-designer\data\projectx.db` 改名备份后重启，会重建一个全新库并按引导态发新口令（注意：本机已有答题卡与成绩会随旧库一起"消失"，需要时可用备份文件恢复）。
- ⚠️ 当前版本起不再存在任何固定初始口令（历史上曾公开写为 `admin123`）。任何文档、脚本或 CI 里残留的 `admin123` 都不再可用，请改读引导文件或设置 `PROJECTX_ADMIN_PASSWORD`。

## 四、连接主服务器（可选）

不配置也可以完整使用：单机即可完成扫描与阅卷。配置后可将阅卷结果上传到主服务器统一管理。

1. 先在**主服务器侧**开启远程扫描接入：设置环境变量 `PROJECTX_ENABLE_SCANNER_CLIENT_API=1` 并重启服务。
2. 在扫描端配置一把扫描端 API Key（`sk-xxx`，scope 为 `scanner`）。密钥来源二选一：
   - 主服务器初始化时自动生成「默认扫描端密钥」，其**明文只写入服务器数据目录下的 `scanner-api-key.txt`**（与数据库同目录，仅首次生成时写入）；
   - 或由管理员在主网站管理后台重新签发一把新 Key（签发时明文仅显示一次）。
3. 扫描端登录页展开「服务器连接（可选）」，填入：
   - 服务器地址：**跨机部署请用 `https://`**，如 `https://projectx.school.edu.cn`；本机自测可填 `http://127.0.0.1:5174`
   - API Key：上一步的 `sk-xxx`
4. 点「测试连接」：
   - ✅ 服务器可达 —— 地址通且远端已开启扫描客户端 API；
   - ✅ 「服务器可达，但 …… 是跨机明文 HTTP，未发送 API Key」—— 见下面第 6 步的明文口径；
   - ❌ 「服务器在线，但未启用远程扫描客户端 API」—— 检查第 1 步的环境变量；
   - ❌ 连接失败 —— 检查地址、端口与防火墙。
5. 点「保存配置」。此后扫描结果将上传到该服务器。
6. **跨机明文 HTTP 的口径（安全 R32）**：填 `http://192.168.x.x:5174` 这类跨机明文地址时，
   扫描端**默认不发送 API Key**，上传会以「配置错误」立即失败——因为这把 Key 能向服务器写入扫描结果，
   明文经过整个网段等于把它交给同网段任何人。两条出路：
   - **正式部署**：改用 `https://`（部署指南里的 nginx 配方已含证书与跳转）；
   - **隔离的内网测试环境**：在「服务器连接」里勾选「我确认这是隔离的内网测试环境，允许向该地址明文发送凭据」
     再保存。该许可**按 host:port 记录**，换服务器地址不会继承；改回 https 或回环后保存即自动撤销。
   本机 `127.0.0.1` / `localhost` 的明文地址不受此限（流量不出本机），单机模式照旧可用。
   不带凭据的健康探测始终放行，所以「服务器连接」指示灯仍能区分「服务器不可达」与「服务器可达但凭据被拦下」。

## 五、扫描与阅卷流程

1. 登录后在答题卡列表选择要批改的答题卡（单科考试与大考分属两个标签页）。
2. 进入扫描工作台。左侧首位是**「图片去向」**（v2.5.6 起常驻）：选择「仅本地」则图片与成绩只留在本机；选择「本地判分+上传服务器」则本地照常判分，图片与识别结果同时上传远端（未配置服务器时会给出提示与「去配置」入口）。该选择对下面的两种录入方式同时生效。
3. 录入方式二选一：
   - **TWAIN 扫描仪直扫**：先安装好扫描仪驱动，在工作台内直接发起扫描；检测不到数据源时**不阻止扫描**，可留空使用系统默认扫描仪或手工填写数据源名称。
   - **图片文件导入**：把提前扫好的图片文件批量导入。
4. 系统在本机自动完成识别与客观题判分（原生 OMR 引擎），进度实时可见，可中途取消。
5. 阅卷完成后可查看结果；「图片去向」为「上传服务器」时结果上传远端汇总分析。

> 登录页的「使用说明」按钮内置了操作帮助，遇到界面问题可随时打开查看。

## 六、常见问题

| 现象 | 处理 |
|---|---|
| 启动报 `Could not load the 'sharp' module ... win32-ia32` | 使用 v2.4.1+ 安装包（已内置全部 ia32 原生依赖）；旧包请重装升级 |
| 启动报 `EPERM ... C:\Windows\system32\data\...` | v2.4.1 前的已知缺陷，升级即可 |
| 点「检测/开始扫描」提示**桥接程序无法启动（0xC0000135，加载依赖 DLL 失败）** | **v2.5.5+ 安装包已把 VC++ 运行库随包分发**（随应用放在 `resources/native/win-ia32`、`resources/native/win-x64`），目标机**无需再单独安装**「Visual C++ 可再发行程序包」。若仍报此错，先确认安装目录下 `msvcp140.dll` / `vcruntime140.dll` / `concrt140.dll` 齐全（不齐=安装被精简，重装），齐全则多为**安全软件隔离**：把安装目录加入白名单后重试。注意该报错由 Windows 报告，不代表扫描仪或驱动有问题；期间可用「导入阅卷」导入图片判分 |
| 点「检测/开始扫描」提示**桥接程序在访问 TWAIN 设备时崩溃** | 多为扫描仪驱动与 32 位进程不兼容或驱动损坏：重装/更新扫描仪驱动；期间用「导入阅卷」方式判分 |
| 点「检测」提示**未检测到扫描仪** | v2.5.5+ 起该提示附带**可展开的技术细节**（TWAIN DSM 加载路径与搜索记录、OPENDSM 返回码、条件码、进程位数、桥接退出码），并可点**「复制诊断」**一键复制反馈（无需翻日志）。常见原因：驱动未安装、**32 位驱动与 64 位进程位数不匹配**（老旧扫描仪多为 32 位驱动，须用 ia32 安装包）、或数据源被其它 TWAIN 程序独占 |
| **检测失败就完全没法扫描**（设备在厂商软件里能扫） | v2.5.6 起**检测失败不再阻止扫描**：扫描设置与「开始扫描」始终显示，「扫描仪数据源名称」可留空（留空则由桥接改用系统默认数据源），也可手工填入厂商软件中显示的数据源名称。旧版请升级 |
| 扫描推进到某张后长时间不动 | 在工作台「扫描设置」中调整**等纸超时（秒）**（默认 15 秒，可设 2–120）：老机器进纸慢可调大，调小可更快跳过空位 |
| 重传旧扫描页时提示**「该扫描会话已完成，页面不可再改写」**（HTTP 409） | 2026-10-04 起的安全收紧：会话一旦完成，其上传令牌即失效，不能再覆盖已入库的图片与成绩。**新建一次扫描会话**重扫即可，已入库成绩与其阅卷切图的归属不受影响 |
| 上传被 **400 / 413** 拒绝 | 按上限处理（单一来源 `src/shared/scanUploadLimits.ts`）：单个会话最多 200 页；扫描页单张 50 MiB；题块切图单次最多 50 张、单张 12 MiB、一次请求累计 160 MiB；导入阅卷单次最多 300 张、累计 1 GiB。降低 DPI/分辨率或分批上传即可。其中「一次请求累计字节」超限会返回 `UPLOAD_BUDGET_EXCEEDED` 并在提示里写明上限，其余档位只给通用的超限文案。**这些是默认值而不是写死的数**：整套批量确实超限时，管理员可用 `PROJECTX_UPLOAD_MAX_SESSION_PAGES`、`PROJECTX_UPLOAD_MAX_BATCH_TOTAL_MIB` 等环境变量在服务端放宽（体积按 MiB 填），每档都有安全天花板，超出会被夹紧；改完重启后看启动日志 `[upload-limits] …` 一行确认实际生效值，详见 README「API 接口一览」下的上传限制说明 |
| 点「复制诊断」毫无反应，或粘贴出来不是诊断内容 | 2026-10-05 前的扫描端安装包有这个问题：壳的权限策略（安全 R23）对设备能力一律默认拒绝，写剪贴板也被一起拒掉。现在只对**壳自己加载的那个来源**放行「写剪贴板」（读剪贴板仍然全拒），并且 Clipboard API 被拒或不可用时自动退回隐藏文本框选中复制；两条路都不通时按钮不再显示「已复制」（评审 P2-7） |
| 连续翻看多张原卷/切块图后，回看最早那一张变成占位图 | 资源票据每账号有存活上限（默认 8 张，服务端 `PROJECTX_MEDIA_TICKET_MAX_PER_USER`），此前客户端不限存、服务端会驱逐最早过期的那张，回看就命中已失效的票据。现在客户端按同一上限与同一驱逐策略缓存，图片加载失败时还会对那一个地址重签一次（评审 P2-3） |
| 安装目录用 junction/挂载点指到别的盘后，提示未检测到扫描仪（DSM 被判为不在安装目录内） | 2026-10-05 前只比较逻辑路径，合法 junction 会让随包 `twaindsm.dll` 被当成外部 DLL 而拒绝加载。现在安装目录与 DLL 都先解析成真实路径再比（评审 P2-6）；DLL 自身解析失败仍然拒绝加载 |
| 导入阅卷/识别提示图片尺寸非法，但图片本身正常 | 位图规范允许负高度（top-down 行序），此前按无符号读取会把 `-3000` 当成 4294963000 而判成伪造头并拒绝，现已按有符号读取（评审 P2-5）；对伪造尺寸的防护不变 |
| 登录页样式与预期不符 | 清除浏览器数据不适用——检查是否首次进入被引导层拦截，二选一确认即可 |

## 附：维护者打包备忘（开发者向）

- 打包命令：`npm run electron:msi:ia32`（MSI）/ `electron:pack:ia32`（目录）/ `electron:dist:ia32`（便携版）。脚本已自动串联：构建 → better-sqlite3 ia32 重编译 → sharp ia32 二进制补齐 → **VC++ 运行库落位** → electron-builder。
- VC++ 运行库由 `scripts/stage-vc-runtime.cjs`（`npm run native:runtime[:ia32]`）从本机 VS 安装中提取，落地到 `resources/native/<arch>/`，随后由 `extraResources` 整目录带入安装包（app-local 部署，免管理员权限）。因此 `resources/native/win-ia32`、`resources/native/win-x64` 下的 `msvcp140*.dll` / `vcruntime140*.dll` / `concrt140.dll` **属于随包资产，必须提交到仓库**。
- 打包机建议设置镜像变量加速下载：`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`、`ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/`。

## 重复学号与保存状态

Windows 扫描端执行扫描及原生识别；Linux 服务端接收原图和识别结果，校验答题卡完整性并判分入库。远端不执行 OMR。

“已保存”需要主库成绩及对应考试、原卷的入库凭据；仅有汇总缓存不算入库。学号未匹配、未关联考试或不在应考名单时会显示失败，修正后可重新保存。

同一考试出现重复学号时，不合并多份卷的较优答案，也不覆盖旧成绩。新旧卷一并显示待核对；已入库的总分和逐题分数撤出，原图、识别结果和成绩快照保留，排名重算，考试恢复未公布状态。订正后需要明确重新保存，旧卷不会自动恢复。重复提交同一原卷不算重复学号。

历史数据优先核对缓存、原卷及逐题成绩，能够唯一确认的来源会补登记。无法确认来源的历史成绩显示快照及匹配的历史图片，需人工核对、订正后恢复。

数据库迁移 v49 为 SQLite 和 MariaDB 增加 `scanner_submissions` 入库凭据及冲突证据表；不会在迁移时批量撤出已有成绩，校验相关扫描会话时才核查处理。
