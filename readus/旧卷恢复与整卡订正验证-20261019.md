# 旧卷恢复与整卡订正验证

日期：2026-10-19；基线为 `7401c62`，验证对象为本次修复分支。

## 修复内容

历史卷补识别保存后，坐标快照已有当前版式，但会话版本仍为空。异常卷列表曾只检查会话版本，持续显示版本错误；有坐标的旧快照还会失去重新核验入口。

v64 为订正快照增加 `recovery_fingerprint`，在签名补识别、教师核对并保存后，绑定该页的原图完整字节、页序、识别数据、版式及订正快照。异常卷列表、确认入库和后续订正使用同一校验。已有旧快照可重新核验，并保留同版式下先前教师保存的填涂修改。已保存的恢复记录跨服务重启有效，后续人工改分同步更新记录。

恢复仅适用于当前原卷；会话的未知版本保持原状，其他卷需分别核验，普通上传完成接口继续拒绝未知或过期会话版本。原图替换、签名修改、过期确认和版式不符继续拒绝。

完整操作中还发现：一份重复卷订正后，另一份从未入库的卷转为 `pending`，却因没有撤出成绩快照被网页过滤。列表现保留全部待保存卷，显示为“待订正保存”，可继续核验并保存。

本次同时包含扫描端未同步本机考试时的整卡访问修复，以及网页异常卷列表滚动修复；对应背景与验证记录见 [整卡改分说明](整卡改分说明.md)。

1. Windows Edge 登录并打开成绩分析，三份卷均可见，旧快照显示重新核验入口。
2. 名单外卷调用 Linux 补识别成功，二维码通过，原图尺寸为 2480×3508；保存返回 200，版本提示消失，“确认加入名单并入库”可用。同会话另两份卷仍需核验。
3. 重启服务容器，重新登录并打开此卷：坐标及恢复状态保留，无需重新补识别。确认名单后该卷入库。

5. 补识别并保存剩余 12346，异常列表清空。分析页显示实考 3 人、均分 5、最高与最低均为 5。
