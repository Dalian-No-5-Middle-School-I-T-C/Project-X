# 答题卡二维码校验与方向纠正

每页页眉使用 18 mm 黑白二维码替换原六个小方块，保留可读 ID 和两侧定位条。预览和 PDF 由同一矩阵绘制；二维码包含四模块白色静区，打印时不要裁掉或涂写。

## 扫描与导入

- 默认严格校验卡 ID 和页码。缺码、不可读、错卡、错页、协议错误或二维码冲突会阻止该页判分和上传，保留原图供检查。
- A4、A3 支持横置和倒置的方向纠正。二维码辅助确定方向，原有定位条负责整页透视校正；不会按二维码自动切换卡或重排页面。
- 已打印的旧卡，可在扫描或导入前勾选“兼容旧卡”。该选择只作用于本次任务，重试沿用，新任务恢复严格模式。兼容模式只放宽缺码/不可解码；读出的错卡、错页仍被拒绝。界面持续提示未校验卡 ID。
- 多页按原有顺序扫描/导入。导入工作台通过 `pageOrder=sequential` 按文件顺序循环预期页码，二维码用于核对该顺序；单页识别 API 仍使用显式 `page`。
- 同份卡有失败页时不能作为完整成绩提交。人工填写学号不能覆盖二维码拒绝。重新识别前清除旧识别缓存和切块；已有保存回执的成绩按所属回执撤回，需识别成功后重新保存。

## 接口与升级

载荷格式：`PXAC:1:<encodeURIComponent(cardId)>:<pageNumber>`，页码从 1 开始。当前不含版式版本或学生身份，也不用于验证上传端是否可信。

识别与扫描请求使用 `identityMode: strict | legacy`，缺省 `strict`。原生 CLI 对应 `--identity-mode`。JSON 结果新增 `identity`（`status`、`code`，解码成功时有 `cardId`、`pageNumber`）；`quality.rotationDegrees` 表示施加的顺时针纠正角度。

SQLite 和 MariaDB 的迁移 51 增加会话 `identity_mode` 与扫描记录 `identity_json`。旧记录没有校验证明，不能直接重新提交，需要在 Windows 扫描端重新识别。服务端仍只接收本机识别结果，不执行 OMR。

Windows 扫描端的 Node 层与原生程序需要配套升级；旧程序缺少身份校验能力时明确报错，不降级放行。发布前分别运行：

```text
scripts\build-answer-card-recognizer.bat x64
scripts\build-answer-card-recognizer.bat ia32
npm run verify:card-identity
npm run verify:recognizer-layout
npm run build
npm run build:scanner:full
```

`ANSWER_CARD_RECOGNIZER_EXE` 可指定待测 x64/ia32 程序。`scripts/scanner-batch-results-smoke.ts` 覆盖保存、上传和失败重试；其文件头说明如何切换到一次性 MariaDB 数据库。二维码验证使用合成扫描图，仍须用实际打印件和扫描仪验收。
