# 虚拟扫描仪验证

Project-X 可以使用 [TWAIN 官方软件扫描仪](https://github.com/twain/twain-samples)验证 Windows 扫描桥。数据源名为 `TWAIN2 Software Scanner`，从图片生成扫描帧，提供 ADF 和色彩能力。当前官方样例声明 `CAP_DUPLEX=TWDX_NONE`，可用于验证不支持双面的设备被安全拒绝。

## 安装与运行

1. 下载[官方 v2.5.0 完整发行包](https://github.com/twain/twain-samples/releases/tag/v2.5.0)中的 `Twain_sample01_02050000.zip`，解压后安装所需位宽的 `twainds.win32.installer.msi` 或 `twainds.win64.installer.msi`。如已安装旧样例，先卸载旧样例再安装。旧仓库 `releases/Twain_Ds_sample01_02040100` 的 MSI 缺少 Qt 平台插件，请使用完整发行包。
2. 确认对应目录中存在数据源和插件：32 位位于 `C:\Windows\twain_32\sample2`，64 位位于 `C:\Windows\twain_64\sample2`，插件为 `platforms\qwindows.dll`。
   x64 样例的 `FreeImage.dll` 还依赖 `VCOMP140.DLL`；缺少时需安装[微软官方 Visual C++ v14 x64 运行库](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)。
3. 在 Windows 仓库目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-twain-virtual-scanner.ps1 -Arch ia32
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-twain-virtual-scanner.ps1 -Arch x64
```

追加 `-Extended` 可运行每个位宽 23 个场景，包含 150 / 200 / 300 / 400 / 600 DPI × 彩色 / 灰度 / 黑白、无限批量、提前截断、默认数据源、拒绝 350 DPI 与 A4 / A3。每帧同时检查 Letter 像素尺寸、源图像色彩、桥接返回 DPI 和 JPEG DPI。

脚本将桥接程序、随包运行库与官方样例依赖复制到独立测试目录，设置仅在本次测试进程生效的 Qt 插件路径，并依次执行单面三帧、请求双面时拒绝走纸。检查返回状态、物理张号、实际 JPG 文件，以及双面失败时零帧、零图像、未进入采集；输出 JSON 中包含每次运行的目录。默认工作目录为 `%TEMP%\projectx-twain-virtual`，可通过 `-WorkDir` 修改。成功的双面多帧配对在下述模拟 DSM 回归中覆盖。

官方样例支持的预设纸型包括 Letter；测试使用 `--size Letter`、150 DPI、彩色、2 秒等纸超时。`CAP_XFERCOUNT` 环境变量控制样例送纸数量，脚本退出时恢复原环境设置。

## 2026-10-16 验证记录

环境为 Parallels 中的 Windows 11，使用仓库随包 DSM、重建的扫描桥和官方 2.5.0 数据源。工作目录为 `C:\ProjectXTests\pr330-virtual-scanner`。

| 桥接位宽 | 场景 | 结果 |
| --- | --- | --- |
| ia32 | 单面连续三帧 | 返回三帧，张号 1/2/3，三张 JPG 均可解码且尺寸与返回值一致 |
| ia32 | 请求双面 | 采集前报错，零帧、零图像 |
| x64 | 单面连续三帧 | 返回三帧，张号 1/2/3，三张 JPG 均可解码且尺寸与返回值一致 |
| x64 | 请求双面 | 采集前报错，零帧、零图像 |

扩展矩阵于同一环境完成，ia32 与 x64 各 23 个场景全部通过。每个位宽的 15 种 DPI / 色彩组合均验证像素尺寸为 `8.5 × DPI` / `11 × DPI`，源格式分别为 RGB 24 位、灰度 8 位和黑白 1 位，返回值和 JPEG 元数据均为请求 DPI。不限张数正确得到四帧；四张输入限制为一张时先 RESET 再关闭驱动；不支持的分辨率和纸型在取图前失败并保持零文件。

状态 5 续扫修复后，两种位宽各复测单面三帧、不限张数四帧、限制一张及双面拒绝，共 8 个场景全部通过。不限张数用例确认新桥在 `pending=0` 后进入配置的 2 秒事件等待；严格模拟 DSM 在启用后拒绝 `CAP_FEEDERLOADED` 查询，确认实际扫描循环不再发出该查询，并继续接收延迟的下一页与背面。

色彩模式严格检查修复后，ia32 / x64 再次各通过完整 23 个场景。所有成功帧均核对新增的 `image pixel mode` 日志，请求与实际模式一致；彩色、灰度、黑白的源格式及各档 DPI 检查继续通过。模拟 DSM 另覆盖模式被替代、设置拒绝、回读失败、驱动启用时覆盖，以及第二帧改变模式后保留第一页并报错。

取图前单双面复核修复后，两种位宽的 23 个场景再次全部通过，日志确认每个成功帧均在状态 6 验证单双面契约。官方样例为单面设备；窗口切换单双面的故障由模拟 DSM 覆盖，包含显式窗口、无界面启动失败后回退窗口、`CHECKSTATUS` 隐式窗口、延迟或同步就绪，以及背面到达前模式变化。匹配模式仍可扫描，无法确认或不匹配时停止，先前成功页面保留；启用后校验只读，不再 SET 双面能力。

显示官方驱动窗口时，应用传入 300 DPI，窗口的 Resolution (DPI) 实际显示 300；点击 Scan 后成功生成一帧，尺寸 2550×3300，JPEG 横纵 DPI 均为 300。驱动窗口覆盖分辨率导致的失败由下面的模拟 DSM 用例验证。旧桥输出的 150 DPI 图像曾被读取为 192 DPI 元数据，修复后的全部矩阵输出均与请求一致。

软件链路验证同时修复了启动调用内部就绪状态被覆盖，以及 `ENDXFER` 返回 `65535` 时错误等待新通知的问题。非零剩余数时继续传输的行为见 [TWAIN 规范的多图像传输约定](https://www.twain.org/wp-content/uploads/2017/03/TWAIN-2.4-Specification.pdf)。

## 故障模拟

正常软件数据源适合验证 DSM 枚举、能力协商、原生取图、文件保存和多帧配对。慢速进纸、错误的剩余页数等特定故障由现有自动回归模拟：

```bash
npm run verify:scanner-adf-recheck
npm run verify:scanner-scan-timeout
npm run verify:scanner-partial-failure
npm run verify:scanner-panel-session
```

`scanner-native-recheck-smoke.ts` 编译实际扫描循环，使用模拟 DSM 与时钟，覆盖 `Count=0` 后的延迟帧、状态 5 禁止查询送纸器、双面配对、双面设置被拒或替代、能力回读失败、合法单面源省略双面能力、英寸单位及 X/Y DPI 协商、能力设置顺序重置 DPI、色彩模式协商与实际取图一致性、驱动启用时覆盖 DPI、JPEG 保存失败收尾、驱动关闭请求、页数上限、启动期间同步就绪事件，以及非零剩余数时直接继续传输。真实子进程回归覆盖父进程超时预算、双面奇数帧上限和不限页数时按进度续期。

需要通过完整 TWAIN DLL 链路注入特定故障时，可扩展官方样例中的 `CScanner_FreeImage.cpp` 与 `CTWAINDS_FreeImage.cpp`，增加出帧延迟、错误 Count、固定托盘读数及能力拒绝开关。按 TWAIN 数据源接口实现即可，无需内核扫描仪驱动。柯达 i3000 的机械走纸和厂商驱动行为仍在现场验证。
