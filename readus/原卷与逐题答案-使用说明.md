# 原卷与逐题正确答案 · 使用说明（v2.6.0 起，v68 增补「答案原文件直接下发」）

面向老师/管理员的配置流程，与面向学生的展示口径。接口字段的权威定义在 `src/shared/types.ts`、`src/shared/answerKeyMode.ts` 与 `src/server/services/ExamPaperViewService.ts`。

## 0. 两种答案下发模式（v68）

「本次正确答案」有两份数据、一条通道，**发哪一份由考试级开关 `exams.answer_key_mode` 决定，客户端不自行推断**：

| 模式 | 学生看到 | 逐题文字 `exam_answer_keys` | 上传的原文件 `exam_answer_key_pages` |
| --- | --- | --- | --- |
| `text`「逐题文字（OCR）」（默认） | 逐题答案表 + 每张原卷页下方的本页答案 | 下发 | **不下发**（只在教师端留档核对） |
| `file`「原文件直接下发」 | 老师上传的那份文件本身（图片内联、PDF/DOCX 打开预览） | **不下发** | 下发（带 `fileUrl`） |

- **切换不销毁数据**：两份数据各自完整保留，切回去即可复用；存量考试默认 `text`，行为与 v2.6.0 完全一致。
- **直发时不再跑 OCR**：面板勾选「上传时自动 OCR 识别」在 `file` 模式下会带 `?ocr=0` 上传，省掉一次无用的识别；「重新识别」按钮在该模式下隐藏。
- **直发但一个文件都没传**：教师端面板给出红字提醒，学生端显示空态，不会退化成空白页。
- 答案模式与「显示原卷」`show_original_paper` **互不隶属**：原卷图片只受后者控制。只发答案不开卷时，`file` 模式可以给学生只看答案文件。

## 1. 谁能配置，谁能看到

| 角色 | 配置「显示原卷」/答案模式/上传答案 | 查看原卷与逐题答案 |
| --- | --- | --- |
| 管理员 | ✅ | ❌（不看学生端界面） |
| 教师（该考试数据范围内） | ✅ | ❌ |
| 学生 | ❌ | ✅ 仅本人、仅本场已公布且开关打开 |

学生**看不到也不用到**教师的答案上传页：`/api/exams/:examId/answer-key*` 全部要求 `EXAM_READ` / `EXAM_WRITE`，学生令牌访问返回 403。学生侧只走 `/api/scores/me/exams/:examId/paper*`。

## 2. 教师端配置流程

入口：考试管理页 → 该考试行的 **「原卷答案」** 按钮。

1. **上传原卷**（若还没传）：原卷图片是**答题卡级**资产，在「答题卡管理」里上传，不是在这个面板。面板顶部的「原卷页」列表只读，可逐页点开核对；为空时提示「原卷未上传」。
2. **上传「本次正确答案」**：支持图片 / PDF / DOCX（`.doc` 一律拒绝并提示转 `.docx`），一次最多 10 页、单场最多 200 题、单文件 ≤50MB。勾选「上传时自动 OCR 识别」时，识别结果只作为**草稿填入空白单元格**，不会覆盖已经手写的修正；某页识别不出内容会明确提示手动录入，可对该页单独「重新识别」。
3. **逐题修正**：题号（1–200）、答案文字（≤500 字）、归属原卷页。归属选「不指定」时，该题答案会渲染在**最后一页**下方（保证有答案就一定显示得出来，不静默丢弃）。删除某答案页时，挂在它下面的答案行自动改为「无归属」。
4. **保存答案**：OCR 草稿不落库，必须点「保存答案」；保存是**整场全量替换**，未提交的题号会被删除。
5. **显示原卷开关**：面板内可直接开关（等同考试编辑页的开关，跟随考试保存），默认关闭。
6. **答案展示方式**（v68）：面板内的分段控件「逐题文字（OCR）」/「原文件直接下发」，即时 `PATCH /api/exams/:examId`，请求失败会回滚显示并给出原因。选到「原文件直接下发」时，考试管理页该考试会出现「答案直发」标记，且逐题文字表不再作为学生视图出口。

## 3. 成绩公布表单的「公布后显示原卷」

- 单场公布与批量公布都有该勾选，**默认勾选**。
- 勾选 → `score_published=1` 且 `show_original_paper=1`；取消 → `score_published=1` 但 `show_original_paper=0`（只公布成绩，原卷保持隐藏）。
- 重新公布时沿用教师上一次的选择，不会把之前刻意关掉的原卷意外公开。
- 旧客户端/脚本不带该字段调用公布接口时，**不改变**开关现值（`COALESCE` 兜底），避免历史调用方误公开含答案的试卷。
- 公布表单**不含**答案模式：模式跟着考试走，不跟着公布动作走，避免批量公布时误把整批考试切成直发。

## 4. 学生端会看到什么

四重门（后端强制，任一不满足即 404，客户端不自行推断）：考试未删除 → 本人本场有成绩 → 成绩已公布 → （教师开启「显示原卷」 **或** 答案模式为 `file`）。原卷图片路由额外再要 `show_original_paper=1`，答案文件路由额外再要 `answer_key_mode='file'`。

- **入口**：成绩列表卡片上的「查看原卷 ›」、成绩详情页的「查看答案解析」。两处都由后端下发的 `paper_visible`（列表逐条）/ `paperVisible`（单场详情）控制，与 `/paper` 接口同一道门，因此不会出现「点进去 404」。**只开直发、不开原卷的考试同样会有入口**。
- **`text` 模式**：逐题答案 → 原卷（每张页图下方按题号渲染本页答案）→ 本人作答图块（先看卷、再看作答）。答案按老师保存的原样渲染，系统不判对错、不与本人得分比对。
- **`file` 模式**：正确答案（老师上传的原文件：图片内联可预览，PDF / DOCX 点开走系统文档预览，网页端提供「打开 / 下载」两个动作）→ 原卷（若开放）→ 本人作答图块。此模式下**不再显示逐题文字表**，接口也不会把文字答案发下来。
- **方向不正可旋转**：工具条上的旋转按钮每次转 90°，一次设置同时作用于本场全部原卷页、答案文件图与作答图块；只改显示方向，服务器上的图片与识别坐标都不变。
- **老师从未上传原卷图片**：显示「原卷未上传」，答案照常按当前模式显示。
- 小程序与网页学生端行为一致；小程序图片与文档都走带鉴权头的 `downloadFile`（token 不进 URL），失败不留破图、可下拉重试。
- ⚠️ **旧版本小程序不认识 `file`**：后端切到直发而学生仍跑旧版本时，页面不崩但会显示「老师尚未录入逐题答案」（旧客户端只读 `answers`，而直发模式不下发文字）。上线次序应为「先发小程序新版本，再对具体考试打开直发」。

## 5. 接口一览

教师配置：
- `GET /api/exams/:examId/answer-key` — 回显开关、答案模式、原卷页、答案页、逐题答案
- `PUT /api/exams/:examId/answer-key` — 全量保存逐题答案 `{ answers: [{ questionNumber, answerText, pageIndex }] }`
- `POST /api/exams/:examId/answer-key/pages` — 上传答案页（`multipart/form-data`，`?ocr=0` 跳过识别）
- `POST /api/exams/:examId/answer-key/pages/:pageIndex/ocr` — 单页重新识别
- `GET /api/exams/:examId/answer-key/pages/:pageIndex/image` · `DELETE .../:pageIndex`
- `PATCH /api/exams/:examId` — `{ showOriginalPaper: boolean }`、`{ answerKeyMode: 'text' | 'file' }`（非法值 400）

学生查看：
- `GET /api/scores/me` — 每条成绩附 `paper_visible`
- `GET /api/scores/me/exams/:examId` — 附 `paperVisible`
- `GET /api/scores/me/exams/:examId/paper` — `answerKeyMode` + `showOriginalPaper` + 原卷页 + 按页归集的答案 + `answerFiles[]`（每项带 `fileUrl`）+ 本人作答图块
- `GET /api/scores/me/exams/:examId/paper/pages/:pageIndex/image` — 原卷页字节
- `GET /api/scores/me/exams/:examId/paper/answer-file/:pageIndex` — 答案原文件字节（文件名取库中登记值，`Cache-Control: private, no-store`，DOCX 带 `Content-Disposition: attachment`；已加入 R30 媒体白名单）。新上传的图片按原字节保存，OCR / 教师预览另读 `<base>.preview.jpg`；更早入库、当时已被压成 JPEG 的页没有原件，继续下发登记文件。

数据表：`exams.show_original_paper`、`exam_answer_keys`、`exam_answer_key_pages`（迁移 `54 / exam-original-paper-and-answer-keys`），`exams.answer_key_mode`（迁移 `68 / exam-answer-key-mode`，`NOT NULL DEFAULT 'text'`，存量数据不回填）。v66 `feedback-reports` 与 v67 `feedback-attachments` 留给问题反馈，本列不占用这两号。SQLite 与 MariaDB 同步。答案页文件落在 `dataDir/answer-keys/<examId>/answerkey[-N].<ext>`。

## 6. 部署前必须补的验收

`npm run verify:exam-paper` 在迁移改为 v68 后，临时 SQLite + 真实 HTTP 覆盖了 119 项断言（含「v66 已记成 feedback-reports 时仍由 v68 补列」、原图字节一致、答案文件不缓存、脏值 `FILE` 不放行，以及模式闸门、两种模式各自的下发内容、答案文件路由的鉴权与越界页码、DOCX 附件头），但仍有边界：

1. **MariaDB 方言**：`scripts/verify-mariadb.ts` 的断言已跟到 v68，入口 SQL 改为精确比较并覆盖脏值 `FILE`。空库 `projectx_ci`（MariaDB 10.11.14）上 `npm run verify:mariadb` 已通过。
2. **真实 OCR**：tesseract.js 的图片识别端到端未跑（PDF 走文字层、DOCX 走 mammoth 的路径同理），首次上线建议用一张真实答案页验证草稿质量。
3. **端到端界面**：网页学生端与教师面板已在真实 HTTP + 真实字节（jpg / pdf / docx）的浏览器验收下过了一遍六种状态；**小程序真机仍未验**——`wx.openDocument` 能否拉起 PDF / DOCX 预览、右上角转存菜单、以及旧版本小程序遇到 `file` 模式的实际表现，都要在有工具的设备上确认。
