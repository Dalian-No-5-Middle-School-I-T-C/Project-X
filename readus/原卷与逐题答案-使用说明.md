# 原卷与逐题正确答案 · 使用说明（v2.6.0）

面向老师/管理员的配置流程，与面向学生的展示口径。接口字段的权威定义在 `src/shared/types.ts` 与 `src/server/services/ExamPaperViewService.ts`。

## 1. 谁能配置，谁能看到

| 角色 | 配置「显示原卷」/上传答案 | 查看原卷与逐题答案 |
| --- | --- | --- |
| 管理员 | ✅ | ❌（不看学生端界面） |
| 教师（该考试数据范围内） | ✅ | ❌ |
| 学生 | ❌ | ✅ 仅本人、仅本场已公布且开关打开 |

学生**看不到也不用到**教师的答案上传页：`/api/exams/:examId/answer-key*` 全部要求 `EXAM_READ` / `EXAM_WRITE`，学生令牌访问返回 403。学生侧只走 `/api/scores/me/exams/:examId/paper*`。

## 2. 教师端配置流程

入口：考试管理页 → 该考试行的 **「原卷答案」** 按钮。

1. **上传原卷**（若还没传）：原卷图片是**答题卡级**资产，在「答题卡管理」里上传，不是在这个面板。面板顶部的「原卷页」列表只读，可逐页点开核对；为空时提示「原卷未上传」。
2. **上传「本次正确答案」**：支持图片 / PDF / DOCX，一次最多 10 页、单场最多 200 题、单文件 ≤50MB。勾选「上传时自动 OCR 识别」时，识别结果只作为**草稿填入空白单元格**，不会覆盖已经手写的修正；某页识别不出内容会明确提示手动录入，可对该页单独「重新识别」。
3. **逐题修正**：题号（1–200）、答案文字（≤500 字）、归属原卷页。归属选「不指定」时，该题答案会渲染在**最后一页**下方（保证有答案就一定显示得出来，不静默丢弃）。删除某答案页时，挂在它下面的答案行自动改为「无归属」。
4. **保存答案**：OCR 草稿不落库，必须点「保存答案」；保存是**整场全量替换**，未提交的题号会被删除。
5. **显示原卷开关**：面板内可直接开关（等同考试编辑页的开关，跟随考试保存），默认关闭。

## 3. 成绩公布表单的「公布后显示原卷」

- 单场公布与批量公布都有该勾选，**默认勾选**。
- 勾选 → `score_published=1` 且 `show_original_paper=1`；取消 → `score_published=1` 但 `show_original_paper=0`（只公布成绩，原卷保持隐藏）。
- 重新公布时沿用教师上一次的选择，不会把之前刻意关掉的原卷意外公开。
- 旧客户端/脚本不带该字段调用公布接口时，**不改变**开关现值（`COALESCE` 兜底），避免历史调用方误公开含答案的试卷。

## 4. 学生端会看到什么

四重门（后端强制，任一不满足即 404，客户端不自行推断）：考试未删除 → 本人本场有成绩 → 成绩已公布 → 教师开启「显示原卷」。

- **入口**：成绩列表卡片上的「查看原卷 ›」、成绩详情页的「查看答案解析」。两处都由后端下发的 `paper_visible`（列表逐条）/ `paperVisible`（单场详情）控制，与 `/paper` 接口同一道门，因此不会出现「点进去 404」。
- **原卷页顺序**：逐题答案 → 原卷（每张页图下方按题号渲染本页答案）→ 本人作答图块（先看卷、再看作答）。
- **只出文字**：答案按老师保存的原样渲染，系统不判对错、不与本人得分比对。
- **老师从未上传原卷图片**：显示「原卷未上传」，逐题答案仍照常显示。
- 小程序与网页学生端行为一致；小程序图片走带鉴权头的下载（token 不进 URL），失败不留破图、可下拉重试。

## 5. 接口一览

教师配置：
- `GET /api/exams/:examId/answer-key` — 回显开关、原卷页、答案页、逐题答案
- `PUT /api/exams/:examId/answer-key` — 全量保存逐题答案 `{ answers: [{ questionNumber, answerText, pageIndex }] }`
- `POST /api/exams/:examId/answer-key/pages` — 上传答案页（`multipart/form-data`，`?ocr=0` 跳过识别）
- `POST /api/exams/:examId/answer-key/pages/:pageIndex/ocr` — 单页重新识别
- `GET /api/exams/:examId/answer-key/pages/:pageIndex/image` · `DELETE .../:pageIndex`
- `PATCH /api/exams/:examId` — `{ showOriginalPaper: boolean }`

学生查看：
- `GET /api/scores/me` — 每条成绩附 `paper_visible`
- `GET /api/scores/me/exams/:examId` — 附 `paperVisible`
- `GET /api/scores/me/exams/:examId/paper` — 原卷页 + 按页归集的答案 + 本人作答图块
- `GET /api/scores/me/exams/:examId/paper/pages/:pageIndex/image` — 原卷页字节

数据表：`exams.show_original_paper`、`exam_answer_keys`、`exam_answer_key_pages`（迁移 `53 / exam-answer-key`，SQLite 与 MariaDB 同步）。答案页文件落在 `dataDir/answer-keys/<examId>/answerkey[-N].<ext>`。

## 6. 部署前必须补的验收

`npm run verify:exam-paper` 用临时 SQLite + 真实 HTTP 覆盖了 51 项断言，但接口统一带 `?ocr=0`，因此以下三项**尚未验证**：

1. **MariaDB 方言**：`scripts/verify-mariadb.ts` 已加 v53 断言，需在一次性空的 `projectx_ci` 库上跑 `npm run verify:mariadb`。
2. **真实 OCR**：tesseract.js 的图片识别端到端未跑（PDF 走文字层、DOCX 走 mammoth 的路径同理），首次上线建议用一张真实答案页验证草稿质量。
3. **端到端界面**：小程序真机与网页学生端的浏览器验收未做，含「原卷未上传」「开关关闭」「撤回后重新公布」三种边界。
