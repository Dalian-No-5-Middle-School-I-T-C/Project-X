# Project-X 多端使用说明

> **适用版本**: v1.5.0 及以上
> **适用对象**: 管理员、教师、打包维护人员  
> **关联文档**: [`ADMIN-GUIDE.md`](./ADMIN-GUIDE.md) · [`ACCOUNT-CONTROL.md`](./ACCOUNT-CONTROL.md) · [`ARCHITECTURE.md`](./ARCHITECTURE.md)

Project-X 当前按“同一代码库，多产品变体”打包。学生端、教师普通端、教师扫描端是三个独立 Electron 包，但默认访问同一套本机数据，方便管理员先在教师端建账号、导入学生，再让学生端直接登录查看成绩。

---

## 1. 三个端分别做什么

| 端 | 变体值 | 默认首页 | 可见功能 | 原生资源 |
|------|------|------|------|------|
| 学生端 | `student` | 我的成绩 | 仅“我的成绩” | 不打包识别和扫描资源 |
| 教师普通端 | `teacher` | 设计 | 设计、阅卷、分析、账号 | 打包识别引擎和 OpenCV，不打包 TWAIN 扫描资源 |
| 教师扫描端 | `teacher-scanner` | 阅卷 | 设计、阅卷、分析、账号、扫描仪录入 | 打包识别引擎、OpenCV、扫描桥和 TWAINDSM |

前端会先按产品端限制功能，再按账号角色和权限限制功能。也就是说，即使管理员账号登录学生端，也只能看到学生端允许的页面；学生账号登录教师端，也不会获得教师功能。

---

## 2. 数据目录和账号是否互通

当前三个端默认共用同一个本机数据目录：

```text
%APPDATA%\answer-card-designer
```

主要数据位置：

| 数据 | 路径 |
|------|------|
| 主数据库 | `%APPDATA%\answer-card-designer\data\projectx.db` |
| 答题卡 JSON、扫描图片、资源文件 | `%APPDATA%\answer-card-designer\data\answer-card\` |
| Electron 本地状态和登录态 | `%APPDATA%\answer-card-designer\` |

因此：

1. 管理员在教师端或教师扫描端创建的账号，学生端可以直接使用。
2. 教师端录入的考试和成绩，学生端会从同一个数据库读取。
3. 三个端不是三套库，不会再分别写入 `projectx-student`、`projectx-teacher`、`projectx-teacher-scanner`。
4. 如果电脑上曾经运行过旧的隔离版目录，这些旧目录只是历史残留，不是当前默认数据源。

## 3. 学生账号和默认密码

学生账号一般由管理员在“账号”页面创建，或通过花名册导入。

学生登录规则：

| 项目 | 说明 |
|------|------|
| 登录名 | 可使用用户名，也可使用学号 |
| 默认密码 | 新建或导入学生时，默认密码为该学生的学号 |
| 5 位学号 | 允许作为学生初始密码使用 |
| 主动改密码 | 用户自己修改密码时仍要求至少 6 位 |

如果学生的用户名、学号、密码都是 `24207`，正常情况下可以用下面任一方式登录：

```text
用户名: 24207
密码: 24207
```

或：

```text
学号: 24207
密码: 24207
```

如果仍提示“用户名或密码错误”，优先检查：

1. 是否正在访问上面写的同一个 `answer-card-designer` 数据目录。
2. 管理员端里该学生是否存在，且学号确实是 `24207`。
3. 是否是旧数据里学生密码为空。新版登录逻辑会在“密码等于学号”时自动修复旧学生密码；也可以由管理员在账号管理里重置密码。

## 4. 打包命令

建议在普通 PowerShell 或 CMD 中按顺序打包，不要并行运行多个端的打包命令，因为它们会共用 `dist/` 构建目录。默认命令生成 `x64` 包；带 `:ia32` 后缀的命令生成 32 位包。

如需重新构建 C++ 原生组件，先按目标架构生成 native 资源：

```powershell
npm run native:build:x64
npm run native:build:ia32
```

`native:build:x64` 输出到 `resources/native/win-x64/`，`native:build:ia32` 输出到 `resources/native/win-ia32/`。学生端不会携带这些 native 资源；教师普通端携带识别器和 OpenCV；教师扫描端携带识别器、OpenCV、扫描桥和 TWAIN DSM。

### 目录包

```powershell
npm run electron:pack:student
npm run electron:pack:teacher
npm run electron:pack:scanner

npm run electron:pack:student:ia32
npm run electron:pack:teacher:ia32
npm run electron:pack:scanner:ia32
```

### 便携 EXE

```powershell
npm run electron:dist:student
npm run electron:dist:teacher
npm run electron:dist:scanner

npm run electron:dist:student:ia32
npm run electron:dist:teacher:ia32
npm run electron:dist:scanner:ia32
```

### MSI 安装包

```powershell
npm run electron:msi:student
npm run electron:msi:teacher
npm run electron:msi:scanner

npm run electron:msi:student:ia32
npm run electron:msi:teacher:ia32
npm run electron:msi:scanner:ia32
```

如需一次生成三端的 x64 与 ia32 MSI：

```powershell
npm run electron:msi:all
```

默认脚本仍指向扫描端，方便保留原先的完整功能包：

```powershell
npm run electron:pack
npm run electron:dist
npm run electron:msi
```

## 5. 产物和资源检查

打包后产物按端和架构输出到：

```text
release\student\                 # 学生端 x64
release\teacher\                 # 教师端 x64
release\teacher-scanner\         # 教师扫描端 x64
release\student-ia32\            # 学生端 ia32
release\teacher-ia32\            # 教师端 ia32
release\teacher-scanner-ia32\    # 教师扫描端 ia32
```

安装包文件名会保留 `${arch}`，例如 `Project-X 教师扫描端-1.3.0-x64.exe` 或 `Project-X 教师扫描端-1.3.0-ia32.exe`。

检查点：

| 端 | 应存在 | 不应存在 |
|------|------|------|
| 学生端 | `Project-X 学生端.exe` | `native\win-x64\answer-card-recognizer.exe`、`native\win-ia32\answer-card-recognizer.exe`、`scanner-bridge.exe`、`TWAINDSM.dll` |
| 教师普通端 | `Project-X 教师端.exe`、`native\win-<arch>\answer-card-recognizer.exe`、`native\win-<arch>\opencv_world4130.dll` | `scanner-bridge.exe`、`TWAINDSM.dll` |
| 教师扫描端 | `Project-X 教师扫描端.exe`、`native\win-<arch>\answer-card-recognizer.exe`、`native\win-<arch>\opencv_world4130.dll`、`native\win-<arch>\scanner-bridge.exe`、`native\win-<arch>\TWAINDSM.dll` | 无 |

其中 `<arch>` 为 `x64` 或 `ia32`。运行时会按 `process.arch` 查找 `resources/native/win-x64` 或 `resources/native/win-ia32`；`ANSWER_CARD_RECOGNIZER_EXE` 与 `SCANNER_BRIDGE_EXE` 环境变量仍具有最高优先级。

非扫描端访问 `/api/scanner` 会返回“扫描功能未启用”，不是缺少 exe 后才报错。

v1.3.0 的学科模板、题级评分规则和删除保护均属于共享前端/后端能力，教师普通端与教师扫描端表现一致；学生端只读取最终成绩，不显示答题卡设计和考试删除入口。

## 6. 常见问题

### 学生端登录不了

先确认管理员端和学生端是否共用：

```text
%APPDATA%\answer-card-designer\data\projectx.db
```

然后在管理员端检查学生账号是否存在、学号是否正确。学生默认密码可以是 5 位学号，但学生自己改密码时至少 6 位。

### 教师普通端看不到扫描入口

这是正常行为。教师普通端用于图片或目录导入阅卷，不带 TWAIN 扫描硬件依赖。需要扫描仪录入时使用教师扫描端。

### 打包时出现 `win-unpacked.tmp` 或 `EPERM`

先关闭正在运行的 Project-X、`node.exe`、`esbuild.exe` 或相关 Electron 进程，清理对应 `release\...\win-unpacked.tmp` 后重试。

### 多端同时运行会不会冲突

当前三个端共用数据目录，本地服务会优先尝试 `127.0.0.1:5174`。v1.2.0 起，如果该端口被占用或被系统拒绝绑定，Electron 会自动切换到随机端口，并通过 `/api/app/health` 确认接口可用后再打开窗口。仍建议日常使用时不要同时打开多个端，因为它们默认共用同一套本机 SQLite 数据。

### AI 成绩分析是否随 Electron 自动启动？

不会。AI 成绩分析使用独立的 Python `llmclient` 服务，需要手动启动并配置 API Key。多端 Electron 仍只负责启动本机 Express；AI 服务配置见 [`AI成绩分析.md`](./AI成绩分析.md)。

## 7. 预留的服务器模式

当前默认仍是本机一体化模式：Electron 启动本机 Express，数据写入本机 SQLite。

已经预留的配置：

| 配置 | 说明 |
|------|------|
| `VITE_PROJECTX_API_BASE` | 前端 API 基址。为空时继续请求本机 Express |
| `PROJECTX_SERVER_MODE=local\|remote` | 预留本地或远程服务模式。本轮默认 `local` |

将来切到 `remote` 后，学生端和教师普通端可以只连接校园内网或公网服务，不再初始化本机 SQLite。
