# Project-X 多端使用说明

> **适用版本**: v1.6.2 及以上（当前文档随 v2.0.0 校订）
> **适用对象**: 管理员、教师、打包维护人员
> **关联文档**: [ADMIN-GUIDE.md](./ADMIN-GUIDE.md) · [ACCOUNT-CONTROL.md](./ACCOUNT-CONTROL.md) · [ARCHITECTURE.md](./ARCHITECTURE.md)

Project-X 自 v1.6.1 起拆分为两个独立构建目标：

1. **Web 端** (`dist/web/`)：教师 + 学生功能，部署到服务器后通过浏览器访问。
2. **扫描端** (`dist/scanner/`)：答题卡选择、TWAIN 直扫、文件导入阅卷和结果预览，打包为 Electron 桌面应用。

教师/学生不再有独立 Electron 端，统一使用浏览器访问 Web 端。

---

## 1. 两端分别做什么

| 端 | 构建命令 | 可见功能 | 原生资源 |
|---|---|---|---|
| Web 端 | `vite build --mode web` | 设计、图片导入阅卷、成绩分析、账号管理、我的成绩 | 不含原生扫描代码 |
| 扫描端 | `vite build --mode scanner` | 答题卡选择、TWAIN 扫描、文件/目录导入阅卷、结果预览 | 识别引擎、OpenCV、扫描桥、TWAINDSM |

Web 端不含扫描仪控制能力，扫描端不含教师/学生管理页面。两端共用同一个后端 API。

---

## 2. 数据目录与账号

### 开发 / Web 部署

默认数据目录：

```text
data/projectx.db
data/answer-card/
```

可通过环境变量自定义：

```bash
export PROJECTX_DB_PATH=/var/lib/project-x/projectx.db
export ANSWER_CARD_DATA_DIR=/var/lib/project-x/answer-card
```

### 扫描端（Electron）

默认数据目录：

```text
%APPDATA%\answer-card-designer\data\projectx.db
%APPDATA%\answer-card-designer\data\answer-card\
```

管理员在 Web 端创建的账号、答题卡和考试可由扫描端通过本地或远程模式复用。

## 3. 扫描端使用流程

扫描端打开后分两步：

1. **答题卡选择页**：搜索或按学科筛选答题卡，也可切换到“大考”Tab 展开考试组选择下辖考试。
2. **扫描工作台**：选卡后进入，左侧为 ScannerPanel 直扫区，右侧为扫描设置和文件/目录导入阅卷。

两种阅卷方式可同时使用：

- **扫描仪直扫**：通过 TWAIN 驱动扫描仪，自动识别学号、题目和分数。
- **文件导入阅卷**：导入目录或单张图片，调用后端判分 API。

### 大题作答图片（v1.6.2）

识别成功后，系统会按答题卡 layout 的大题块裁剪作答图片：

- 普通批量阅卷和扫描仪 OCR 都会写入 `answer_block_crops`。
- 同一大题跨页时生成多张续页图片，不拼接。
- 学生成绩详情、教师个别改分页优先显示大题切块；缺少切块时仍回退到整页答题卡图片。
- 点击题目分数时，前端按 `questionNumbers` 定位到对应大题块。

## 4. 扫描端远程模式

扫描端支持本地 / 远程双模，在 ScannerPanel 界面上方切换。

| 模式 | 数据存储 | 扫描图片 | 答题卡来源 |
|---|---|---|---|
| 本地（默认） | 本机 SQLite | 本机 `data/answer-card/scans/` | 本机数据库 |
| 远程 | 远端 SQLite/MariaDB | 上传到远端 `scanner-uploads/` | 远端 `/api/cards` |

远程模式配置位于登录页“服务器连接（可选）”折叠面板：

- **服务器地址**：例如 `http://192.168.1.100:5174`。
- **API Key**：管理员在账号设置中生成的扫描端专用 Key。

扫描完成后自动三步上传：创建会话 → 逐页上传图片 → 标记完成。v1.6.2 预留切块 manifest/文件上传接口，服务端可直接接收扫描端本地识别生成的大题切块。

## 5. 构建与打包

### Web 端

```powershell
npm run build:web:full
```

产物：

```text
dist/web/          # 前端静态资源
dist/server/       # 后端 API bundle
```

### 扫描端（Electron）

```powershell
# 目录包（调试用）
npm run electron:pack
npm run electron:pack:ia32

# 便携 EXE
npm run electron:dist
npm run electron:dist:ia32

# MSI 安装包
npm run electron:msi
npm run electron:msi:ia32
```

打包前如需重新编译 C++ 原生组件：

```powershell
npm run native:build:x64
npm run native:build:ia32
```

### v1.6.2 打包注意事项

- scanner 构建日志中仍会出现 `index-scanner.html`，构建完成后会自动重命名为 `dist/scanner/index.html`，Electron 运行时按这个入口加载。
- x64 打包复用 `node_modules/electron/dist`；ia32 打包不复用 x64 Electron，会获取真正 32 位 Electron。
- ia32 打包会重建 Electron ia32 的 `better-sqlite3`。打包结束后建议运行：

```powershell
npm run native:rebuild:node
```

## 6. 产物与资源检查

目录包输出：

```text
release\win-unpacked\
release\win-ia32-unpacked\
```

便携版文件名（版本号 = `package.json` 的 version，以 Releases 实际发布为准）：

```text
release\答题卡扫描端-2.0.0-x64.exe
release\答题卡扫描端-2.0.0-ia32.exe
```

检查点：

- `resources/app.asar` 应包含 `dist/scanner/index.html`。
- x64 exe 应为 x64；ia32 exe 应为 x86。
- x64 包中的 `better_sqlite3.node` 应为 x64；ia32 包中的 `better_sqlite3.node` 应为 x86。
- 扫描端应包含 `native/win-x64/answer-card-recognizer.exe` 或 `native/win-ia32/answer-card-recognizer.exe`，以及对应 OpenCV/TWAIN 资源。

## 7. 常见问题

### Web 端看不到扫描入口

这是正常的。Web 端用于教师/学生通过浏览器访问，不含硬件扫描功能。扫描仪录入仅在 Electron 扫描端可用。

### 运行扫描端提示 `dist\scanner\index.html not found`

请确认使用 v1.6.2 及以上打包脚本重新生成产物，并检查 `resources/app.asar` 中是否包含 `dist/scanner/index.html`。不要只运行 `npm run build` 后直接打包扫描端；扫描端需要 `npm run build:scanner:full` 或 `npm run electron:*` 系列脚本。

### 打包时出现 `localtunnel@undefined`

v1.6.2 已移除未使用的 `localtunnel` 运行依赖。若仍看到该警告，先确认 `package.json` 和 `package-lock.json` 中没有 `localtunnel`，再重新安装依赖。

### 打包时出现 `win-unpacked.tmp`、`EPERM` 或 `EBUSY`

先关闭正在运行的扫描端、`node.exe`、`esbuild.exe` 或相关 Electron 进程，再重试。旧的 `release/win-unpacked/答题卡扫描端.exe` 被占用时，electron-builder 无法覆盖。

### 32 位包目录生成了，但 exe 仍是 x64

v1.6.2 已修复：ia32 打包不再复用 `node_modules/electron/dist`。如果手工调用 electron-builder，请不要给 ia32 架构传入 x64 的 `electronDist`。

### AI 成绩分析是否随 Electron 自动启动

不会。AI 成绩分析使用独立 Python `llmclient` 服务，需要手动启动并配置 API Key。详见 [AI成绩分析.md](./AI成绩分析.md)。

## 8. 从旧版迁移

v1.6.1 起废弃学生端/教师端 Electron 打包；v1.6.2 修复扫描端打包入口和 32 位运行时。

1. 学生访问 Web 端部署地址。
2. 教师访问 Web 端；如需扫描，使用扫描端 Electron。
3. 原数据目录不变，迁移到 Web 端后可继续使用。
4. 旧扫描端建议重新打 v1.6.2 包，避免 `dist/scanner/index.html` 缺失。
