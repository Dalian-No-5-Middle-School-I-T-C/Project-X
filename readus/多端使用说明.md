# Project-X 多端使用说明

> **适用版本**: v1.6.1 及以上
> **适用对象**: 管理员、教师、打包维护人员
> **关联文档**: [`ADMIN-GUIDE.md`](./ADMIN-GUIDE.md) · [`ACCOUNT-CONTROL.md`](./ACCOUNT-CONTROL.md) · [`ARCHITECTURE.md`](./ARCHITECTURE.md)

Project-X v1.6.1 拆分为两个独立构建目标：

1. **Web 端** (`dist/web/`) — 教师 + 学生功能，部署到服务器，浏览器访问
2. **扫描端** (`dist/scanner/`) — 扫描面板，打包为 Electron 桌面应用

教师/学生不再有独立的 Electron 端，统一使用浏览器访问。

---

## 1. 两端分别做什么

| 端 | 构建命令 | 可见功能 | 原生资源 |
|------|------|------|------|
| Web 端 | `vite build --mode web` | 设计、阅卷（图片导入）、分析、账号管理、我的成绩 | 不含原生代码 |
| 扫描端 | `vite build --mode scanner` | 答题卡选择 + TWAIN 扫描 + 结果预览 | 识别引擎、OpenCV、扫描桥、TWAINDSM |

Web 端不含扫描代码，扫描端不含教师/学生管理页面。两端共用同一后端 API。

## 2. 数据目录和账号

### 开发 / Web 部署

数据默认存放在项目根目录：

```text
data/projectx.db
data/answer-card/
```

可通过环境变量自定义：

```bash
export PROJECTX_DB_PATH=/var/lib/project-x/projectx.db
export ANSWER_CARD_DATA_DIR=/var/lib/project-x/answer-card
```

### 扫描端（Electron）

数据存放在 `%APPDATA%\answer-card-designer\`：

```text
%APPDATA%\answer-card-designer\data\projectx.db
%APPDATA%\answer-card-designer\data\answer-card\
```

### 扫描端使用流程 (v1.6.1)

扫描端打开后分两步：

1. **答题卡选择页**：搜索或按学科筛选答题卡，也可切换到「大考」Tab 展开大考组选择下辖考试
2. **扫描工作台**：选卡后进入，左侧 ScannerPanel（直扫），右侧扫描设置 + 文件/目录导入阅卷

两种阅卷方式可同时使用：
- **扫描仪直扫**：TWAIN 驱动扫描仪，自动识别判分
- **文件导入阅卷**：导入目录或单张图片，调用后端判分 API

### 扫描端远程模式 (v1.6.0)

扫描端支持本地/远程双模，在 ScannerPanel 界面上方切换：

| 模式 | 数据存储 | 扫描图片 | 答题卡来源 |
|------|---------|---------|-----------|
| **本地**（默认） | 本机 SQLite | 本机 `data/answer-card/scans/` | 本机数据库 |
| **远程** | 远端服务器 SQLite/MariaDB | 上传到远端 `scanner-uploads/` | 远端 `/api/cards` |

**远程模式配置**：登录页的「服务器连接（可选）」折叠面板填入：
- **服务器地址**：如 `http://192.168.1.100:5174`
- **API Key**：管理员在账号设置 → API Key 中生成的扫描专用 Key

扫描完成后自动三步上传：创建会话 → 逐页上传图片 → 标记完成。详见 [ARCHITECTURE.md](./ARCHITECTURE.md) 6.3 节。

## 3. 学生账号和默认密码

学生账号由管理员在 Web 端「账号」页面创建，或通过花名册导入。

学生登录规则：

| 项目 | 说明 |
|------|------|
| 登录名 | 可使用用户名，也可使用学号 |
| 默认密码 | 新建或导入学生时，默认密码为该学生的学号 |
| 改密码 | 学生自己改密码时要求至少 6 位 |

## 4. 构建与部署

### Web 端

```powershell
# 构建
npm run build:web:full

# 产物
dist/web/          # 前端静态资源（部署到 Nginx 或 Express 托管）
dist/server/       # 后端 API
```

### 扫描端（Electron）

```powershell
# 目录包（调试用）
npm run electron:pack

# 便携 EXE
npm run electron:dist

# MSI 安装包
npm run electron:msi

# 32 位版本
npm run electron:pack:ia32
npm run electron:dist:ia32
npm run electron:msi:ia32
```

### 原生组件编译

打包前需先编译 C++ 原生组件：

```powershell
npm run native:build:x64     # 64 位
npm run native:build:ia32    # 32 位
```

## 5. 产物和资源检查

打包后产物输出到：

```text
release\win-unpacked\         # electron-builder 目录包
release\答题卡扫描端-*.exe    # 便携 EXE
```

检查点：
- 扫描端应包含 `native\win-x64\answer-card-recognizer.exe`、`opencv_world4130.dll`、`scanner-bridge.exe`、`TWAINDSM.dll`
- 非扫描端访问 `/api/scanner` 会返回「扫描功能未启用」

## 6. 常见问题

### Web 端看不到扫描入口

这是正常的。Web 端用于教师/学生通过浏览器访问，不含硬件扫描功能。扫描仪录入仅在使用 Electron 扫描端时可用。

### 打包时出现 `win-unpacked.tmp` 或 `EPERM`

先关闭正在运行的 Project-X、`node.exe`、`esbuild.exe` 或相关 Electron 进程，清理对应 `release\...\win-unpacked.tmp` 后重试。

### 多端同时运行会不会冲突

扫描端（Electron）和 Web 端都可以连接同一个后端服务。如果都使用本地模式且共用同一个数据库，建议不要同时打开，避免 SQLite 写入冲突。

### AI 成绩分析是否随 Electron 自动启动？

不会。AI 成绩分析使用独立的 Python `llmclient` 服务，需要手动启动并配置 API Key。详见 [`AI成绩分析.md`](./AI成绩分析.md)。

## 7. 从旧版迁移

v1.6.1 废弃了学生端/教师端 Electron 打包。如果你的用户正在使用旧版 Electron：

1. **学生**：引导他们访问 Web 端部署地址（浏览器）
2. **教师**：引导他们访问 Web 端（浏览器）；如需扫描，使用扫描端（Electron）
3. 数据目录不变，迁移到 Web 端后可直接使用原数据
