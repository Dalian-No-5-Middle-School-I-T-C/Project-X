## 已修复的阻塞

### 1. 刚同步的答题卡被判为版本不一致

初次 50 个上传任务均在创建会话时返回 `409 CARD_VERSION_MISMATCH`。服务器内容指纹为 `36fbd21b5c53…`，扫描端为 `a8660167ca9e…`。

根因是仓储读取会补出空的 `multipleScoring` 默认值；扫描端通过正式 PUT 保存同步卡时，旧版兼容逻辑将这个空配置展开成逐题评分规则，改变内容指纹。修复 `src/shared/grading.ts`，不将空配置且错误得分为零的默认值展开为评分规则；实际配置的旧评分规则继续参与归一化。

新增正式接口“保存 → 读取 → 原样保存 → 再读取”回归。修复前回归失败；修复后两端实际卡片指纹一致，50 张卡正常进入上传流程。

### 2. MariaDB 下老师学生详情因切图 JSON 失败

老师搜索 10008 并打开改分详情时，接口返回 500：`crop.questionNumbers.map is not a function`。

MariaDB 驱动可将 JSON 列直接返回为数组或对象；旧读取代码再次 `JSON.parse`，单元素题号数组 `[5]` 经隐式字符串转换变成数字 `5`，多元素数组和坐标也会被误处理。修复 `AnswerBlockCropService.ts`，兼容已解码 JSON 与 SQLite JSON 文本，并校验数组、对象形状。

新增真 MariaDB 回归，覆盖单元素题号、多元素题号、坐标对象与学生题块得分汇总。修复后老师详情、整卡改分和学生作答图片均正常。

### 3. 老师成绩 Excel 导出被管理员中间件提前拒绝

老师点击“导出 Excel”，模板和成绩导出接口均返回 403。账号账密导出路由和成绩导出路由共用 `/api/export`，前者在整个路由器上挂了 `user:manage` 校验，导致后续成绩路由也先受管理员限制。

将管理员校验限定到四个账号账密导出入口。成绩导出继续使用已有的考试范围、成绩查看、名单查看及 `grade:read` 校验。新增完整路由栈回归：老师可读自己的模板并导出成绩；四个账密入口仍拒绝教师；名单查看被关闭时成绩导出仍拒绝。修复前两个正向用例失败，修复后通过，真实 Edge 下载和工作簿内容核验亦通过。

## 尚未修改的问题

1. **学生成绩天梯无法选择考试。** 学生页请求 `/api/exams`、`/api/exam-groups` 返回 403，前端捕获后展示空选择器；本人查分、趋势、学科与学期页面可用。天梯仍使用教师侧列表入口，需要改用受学生范围约束的列表接口。本次没有扩大教师接口的学生访问权限。
2. **扫描端主表保留首次识别状态。** 远端订正、重新保存成功后，上传卡显示成功、数据库已达到 50 人，但主成绩表仍显示原撞号学号和 10007 的“未识别/failed”，10008 也仍显示首次本地判分 33 分。应将这张表明确标注为初次识别快照，或在操作后刷新对应状态，减少现场误判。
3. **教师改分及导出弹窗标题缺少考试名。** 实际操作对象和数据正确，标题显示“成绩修改 —”“导出成绩 —”。截图可复现。
