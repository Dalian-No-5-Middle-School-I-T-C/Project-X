# 异常卷手动处理修复验证

日期：2026-10-11。修复分支：`codex/fix-scanner-manual-recovery`。

## 问题与修复

远程异常卷面板的“重新保存此会话”原先向 `/api/scanner/upload/sessions/:sessionId/complete` 发送空请求体，服务端要求 `cardVersion`，因此手动保存被 400 拒绝。现在保存由上传管理器执行，使用目标会话自己的答题卡版本及原服务器凭据。版本回执按服务器、答题卡和会话保存到浏览器本地存储，关闭任务或重建队列后仍可读取，服务端原有版本校验继续执行。

同一组冲突证据原先在每条失败记录及多个上传任务中反复出现。现在本地汇总和远程浮层按会话、分组去重；每份原卷保留一个查看、订正和保存入口。关联旧任务只接收属于它自己的失败分组，已有其他失败也予以保留。

手动保存后通过 GET 刷新同一服务器、凭据、答题卡的相关任务。刷新包含部分保存成功后的状态，直接反映服务器结果，不再次提交 complete。订正后的新卷即使已不属于重复学号，也会保留未保存原卷的操作入口。普通入库失败也可继续订正；后端拒绝改动已保存的分组。重复卷面板收口到原卷订正操作，上传失败与保存失败的重试文案分别显示“重试失败页”和“重试保存”。

## 验证边界

Windows 界面回归使用请求桩；Ubuntu 回归调用真实认证路由和 MariaDB，使用预置识别记录。此次没有运行 Windows 原生 OMR、TWAIN 或真实扫描仪。后续生产升级和数据修复单独记录如下。

旧版本应用从未记录的原始指纹无法重建。v61 将既有会话标记为 `legacy`：首次无版本保存时记录当前答题卡指纹及 `legacy_recovered` 来源，之后继续固定该版本校验；客户端有原指纹时记录 `legacy_verified`。新增上传在创建会话时保存服务端版本。空请求体仅复用服务端记录或走历史恢复，显式非法、过期指纹仍被拒绝，新上传也继续要求有效指纹。

历史已入库卷优先恢复完整成绩快照，保留人工改分、逐题成绩和时间，同时恢复切图的考试及学生归属。没有成绩快照的历史卷仍从原识别结果按恢复时的规则入库，保留身份、页数、应考名单及重复学号校验。

`discarded` 回执保留原图和识别证据；分组编号仍按完整原始页序计算。预览、订正和再次提交都不会重新激活撤销副本，其原上传令牌也不能覆盖已撤销页。
