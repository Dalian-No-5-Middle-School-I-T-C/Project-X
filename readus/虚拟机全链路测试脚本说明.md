# 虚拟机全链路测试脚本说明

这组脚本用于复用本次隔离虚拟机部署，验证 50 张答题卡的扫描、异常订正、改分、公布和补录流程。本轮结果见 [Ubuntu 与 Windows 双机全链路测试记录](Ubuntu与Windows双机全链路测试-20261121.md)。2026 年 10 月的历史结果见[首轮报告](全链路生产模拟测试-20261015.md)和[当次修复复测报告](剩余问题修复与虚拟机复测-20261015.md)。

## 环境与配置

- 宿主机安装 Parallels CLI。用 `prlctl list -a` 核对本轮专用测试机的名称或 UUID，将两台虚拟机分别设为 `WINDOWS_VM` 与 `UBUNTU_VM`。每次执行客机脚本都需要显式传入 `--vm-name`。
- Ubuntu 使用 MariaDB、Nginx 和启用认证的服务端。Node 22 需要 22.23.4 或以上的 22.x，Node 24 需要 24.22.1 或以上的 24.x，Node 26 需要 26.12.1 或以上。部署步骤见 [README](../README.md)。
- 将私有配置中的 `server` 设为隔离 Ubuntu 的 HTTP 或 HTTPS 来源，`scanner` 设为扫描端实际监听的回环来源。服务器支持回环和私网 IP。HTTPS 测试需在 Windows 及运行种子脚本的 Node 中信任测试 CA。
- Windows 运行目录通过 `--workdir` 指定，默认位于当前用户的 `%LOCALAPPDATA%\ProjectX-Flow`。该目录使用 `tools/node_modules/playwright-core`，可通过 `npm install --prefix tools playwright-core` 安装。脚本优先使用 Windows Node，也支持运行目录中的 `runtime/*.exe` Electron。默认启动 Edge，可通过 `--browser` 指定可执行文件。
- 宿主机的 `PROJECTX_FLOW_ROOT` 指向本轮配置、图片和证据目录，默认 `ignored/production-flow`。在 Windows 命令上用 `--source-root` 传入该机看到的仓库目录，用 `--shared-root` 传入对应的本轮证据目录。图片生成需要 PyMuPDF。

在仓库根目录准备私有配置：

```bash
mkdir -p ignored/production-flow
cp scripts/fixtures/production-flow-config.example.json ignored/production-flow/config.json
```

编辑三个密码占位值：`password` 为测试师生和首次引导账号的初始密码，`adminPassword` 为 Ubuntu 管理员完成首次改密后的密码，`changedPassword` 为浏览器首次登录改密所用密码。均使用本轮私有测试密码，长度至少 12 位；配置、状态和账号令牌保留在忽略目录。Windows 扫描服务的初始管理员密码需与配置一致。测试复用持久的 Edge 登录配置；如重建该配置，应同步私有状态中的当前账号密码。

首次引导可使用 `admin-bootstrap` 阶段。为此阶段提供一次性 `bootstrapPassword`，改密成功后用 `node scripts/production-flow-seed.mjs --admin-ready` 创建测试数据。脚本校验 PDF 响应中的版本与本次保存的卡片一致。

## 脚本入口

| 脚本 | 作用 |
| --- | --- |
| `production-flow-seed.mjs` | 正式 API 创建班级、账号、考试、应考名单及大考组，保存答题卡并导出 PDF |
| `production-flow-images.py` | 填涂该 PDF，生成 50 张 300 DPI 图片和可核对的分数清单 |
| `production-flow-actions.mjs` | 将已验证的 UI 场景模板替换为当前考试、组和会话 ID |
| `production-flow-browser.cjs` | Windows Edge 操作真实扫描、教师和学生界面，记录请求、截图与异常 |
| `production-flow-windows.ps1` | 将驱动复制到 Windows 运行目录，使用本轮共享目录的配置并记录证据 |
| `production-flow-vm.py` | 在现有 VM 执行脚本；Windows 默认以当前用户运行 |
| `production-flow-check.mjs` | 只读校验当前阶段人数、逐人分数、竞争排名、均分、异常和公布状态 |

## 按阶段执行

在仓库根目录运行。用 `PROJECTX_FLOW_SOURCE_ROOT` 设置 Windows 看到的仓库路径，或为下列 Windows 命令传 `--source-root`。首次准备使用 `seed`；同一隔离库再建新考试时使用 `--reuse-accounts`，它复用账号并创建新的答题卡、考试及大考组。

```bash
node scripts/production-flow-seed.mjs
ignored/production-flow-venv/bin/python scripts/production-flow-images.py
node scripts/production-flow-actions.mjs prepare
```

把生成的 `ignored/production-flow/images/` 复制到 Windows 测试运行目录的 `images/`，保持文件名。状态及清单由 PowerShell 入口复制。所有图片均从本轮程序导出的 PDF 生成。

在扫描端设置页配置隔离 Ubuntu 的地址和扫描密钥，测试连接并保存。本轮使用 HTTPS。使用明文 HTTP 的隔离测试网需在该设置页显式允许发送凭据。

```bash
python3 scripts/production-flow-vm.py windows scripts/production-flow-windows.ps1 --vm-name "$WINDOWS_VM" --stage scanner-prepare
python3 scripts/production-flow-vm.py windows scripts/production-flow-windows.ps1 --vm-name "$WINDOWS_VM" --stage scanner-live
```

`scanner-live` 保持打开，供后续命令操作同一个页面。在另一个终端等待 `evidence/扫描会话就绪.json` 的时间更新为本轮，并查看 `evidence/scanner-live-requests.json` 确认当前答题卡 ID。若上次留下 `ui-command.json`，应在启动新扫描前移除该旧命令文件。

```bash
node scripts/production-flow-check.mjs initial
node scripts/production-flow-actions.mjs early
```

等待 `evidence/扫描操作结果.json` 的本轮命令执行完成且无 `error`，再继续：

```bash
node scripts/production-flow-check.mjs early
python3 scripts/production-flow-vm.py windows scripts/production-flow-windows.ps1 --vm-name "$WINDOWS_VM" --stage teacher-correct
node scripts/production-flow-check.mjs corrected
node scripts/production-flow-actions.mjs sync
```

`sync` 核验扫描主表读取教师订正后的 45 分及明细，断言允许等待 30 秒自动刷新。确认命令成功后公布：

```bash
python3 scripts/production-flow-vm.py windows scripts/production-flow-windows.ps1 --vm-name "$WINDOWS_VM" --stage teacher-publish
node scripts/production-flow-check.mjs published
python3 scripts/production-flow-vm.py windows scripts/production-flow-windows.ps1 --vm-name "$WINDOWS_VM" --stage student10008:published
```

在独立终端保持 10006 学生页打开：

```bash
python3 scripts/production-flow-vm.py windows scripts/production-flow-windows.ps1 --vm-name "$WINDOWS_VM" --stage student10006:watch
```

等待该页的本轮“补录前学生界面”证据生成，再在另一个终端执行最后三张卡的订正、保存和上传：

```bash
node scripts/production-flow-actions.mjs final
```

待扫描命令成功及学生页自动更新后，完成校验：

```bash
node scripts/production-flow-check.mjs final
python3 scripts/production-flow-vm.py windows scripts/production-flow-windows.ps1 --vm-name "$WINDOWS_VM" --stage teacher-final
python3 scripts/production-flow-vm.py windows scripts/production-flow-windows.ps1 --vm-name "$WINDOWS_VM" --stage student10008:final
node scripts/production-flow-actions.mjs close
```

同一账号配置的浏览器阶段顺序执行；扫描、教师和不同学生分别使用独立浏览器配置。最终预期为 50 人、异常 0 份、10008 为 45 分、成绩保持公布；教师导出和学生单场／大考组／跨考天梯均成功。跨考累计还包含隔离库内其他本人参与且已公布的考试，因此总分随测试库历史变化。

## 证据与检查范围

`ignored/production-flow/evidence/` 保存页面截图、可检索文本、业务请求、前端异常及阶段断言。原始 API 响应和导出内容只在本地保留；每轮应归档该目录后再复测，避免相同文件名覆盖首轮证据。配置、状态、图片、数据库及打包产物均不纳入 Git 提交。

常规回归继续使用 `package.json` 中的 `typecheck`、`verify:permission-scope`、`verify:scanner-upload-manager`、`verify:scanner-batch-results`、`verify:scan-correction`、`verify:security-critical` 和 `verify:mariadb`；MariaDB 专项要求独立空测试库。虚拟机图像导入、原生 OMR、实际界面和设备进纸各有对应验收记录，本轮设备及未配置服务的范围见结果报告。

## 部署服务专项

`node scripts/production-flow-services.mjs <阶段>` 使用本轮种子生成的 `state.json`。以 `PROJECTX_FLOW_ROOT` 指向同一隔离目录，HTTPS 自签测试证书配置在 `NODE_EXTRA_CA_CERTS`。脚本把请求路径、状态及业务断言观测写入该目录的 `evidence/service-<阶段>.json`。

| 阶段 | 输入与检查 |
| --- | --- |
| `console`、`governance` | 管理控制台、构建时间、教师首页、手动周测与微信自检。governance 在 scopes 创建教师后执行。 |
| `organization`、`scopes` | 先导入 60 名学生和三个班，再按源班和目标班校验名册访问与调班。调班会改变夹具，重复运行时使用初始快照。 |
| `card-matrix`、`revision`、`papers` | 保存四种布局、导出实际 PDF、拒绝旧版本与混合原卷。papers 读取本轮证据中的 PNG 与 `原卷练习.docx`。 |
| `answers`、`student-papers` | 核对教师和学生的 PDF 下载、媒体票据及展示开关。学生阶段需要考试已公布且 10008 有成绩。 |
| `feedback`、`demo` | 教师附件与管理处置，以及演示数据导入确认和清理。 |
| `ai`、`student-ai` | 配置 Ubuntu 回环桩和实际 Python 边车。学生单科使用边车环境中的同一个回环供应商，学生总体使用程序内统计。 |
| `rank-seed`、`rank`、`analysis-reports`、`ladder-gate` | 为独立联考记录四种排名预期；后两项核验多科导出、错题工作簿、学生与管理员的天梯权限。rank 要求已写入这组考试的合成成绩。 |
| `backup-formats` | 在损后恢复完成后，以 `SQLite测试备份.zip` 和损坏数据验证 400 以及学生原成绩。 |

在 `organization` 完成后，运行以下命令生成用于当年两个学期的合成成绩 SQL、两张答案 PNG 和独立计算的统计量。Python 需要 3.10 及以上和 PyMuPDF。将 SQL 交给同一隔离 MariaDB 运行一次，然后执行上表的服务端核对；日期可用 `--year` 指定。复用已有样本时，脚本按专用考试名称跳过已存在的数据。

```bash
python3 scripts/production-flow-analysis-fixtures.py --root "$PROJECTX_FLOW_ROOT"
prlctl exec "$UBUNTU_VM" mariadb --default-character-set=utf8mb4 "$TEST_DATABASE" < "$PROJECTX_FLOW_ROOT/analysis-fixtures.sql"
```

在组织、教师权限和双面卷夹具已建立的隔离库中，可用 `scripts/fixtures/production-flow-transfer-seed.sql` 建立两人的历史考试，再跑服务阶段 `transfer-history`。Windows 阶段 `admin-designer-lifecycle` 验证编辑离开和两张测试卡的批量解绑，`admin-review-viewport` 验证分配池和网阅设置，`electron:postprocess-viewport` 验证后处理窄屏操作。两项视口验收都记录 3 种尺寸和 4 种外观。

`scripts/production-flow-weekly-clock.ts` 在 Ubuntu 专用空 MariaDB 库内调用周报服务，分别传入周六 07:59:59 和 08:00:00，验证出分延迟和重复发布。设置常规 `PROJECTX_MARIADB_*` 连接参数，库名采用 `projectx_weekly_e2e_<数字>`，以 `npx tsx scripts/production-flow-weekly-clock.ts` 执行。

Windows 阶段 `admin-card-previews` 核对四套卡的 SVG 和 PDF 导出对话框。已有被领取的作文卷时，`teacher-grading-draft` 检查选分与刷新，`teacher-text-annotation` 和 `teacher-touch-annotation` 检查批注保存、读取与按作者删除。扫描端阶段 `electron:draft-boundaries` 使用同一页的两个版本和独立教师账号，检查过期草稿与账号切换。
