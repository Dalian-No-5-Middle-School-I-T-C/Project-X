# 虚拟机全链路测试脚本说明

这组脚本用于复用本次隔离虚拟机部署，验证 50 张答题卡的扫描、异常订正、改分、公布和补录流程。实测结果见[首轮报告](全链路生产模拟测试-20261015.md)和[最终修复复测报告](剩余问题修复与虚拟机复测-20261015.md)。

## 环境与配置

- macOS 宿主机安装 Parallels CLI `prlctl`，默认虚拟机名称为 `Ubuntu 24.04 (with Rosetta)`、`Windows 11`。可通过 `--vm-name` 指定已有虚拟机。
- Ubuntu 隔离服务地址固定为 `http://10.211.55.4:5196`，使用 MariaDB、Nginx 和 amd64 Node；认证开启、本机扫描关闭、远端扫描接入开启。部署步骤参见 [README](../README.md)及[扫描端配置](SCANNER-SETUP.md)。
- Windows 本机扫描服务地址为 `http://127.0.0.1:5186`，默认测试运行目录 `C:\projectx-flow-20261015`，包含当前构建的 `dist/scanner`、`dist/server`、ia32 原生识别器及其依赖、可用的 Electron Node 运行时（`runtime/*.exe`）。服务使用隔离的数据目录。
- Windows 安装 Edge；在该运行目录安装浏览器驱动：`npm install --prefix tools playwright-core`。宿主机图片生成依赖可放入专用环境：`python3 -m venv ignored/production-flow-venv`，再用该环境的 pip 安装 `pymupdf`。
- Parallels 共享目录允许 Windows 读取本仓库并写入 `ignored/production-flow/`。默认仓库 UNC 路径为 `\\Mac\Home\Documents\project\dl5z\Project-X`，可用 `--source-root` 覆盖；运行目录可用 `--workdir` 覆盖。

在仓库根目录准备私有配置：

```bash
mkdir -p ignored/production-flow
cp scripts/fixtures/production-flow-config.example.json ignored/production-flow/config.json
```

编辑三个密码占位值：`password` 为测试师生和首次引导账号的初始密码，`adminPassword` 为 Ubuntu 管理员完成首次改密后的密码，`changedPassword` 为浏览器首次登录改密所用密码。均使用本轮私有测试密码，长度至少 12 位；配置、状态和账号令牌保留在忽略目录。Windows 扫描服务的初始管理员密码需与配置一致。测试复用持久的 Edge 登录配置；如重建该配置，应同步私有状态中的当前账号密码。

API 写入和浏览器驱动均校验固定的隔离服务地址。切换其他环境时应先检查部署地址、目录及脚本中的隔离约束。

## 脚本入口

| 脚本 | 作用 |
| --- | --- |
| `production-flow-seed.mjs` | 正式 API 创建班级、账号、考试、应考名单及大考组，保存答题卡并导出 PDF |
| `production-flow-images.py` | 填涂该 PDF，生成 50 张 300 DPI 图片和可核对的分数清单 |
| `production-flow-actions.mjs` | 将已验证的 UI 场景模板替换为当前考试、组和会话 ID |
| `production-flow-browser.cjs` | Windows Edge 操作真实扫描、教师和学生界面，记录请求、截图与异常 |
| `production-flow-windows.ps1` | 将脚本和私有状态复制到 Windows 运行目录，运行指定阶段并回收证据 |
| `production-flow-vm.py` | 在现有 VM 执行脚本；Windows 默认以当前用户运行 |
| `production-flow-check.mjs` | 只读校验当前阶段人数、逐人分数、竞争排名、均分、异常和公布状态 |

## 按阶段执行

在仓库根目录运行。首次准备使用 `seed`；同一隔离库再建新考试时使用 `--reuse-accounts`，它复用账号并创建新的答题卡、考试及大考组。

```bash
node scripts/production-flow-seed.mjs
ignored/production-flow-venv/bin/python scripts/production-flow-images.py
node scripts/production-flow-actions.mjs prepare
```

把生成的 `ignored/production-flow/images/` 复制到 Windows 测试运行目录的 `images/`，保持文件名。状态及清单由 PowerShell 入口复制。所有图片均从本轮程序导出的 PDF 生成。

先配置扫描端到隔离 Ubuntu 的连接。在当前测试网络中，通过真实设置页勾选明文内网测试许可，随后执行扫描阶段：

```bash
python3 scripts/production-flow-vm.py windows scripts/production-flow-windows.ps1 --stage scanner-prepare
python3 scripts/production-flow-vm.py windows scripts/production-flow-windows.ps1 --stage scanner-live
```

`scanner-live` 保持打开，供后续命令操作同一个页面。在另一个终端等待 `evidence/扫描会话就绪.json` 的时间更新为本轮，并查看 `evidence/scanner-live-requests.json` 确认当前答题卡 ID。若上次留下 `ui-command.json`，应在启动新扫描前移除该旧命令文件。

```bash
node scripts/production-flow-check.mjs initial
node scripts/production-flow-actions.mjs early
```

等待 `evidence/扫描操作结果.json` 的本轮命令执行完成且无 `error`，再继续：

```bash
node scripts/production-flow-check.mjs early
python3 scripts/production-flow-vm.py windows scripts/production-flow-windows.ps1 --stage teacher-correct
node scripts/production-flow-check.mjs corrected
node scripts/production-flow-actions.mjs sync
```

`sync` 核验扫描主表读取教师订正后的 45 分及明细，断言允许等待 30 秒自动刷新。确认命令成功后公布：

```bash
python3 scripts/production-flow-vm.py windows scripts/production-flow-windows.ps1 --stage teacher-publish
node scripts/production-flow-check.mjs published
python3 scripts/production-flow-vm.py windows scripts/production-flow-windows.ps1 --stage student10008:published
```

在独立终端保持 10006 学生页打开：

```bash
python3 scripts/production-flow-vm.py windows scripts/production-flow-windows.ps1 --stage student10006:watch
```

等待该页的本轮“补录前学生界面”证据生成，再在另一个终端执行最后三张卡的订正、保存和上传：

```bash
node scripts/production-flow-actions.mjs final
```

待扫描命令成功及学生页自动更新后，完成校验：

```bash
node scripts/production-flow-check.mjs final
python3 scripts/production-flow-vm.py windows scripts/production-flow-windows.ps1 --stage teacher-final
python3 scripts/production-flow-vm.py windows scripts/production-flow-windows.ps1 --stage student10008:final
node scripts/production-flow-actions.mjs close
```

同一账号配置的浏览器阶段顺序执行；扫描、教师和不同学生分别使用独立浏览器配置。最终预期为 50 人、异常 0 份、10008 为 45 分、成绩保持公布；教师导出和学生单场／大考组／跨考天梯均成功。跨考累计还包含隔离库内其他本人参与且已公布的考试，因此总分随测试库历史变化。

## 证据与检查范围

`ignored/production-flow/evidence/` 保存页面截图、可检索文本、业务请求、前端异常及阶段断言。原始 API 响应和导出内容只在本地保留；每轮应归档该目录后再复测，避免相同文件名覆盖首轮证据。配置、状态、图片、数据库及打包产物均不纳入 Git 提交。

常规回归继续使用 `package.json` 中的 `typecheck`、`verify:permission-scope`、`verify:scanner-upload-manager`、`verify:scanner-batch-results`、`verify:scan-correction`、`verify:security-critical` 和 `verify:mariadb`；MariaDB 专项要求独立空测试库。虚拟机图像导入、原生 OMR、实际界面和设备进纸各有对应验收记录，本轮设备及未配置服务的范围见结果报告。
