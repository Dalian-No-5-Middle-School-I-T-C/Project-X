# 扫描异常卷整合验证

日期：2026-10-11。整合分支：`codex/fix-scanner-manual-recovery`；PR #324 包含 PR #325 的新增扫描功能。

## 整合行为

保留 #324 的历史版本恢复、原卷清单去重、目标会话版本及凭据、完整人工成绩快照和切图归属恢复。加入 #325 的 CAP_XFERCOUNT 设置、双 DSM 重试、400 张扫描上限、按页超时、自动后台上传和人工作废入口。

判重复用 `scannerDuplicateEvidence`：原图 SHA256、布局页、学号、身份 JSON、客观及主观识别 JSON、识别状态全部相同才归档重传副本。答案相同不能证明是同一原卷；不同原图与同批多份同学号卷保留人工核对。

人工作废和历史修复统一使用 `discarded`，保留原图、识别记录、切图和分组编号。作废前锁定考试并重新检查有效冲突；已入库原卷和成绩快照不能作废，旧归档副本不参与冲突计数。预览、上传、切图上传、订正、重新保存均不能重新激活归档卷。

直扫每份成功卷自动入队，订正后新出现的成功卷也会自动入队；图片导入由整批一个会话改为每份答题卡独立会话。当前或排队任务收到关联冲突时仅记录提示，继续自己的上传；已撤回成绩的完成任务显示待处理，保留手工恢复入口。

## 验证结果

| 场景 | 实际结果 |
| --- | --- |
| 同图同记录再次上传 | 归档副本、原成绩保留，再次保存不会复活副本 |
| 相同学号、相同答案、不同原图 | 形成真实冲突，保留两份原卷 |
| 同一批多份相同学号 | 保留人工核对，不自动消化 |
| 重复卷后继续上传正常卷 | 正常卷提交并入库，不等待重复卷处理 |
| 未涂学号 | 失败页保留；查看原卷、明确订正后复用原会话上传 |
| 图像无法识别 | 人工学号不能绕过识别；清晰重扫另起任务上传成功，原失败页保留 |
| 学号不在名单 | 独立保存失败；远端订正、重新保存后入库 |
| 作废多余副本 | 原图及识别记录保留；剩余原卷显式保存后恢复成绩 |
| 旧会话缺版本记录 | 历史恢复入口继续有效，记录恢复来源，随后固定版本校验 |
| 人工修改后的旧成绩 | 完整总分、题分、人工修改字段及时间保留，切图归属恢复 |
| 人工处理后下一批扫描上传 | 新正常卷继续入队、上传和保存 |

## PR #324 审查反馈修复

`chatgpt-codex-connector` 的五条反馈经当前实现核对均真实存在，已逐项修复：

| 反馈 | 修复及回归证据 |
| --- | --- |
| 快照恢复遗漏 `assigned_score` | 非历史来源及 legacy 快照均恢复赋分；SQLite / MariaDB 验证停用的历史 custom 公式不会把 82 / 73 分变成 NULL |
| 修复脚本中断后无法续跑 | 不再提前批量改为 pending；每份成绩与回执在恢复事务内一起提交，支持原有 pending 快照续跑。模拟应考名单错误导致第一份恢复失败，修正名单后再次 `--apply` 恢复全部成绩，第三次执行幂等 |
| SSE 使用旧模式 / 空版本 | 扫描前读取并固定本次版本，模式、版本、DPI 和纸张保存在会话 ref；实际挂载 React 面板测试首份 legacy、下一份 strict、版本加载期间启动及取消 |
| 每个学号反复加载全考试回执 | 仅处理当前上传及订正影响的学号，复用已读取的回执，归档时在内存排除副本；400 份有效回执的最后一份正常卷仅 4 次事务内回执读取，SQLite / MariaDB 一致 |
| 人工处理刷新所有保留任务 | 仅刷新源会话、冲突关联及实际操作目标；并行结果独立处理。400 个保留任务只刷新 3 个关联会话，一个失效会话不阻止另外两个刷新成功 |

新增 `verify:scanner-panel-session` 和 `verify:scanner-review-regressions`，并将数据库回归接入 CI 的 SQLite / MariaDB 路径。增加 jsdom 26 及类型声明作为 Node 22 兼容的界面测试依赖，既有依赖版本未修改。

类型检查、安全关键 511 项、Web / 扫描端 / 服务端构建，以及上传管理器、历史异常卷、判重、真实上传流程均通过。Parallels Ubuntu 的 MariaDB 10.11 隔离空库通过完整 `verify:mariadb` 和以上数据库回归。此前 67 次请求的同一组异常卷处理流程，在限定关联刷新后减少为 47 次真实 HTTP 请求，仍得到相同的 7 份有效成绩。

## 后续四项审查修复

以下行为取代上文“旧会话缺版本记录自动恢复当前版本”的说明：没有原始版本凭据的历史会话返回 `CARD_VERSION_REQUIRED`，需原版本凭据或重新识别，不再推定当前版本就是扫描版本。

- 快照恢复在同一事务调用 `markScoreMutated`，撤回公布并记录审计；学生查分接口确认恢复成绩在重新公布前不可见。
- 作废分组在汇总前排除，原始页码、原图和记录继续保留；同会话两份同学号卷作废一份后，另一份能保存。
- 双 DSM 重试限于明确的 DSM / 打开设备 / 启动设备错误。无纸、纸张不支持以及未分类的进程故障保留原结果，不盲目重试。
- 新增 `verify:scanner-review-fixes`，覆盖上述三条数据库路径与 DSM 子进程分类，并接入 CI。
