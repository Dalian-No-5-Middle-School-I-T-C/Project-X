## 1. 三十秒形态

- 一套代码，三种交付：**Web 教师/学生端**（`dist/web/`）、**Windows 扫描端**（Electron，`dist/scanner/` + 内嵌 `dist/server/`）、**Ubuntu 服务端**（`scripts/package-server-ubuntu.cjs`，MariaDB）。
- 服务端只有一个入口：`src/apps/answer-card/server/index.ts`（`createApp()`:726、`startServer()`:3118、自启动守卫:3157）。**`src/server/index.ts` 不存在**，不要去找它。业务代码分布在 `src/server/{routes,services,repositories,auth,middleware,db}`。
- 扫描端不是独立后端：`electron/main.cjs` 用 `await import()` **在同进程内**加载 `dist/server/index.mjs`（main.cjs:155 区域），窗口加载 `http://127.0.0.1:<port>`。端口 `PROJECTX_ELECTRON_PORT` 默认 5174，被占用时回落随机端口（:167）。
- 数据库双方言：SQLite（默认本地）/ MariaDB（生产）。切换见 `detectDialect()`（`src/server/db/mysql.ts:34`）：`PROJECTX_MARIADB_HOST|PROJECTX_MYSQL_HOST` > `config.yml database.mode=remote` > SQLite。**迁移两侧当前都是 v62**（SQLite `db/migrations.ts:1342`、MariaDB `db/mysql.ts:1155`，同名 `scan-correction-pages`）。
- 判分/布局/排名的规则集中在 `src/shared/`，两端与原生识别器共用；不要在各端各写一套。

## 4. 三条主线数据流

```
① 设计→导出：React 设计器 → answer_cards(结构化) → buildLayout(card) → layouts/<cardId>.json
                → PDF/导出 .projectx-card.json（含 answerKey + base64 assets + layout）
② 扫描→判分：TWAIN 桥(本机出图) → twain_scan_records(落盘 scans/<cardId>/) → answer-card-recognizer.exe
                → grading.ts → 成绩/阅卷队列 →（扫描端本地或远端）scanner_submissions
③ 成绩→分析：student_scores/question_scores → rankingUpdate.ts（排名/赋分/百分位）
                → analysis 路由 → 前端图表；AI 分析走 llmclient 中转
```

## 5. 跨端契约与不变量（改动必须两侧核对）

- **页码映射**（`src/shared/scanPages.ts`）：native 的 `page` 是**物理张**号，正反面共用同号；`mapScanPageToLayout()`(:48) 由 `(physicalPage, side, layoutPageCount, sided)` 反推布局页与 `groupIndex`；`assignScanRecordPageNums()`(:33) 必须按「纸」加会话偏移，按图片下标递增会破坏双面分组与首页学号继承。
- **张 vs 页**：`--max-pages` 传给桥的是**张**（双面时 `ceil(页/2)`），服务端/上传容量按**页**估算。服务端单会话 800 页 = 400 张双面，与扫描端单次批扫 400 张上限同源（`scanUploadLimits.ts`、`ScannerPanel.tsx:822-825`）。
- **学号订正语义**：`applyScanStudentId()`（`scanPages.ts:5`）只允许在配对成功或人工订正后覆写 native 的「仅学号失败」，`identity.status==="rejected"` 不得覆写。
- **双方言 SQL**：一律 `getMysqlDb()` + `DbAdapter`（`db/mysql.ts:63`，含 `transactionWithNamedLock`:88）；upsert 用 `buildUpsertSQL`(:121)，忽略冲突用 `buildInsertIgnore`(:145)，标识符 `quoteIdent`(:109)。禁止在共享路径直接写单一方言（详见 `readus/双方言SQL函数安全清单.md`）。
- **迁移双侧**：结构变更同时改 `schema.sql`/`migrations.ts` 与 `schema.mariadb.sql`/`mysql.ts` 内联数组，并成对递增版本号（当前双侧 v62）。
- **安全配额三档模式**：`默认值 + PROJECTX_* 覆盖 + 硬天花板`，解析在导入期且不抛错、非法值回落默认。8 个模块同构：`scanUploadLimits` / `aiQuotaLimits` / `mediaTicketLimits` / `reviewPoolLimits` / `cardAssetLimits` / `restoreZipLimits` / `paperStorageLimits` / `wechatLimits`。加新限制照这个模式写，不要只留硬编码或只留环境变量。
- **权限在后端**：`requirePermission`（`middleware/auth.ts:187`）+ 数据范围函数；`PROJECTX_AUTH_ENFORCE` 关闭仅供异常场景，前端隐藏按钮不等于授权。
- **前端兼容**：`vite.config.ts:9,79` target `["es2020","safari15"]`（仅 Web 生效），`package.json:125-128` browserslist `iOS>=15 / Safari>=15`；改动兼顾移动端、明暗模式与两套皮肤。
- **无路径别名**：`tsconfig.json` 无 `paths`，`vite.config.ts` 无 `resolve.alias`，跨目录一律相对路径。

## 9. 陷阱清单（都是踩过的）

- **打包会改脏仓库**：`native:runtime` 把本机 VC/UCRT 运行库就地写进 `resources/native/win-{x64,ia32}`（这 56 个文件受版本控制），`native:rebuild:electron[:ia32]` 会把 `better-sqlite3` 换成 Electron ABI。打包后必须还原，**DLL 与产物一律不提交**；Node 侧测试报 ABI 错用 `npm run native:rebuild:node`。
- **Electron 与 Node ABI 不同**，桌面包能跑不代表 Node 脚本能跑，反之亦然。
- **真机验收**：原生扫描与 OMR 需 Windows + 真实扫描仪；构建/CI 通过不等于设备或视觉验收通过，交付时写清哪些没测。
- **验证用隔离数据**：不动 `data/` 与生产库；不提交运行数据、密钥、打包产物。
- **双面配对前**回读 `CAP_DUPLEXENABLED`，别只信 UI 选项。
- **上传成功后本地原图不清理**，按保留期回收：`PROJECTX_SCAN_RETENTION_DAYS`（默认 30 天，`server/index.ts:749-755` → `db/cleanup.ts`），阅卷中的考试跳过，成绩永不清理。
