# 扫描端运行环境安全升级（2026-10-26）

本次以 main `cc4048280a39c3e5c9c7237840fedb538b5b408f` 为基础，保留 Windows 32 位部署路线。

## 版本与兼容性

| 组件 | 原版本 | 本次版本 |
| --- | --- | --- |
| Electron | 39.8.10 | 43.8.3 |
| 内嵌 Node.js | 22.22.1 | 24.22.0 |
| Chromium | 142.0.7444.265 | 150.0.7871.250 |
| better-sqlite3 | 12.11.1 | 12.11.2 |
| node-abi | 4.31.0（间接依赖） | 4.40.0（显式构建依赖） |

Electron 43 是最后提供 Windows ia32 官方二进制的主版本，44 起取消该平台。现场需要 32 位兼容，因此选择 43.8.3；后续更新同一维护线的安全补丁。参考 [Electron 43 公告](https://www.electronjs.org/blog/electron-43-0) 与 [43.8.3 发布资产](https://github.com/electron/electron/releases/tag/v43.8.3)。

Electron 43 的 ABI 为 148。better-sqlite3 12.11.2 的变更是增加 Electron 43 预编译包。本次安装时 npm 官方注册表对该版本返回 404，依赖固定到官方标签对应的提交 `b5701cb5483d97825778947cb904630c2c2e821e`，锁文件记录归档完整性；Windows 原生插件继续使用同版本官方发布资产并核验 SHA256。参考 [12.11.2 发布说明](https://github.com/WiseLibs/better-sqlite3/releases/tag/v12.11.2)。注册表恢复可用后可改回精确版本号，并重新核对源码与二进制。

打包脚本读取 GitHub 发布元数据时，公共 API 请求失败会尝试已登录的 `gh api`；两种路径均要求发布资产提供 SHA256，并执行同样的摘要核验。

## Brotli 防护

内嵌 Node 24.22.0 低于 CVE-2026-111497 的修复版本 24.22.1，继续启用已有 Node 解码闸门和 Chromium 编码限制。升级运行时后同步移除运行日志中固定描述旧 Electron 39 的句子，错误报告继续显示实际 Node 版本。

服务端应使用已修复版本，例如 Node 24.22.1 LTS。参考 [Node.js 2026 年 10 月安全公告](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)。

## 验证与打包

- 类型检查、Web/服务端构建、扫描端构建通过。
- `PROJECTX_REQUIRE_ELECTRON_PROBE=1 npm run verify:node-runtime-cve`：真实 macOS Electron 43.8.3，151 项通过。
- `npm run verify:scanner-upload-flow`：Node 24.22.1、SQLite 12.11.2，68 次真实 HTTP 请求通过，覆盖上传、重试、订正、成绩保存。
- `npm run verify:release-integrity`：60 项通过。
- 通过 `scripts/package-scanner-win32.cjs --prepare-msi` 准备应用，Windows 11 Parallels 虚拟机使用 `scripts/build-scanner-msi.ps1` 编译与管理解包；随后执行 `--verify-msi` 核对最终包内原生资源。
- 在 Windows 虚拟机运行 MSI 解包后的 ia32 Electron，验证实际运行时版本、Brotli 拒绝解码、SQLite 插入读取、sharp PNG/JPEG 编解码及缩放。

MSI 使用现有 2.7.1 应用版本，WiX 配置启用了 `AllowSameVersionUpgrades`，支持替换同版本旧安装；交付时以 SHA256 区分本次安全更新包。安装包采用现有未签名配置。实体扫描仪与驱动验收按《Windows32位扫描端交叉打包》执行。
