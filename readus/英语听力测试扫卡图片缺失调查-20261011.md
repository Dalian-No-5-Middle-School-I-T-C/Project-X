## 结论

考试 `55`，名称为“2026年10月10日英语听力测试（3）”，答题卡 `84432425`。

修复前有成绩的 199 人中，30 人有已关联切图，169 人没有已关联切图。这 169 人的有效保存回执、整页原图和切图都存在；对应切图的 `exam_id`、`student_id` 为 NULL，因此成绩详情查不到图片。

## 代码因果链

1. [切图上传](../src/server/routes/scanner-upload.ts) 调用 `persistAnswerBlockCrops` 时仅传学号和来源记录，不传考试及用户 ID；上传阶段的切图关联为空。
2. [分组保存](../src/server/services/scannerSubmissions.ts) 在 `processScannerSession(..., "save")` 中逐人提交成绩与 `saved` 回执。其他分组失败不会撤销已成功学生的成绩。
3. [会话完成接口](../src/server/routes/scanner-upload.ts) 第 618–633 行先执行分组保存，随后在 `batch.failures.length > 0` 时返回 409；关联切图的循环位于这一提前返回之后。
4. [成绩详情接口](../src/server/routes/score-editing.ts) 通过 `listAnswerBlockCropsForStudent` 查询图片；[切图查询服务](../src/server/services/AnswerBlockCropService.ts) 同时要求 `exam_id` 和 `student_id` 匹配。169 张未关联切图无法返回。
5. [成绩详情组件](../src/apps/answer-card/client/components/StudentScoreDetail.tsx) 在切图和整页扫描数组均为空时显示“暂无扫描”。

线上 `project-x.service` 初次调查时正在运行 `/opt/project-x-server-2.6.1-81b4d6d-20261011-202501/dist/server/index.mjs`。已直接读取该构建文件，确认其先返回 409，再执行切图关联循环；调查时该问题仍存在。

## 修复建议

代码应让每名学生的切图关联随该学生的成绩和有效回执保存到同一个事务中。批次内其他学生存在冲突时，已成功学生仍应能查看对应图片；冲突或撤销回执的图片继续保留原有证据和归属限制。

历史数据可按这 169 条 `saved` 回执的 `pages_json.recordId` 精确补回切图关联。执行前核对考试、学号、当前成绩、来源记录、切图既有归属及回执状态，并备份及保留审计；仅修复确认归属的切图关联。不要按同学号把所有上传副本一起关联，不需要重新扫描或重新判分。

建议回归场景：同一会话包含正常卷与冲突卷，complete 返回 409，同时断言正常卷成绩已经保存、详情接口返回对应图片、冲突卷图片未错误归属。涉及数据库写入的修复需分别验证 MariaDB 和 SQLite。

## 修复实现与验证

`processScannerSession` 现在在每名学生保存成绩及 `saved` 回执的同一个事务中调用 `linkSavedScannerCrops`。关联先核对有效保存回执、考试、学生和原卷来源，再检查既有图片归属；错误归属使该学生的成绩、回执和关联一起回滚。会话完成接口不再依赖整批成功才关联图片。已有保存回执在显式保存重试时也可补回图片关联。

`scripts/scanner-batch-results-smoke.ts` 新增了以下行为回归，SQLite 与真实 MariaDB 均通过：

- 正常卷与重复学号冲突卷同批提交，complete 返回 409，正常卷图片已关联且真实成绩详情 API 返回该图片。
- 冲突卷的图片不被关联到学生成绩。
- 模拟历史未关联切图后重试，补回图片并保留原成绩、人工改分、逐题分及发布状态；再次重试幂等。
- 图片已经属于其他学生时，新学生的总分、逐题分和保存回执一起回滚，既有图片归属及发布状态保持原值。
- 原有关闭考试、答题卡复用、恢复历史卷、版本校验、保存失败、并发冲突等场景继续通过。

`scripts/repair-scanner-crop-links.ts` 默认只生成审计清单，需显式指定考试、会话、预期切图数量及私有审计目录；`--apply` 才执行。修复只调用有效回执的切图关联，不重新判分、不调用 complete、不重算排名或发布。整个修复事务逐字段比较成绩、考试、回执、识别、发布事件，并检查全表切图只有计划中的两个归属字段变化，任何不符均回滚。

生产 MariaDB 副本演练已通过：计划与实际均为 169 张切图，补回后已有成绩 199 人均有已关联切图；再次按预期 0 张执行无变更。副本已清理，完整审计与验证日志保存在服务器 `/root/projectx-crop-links-20261011/`。
